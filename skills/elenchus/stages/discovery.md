# 탐색·벤치마킹

## 목적

현재 목적에 필요한 해법을 이미 찾아본 사람의 코드·사례·실패 경험을 넓게 찾고 비교한다. 익숙한 후보를 확인하는 데서 끝내지 않고 다른 문제 분해·접근법을 발견한다. [Research의 위임 기본](research.md#research-subagent)을 적용한다. 단일 사실 확인에는 이 문서를 로딩하지 않는다.

## 탐색 범위와 압력

비단순 조사에서는 실제 웹 탐색으로 다음 관점을 각각 살핀다.

| 관점 | 확인할 질문 |
|---|---|
| 직접 해법 | 같은 기능·입출력·문제를 처리하는 라이브러리·도구·프로젝트는 무엇인가 |
| 대체 방식·인접 분야 | 다른 구조·기술·작업 방식으로 풀 수 있는가. 문제 일부를 먼저 풀어본 분야에서 가져올 것은 무엇인가 |
| 실패·운영 제약 | 왜 작동하지 않았는가. 환경·버전·데이터·유지보수·비용에 어떤 조건이 붙는가 |

범주가 현재 문제에 맞지 않거나 관련 자료가 드물면 실제 살핀 질문·경로와 이유를 남긴다. 같은 라이브러리의 소개글 여러 개를 다른 접근으로 세지 않는다. 각각의 링크 개수 대신 해결 방식과 적용 조건의 차이를 드러낸다.

기본 탐색자 두 명은 서로 다른 질문으로 시작하고, 메인의 선호 결론을 공유 전제로 넣지 않는다. 후보를 정하기 전에 그 결과를 비교한다. 사용자 필수 도구가 있어도 그 도구 안의 구현 방식·실패 조건·관련 해법을 살필 수 있다. 필요한 범위가 좁다는 실제 이유가 있을 때만 Research의 간소화 경로를 사용한다.

## 발견에서 적용까지

1. 목적·기능 입출력·실제 환경·확정 제약과 열린 선택으로 질문을 잡는다.
2. 직접 해법과 다른 방식·인접 분야를 서로 다른 검색어·출처로 찾는다. 발견한 용어·프로젝트·개발자·링크를 따라 후보를 갱신한다.
3. 실패·제약·반대 사례로 후보를 점검한다. 같은 원천의 재인용은 합친다.
4. 유력 후보의 실제 코드·기술 문서·유지 상태·사용 조건을 확인한다. 중요한 주장은 이때 구체화하며 자료 확보·출처 검증은 [Web Evidence](web-evidence-loop.md)를 따른다.
5. 우리 목적에서 가져올 부분, 필요한 수정·의존성·비용, 적용하기 어려운 조건을 비교한다.
6. 선택을 바꿀 중요한 미탐색 범주, 같은 원천에 대한 편중, 근거 충돌이 있으면 후속 조사를 수행한다.
7. 우리 환경에서만 답할 수 있는 질문은 [Lab](lab.md)의 실행 기준으로 연결한다. 실행 실패에서 새로운 조건이 나오면 관련 사례와 대체 해법을 다시 찾아온다.

명백히 적용할 수 없는 후보의 상세 구현을 끝까지 읽을 필요는 없다. 제외 이유를 남기고 유력한 대안에 집중한다. 계속 조사할 가치가 있는 질문과 단순한 추가 자료 수집을 구분한다. 검색 수·agent 수·긴 보고서만으로 종료하지 않는다.

## 근거와 관찰

- 구현·재사용 판단은 관련 코드·기술 설명·개발 기록과 실제 환경에 연결한다. API 존재만으로 실행·성능·정확성을 주장하지 않는다.
- 시각적 기능·출력·상호작용을 확인해야 한다면 실제 화면·데모·영상의 관련 부분을 본다. 이미지 URL·소개 문구는 관찰이 아니고 정지 화면은 연속 동작의 증거가 아니다.
- 공개 시각 관찰은 역할·도구 지원에 따라 메인 또는 담당 agent가 수행한다. 사용자 로그인 환경은 Web Evidence의 별도 접근 조건을 따른다.
- `직접 관찰 | 자료의 설명 | 추론 | 미확인`을 구분하고 원문 위치·버전·실패 조건을 남긴다. 사용·재배포 조건을 확인하지 못한 코드를 바로 채택하지 않는다.
- 자료가 없거나 접근할 수 없으면 다른 공개 경로를 확인하고 해당 판단을 미확인으로 남긴다. 아직 확인하지 않은 성능·형식·제품 적합성을 상상으로 채우지 않는다.

## 비교 산출물

현재 R에서 다음 의미를 연결한다. 이미 기록된 정보는 참조하며 별도 장문 보고서를 요구하지 않는다.

| 접근법·사례 | 실제 근거·관찰 수준 | 구현 방식과 차이 | 적용·수정·비용·실패 조건 | 채택·제외·보류와 이유 |
|---|---|---|---|---|

빠진 범주와 이유, 원천 중복·충돌, 추가 실험이 답할 질문을 남긴다. 종합 제품의 화면·동선을 결정하는 대신, 이후 제작자가 선택할 수 있는 기능적 재료와 조건을 전달한다.

## 완료 판정

1. **접근법 비교:** 직접 해법·대체 방식/인접 분야·실패 관점을 살펴 주요 해결 방식과 선택 조건의 차이가 드러난다.
2. **적합한 직접 근거:** 필요한 원문·코드·관찰 대상을 실제 확인하고 자료 설명·추론·실행과 구분했다.
3. **적용 가능성:** 가져올 요소, 필요한 변경·의존성·비용과 적용 한계가 구체적이다.
4. **결정 영향:** 채택·제외·유지·보류가 현재 기능·연구 질문에 연결되며 미승인 제품 선택을 확정하지 않는다.
5. **타당한 종료:** 중요한 미탐색 범주·원천 편중·미해결 충돌을 처리했고 추가 조사의 효용이 낮은 이유를 설명할 수 있다.

웹 비교를 마친 것과 실제 기능을 검증한 것을 구분한다. 미완료 비교를 이후 구현이나 handoff에 넘겼다는 이유로 완료하지 않는다. 접근 제한·사용자 제외·연기라면 그 근거와 남은 범위를 적고 충분한 탐색 종료와 구분한다.
