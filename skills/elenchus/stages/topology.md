# Topology — 탐구의 지형

## 역할

`.elenchus/topology.md`는 사용자 목적, 필요한 기능적 재료, 실제 제약과 열린 질문의 관계를 잡는 현재 기준이다. Codex가 시행착오를 끝까지 진행할 준비를 한다. 기능 목록만 나열하거나 미래 제품의 화면·전체 동선·모든 개발 순서를 확정하는 문서로 만들지 않는다.

## 시작과 연구 준비

원래 요구와 현재 프로젝트를 읽고 목표·기능·입출력·환경·미확인을 정리한다. 조회 가능한 사실은 먼저 확인하고, 해석이 갈리거나 이후 연구를 크게 바꾸는 사용자 선택부터 묻는다. 사용자가 이미 설명한 범위는 다시 형식적으로 확인받지 않는다.

다음 의미를 필요한 만큼 준비한다. 한 문단·표로 합칠 수 있으며 미래 연구의 빈 보고서는 만들지 않는다.

| 내용 | 결정할 것 |
|---|---|
| 목적·사용 맥락 | 해결할 문제, 기능이 필요한 이유, 장기 방향과 이번 범위 |
| 기능적 재료 | 확보할 코드·데이터·테스트·연결 기능, 이미 있는 재료 |
| 기대 입출력 | 형식·규모·출처·의미, 정상·부분 성공·빈 결과·실패 조건 |
| 환경·제약 | OS·도구·라이브러리·기존 코드·접근·비용·원본 데이터 보호 |
| 연구 질문 | 어떤 불확실성을 풀거나 무엇을 실제로 작동시킬지 |
| 달성 조건 | 결론에 필요한 직접 근거·실행·테스트, 반증/실패·보류 기준 |
| 조사·실험 방향 | 살펴볼 해법·인접 분야·실패 경험, 비교·검증 방법과 선행 관계 |
| 재량과 미확인 | 사용자 결정, 아직 자료로 정할 부분, 임시 설계, 이후 제작자의 선택 |

연구를 시작할 때 최소한 **왜 하는지·무엇을 답할지·어떤 근거/실행으로 판정할지·현재 허용 범위**가 드러나야 한다. 후보를 찾아야 달성 조건의 세부 수치를 정할 수 있으면 그 부분을 열린 질문으로 두고 탐색부터 한다. Topology 전체의 완전한 확정을 시작 장벽으로 만들지 않는다.

사용자 답을 반영하거나 Topology를 정리한 뒤에는 [피드백과 다음 행동](../SKILL.md#피드백과-다음-행동)에 따라 그 답으로 정리된 범위와 다음 공백을 연결한다. 연구 준비와 허용 범위가 갖춰졌으면 Research를 시작하고, 사용자 선택이 선행해야 하면 그 질문을 제시한다. 사용자가 이번 범위를 Topology 정리까지로 한정했다면 조사·실험을 시작하지 않고 해당 결과를 전달한다.

사용자가 언급한 방법·API·라이브러리는 `필수 제약 | 현재 환경 | 후보 | 예시`로 분류한다. 확인된 환경 제약과 원하는 조건의 차이를 드러낸다. 환경에서 안 된다는 주장도 실제 확인 전에는 가정이다.

## 기능과 제품화의 경계

기능의 입출력, 오류·재실행 동작, 저장 데이터 의미와 필요한 기능 연결은 연구한다. 테스트·CLI·화면·데모를 통해 직접 관찰할 수 있다. 그 결과만으로 최종 화면 구성·종합 사용 동선·제품 중심 개념을 확정하지 않는다.

이후 제작자가 보존할 것은 사용자 목적·실제로 확인된 제약·데이터 의미·필요한 기능 검증이다. 실험용 함수명·폴더·테이블·UI의 모양은 재구성할 수 있다. 사용자가 직접 정한 요구는 임시 구현과 구분해 보존한다.

## 연구 중 갱신

- 진행할 질문과 의존 관계를 현재 목적 기준으로 정한다. 첫 번째 라이브러리가 빨리 작동했다는 이유로 다른 유력 해법을 미탐색으로 남기지 않는다.
- 같은 질문의 실패·수정·후속 검증은 같은 R에서 이어간다. 독립 질문이 생기면 다음 R을 열고 발생 근거와 관련 목표를 연결한다.
- 연구 계획의 질문에는 실제 R을 만들 때 링크를 붙인다. 예정 질문을 위한 빈 R 문서·추가 번호 체계를 만들지 않는다.
- 목적 안의 질문 구체화·대체 접근·우선순위 조정은 메인이 수행하고 알린다. 목적·중요한 제약·큰 비용·접근 범위의 변경은 그 쟁점만 합의한다.
- 새 사실이 기존 판단을 뒤집으면 이전 판단과 바뀐 이유를 추적할 수 있게 남긴다. 관련 없는 유효한 사용자 합의를 다시 열지 않는다.
- 달성 조건을 정정할 수는 있지만 실제 요구를 버리거나 실패를 성공으로 바꾸는 변경은 기술적 수정처럼 숨기지 않는다.

## 탐구 재개

현재 Topology와 관련 R의 결론·재료·미해결 질문을 읽고 새 목적과 달라진 환경을 확인한다. 유효한 사용자 결정과 R ID를 유지하고, 재검증이 필요한 질문에서 연구를 이어간다.

## 문서 예시

```markdown
# Topology: {목적}
- 상태: 작성 중 | 확정 | 중단됨
- 원요구/관련 기준: {사용자 표현·기존 문서}

## 목적·이번 범위
## 기능·기대 입출력·환경 제약
## 연구 질문·달성 조건·조사/실험 방향
## 사용자 결정·확인된 사실·에이전트 제안
## 현재 결과·추가 질문·보류·이후 제작자의 재량
```

문서의 `확정`은 현재 범위의 정리 상태다. 미실행 연구·제품 선택의 성공이나 사용자의 묵시적 승인이 아니다. R 결론과 충돌하지 않게 갱신하고, 마지막에는 목표별 결과·재료·미검증을 짧게 요약한다. 연구 상세와 실행 로그를 Topology에 다시 복사하지 않는다.
