# beta.2: Topology ↔ Research 아키텍처

## 의도와 기준

사용자가 합의한 역할은 기능적 파트의 실제 시행착오를 미리 수행하고, 코드·데이터·테스트·확인된 제약·실패 경험을 다음 제작자에게 전달하는 것이다. 종합 사용자 경험과 최종 제품 구조는 이후의 재량으로 남긴다. 기능 연결과 검증 UI는 목적에 따라 자유롭게 사용한다.

기준은 `v1.1.0-beta.1` / `73a7ddfcb25b78dcb9071e50f2dcd875d3bf1850`, 개발 브랜치는 `codex/research-foundation-beta2`다. main과 beta.1 태그는 보존한다. beta.2는 새 Draft PR과 `v1.1.0-beta.2` prerelease로 제안하고 사용자 승인 범위의 설치 교체까지 수행한다.

## 책임의 분리

| 책임 | 기준 문서 | 판단 |
|---|---|---|
| 세션·호출·권한·종료 | SKILL | 명시적 진입, 합의 범위, 결과 전달 뒤 일반 모드 |
| 탐구의 지형 | topology | 목적·기능·입출력·환경·질문·달성 조건 준비와 갱신 |
| 연구 조정 | research | 독립 질문/R ID, 역할 분담, 추가 조사, 목적별 결론 |
| 해법 발견 | discovery | 직접·대체/인접·실패 관점, 실제 비교와 탐색 충분성 |
| 증거 검증 | web-evidence-loop | 원문·버전·접근·관찰 수준·충돌과 근거 공백 |
| 실제 시행착오 | lab | 독립 작업장, 구현·연결·실행·실패·재현 가능한 재료 |

상세 절차는 필요할 때만 읽는다. 같은 근거·비교표를 여러 문서에 반복하지 않는다. 새 파일 `.elenchus/topology.md`의 이름은 사용자와 합의한 **Topology — 탐구의 지형**이며 research-plan이라는 파일명을 사용하지 않는다.

## 제거와 호환

Execution 단계, Phase·Build의 전체 합의, 종합 UX 확정 의무를 제거한다. 구판 updater가 요구하는 stages/idea.md·stages/execution.md는 짧은 안내 파일로만 남긴다. 실제 진입은 Topology와 Research로 라우팅한다.

기존 프로젝트 문서는 읽기만 해서 바꾸지 않는다. 명시적 재개에서 새 Topology가 없을 때 현재 의도·유효한 결정·제약을 출처와 함께 추출하고 원문을 남긴다. 기존 R ID·상태·경로·역사적 Phase/Build 참조는 보존한다. 변경할 질문의 현재 연결만 보완한다.

정식 전용 업데이트 인터페이스와 이전 버전의 패키지 경로 호환을 유지한다. 새 Topology/Lab 지침 누락·깨진 라우팅은 패키지 검사로 검출한다. 과거 버전 번호 오타3.0.0을 고려해 버전의 크기만으로 새 아키텍처를 요구하지 않는다.

## 작업 범위와 완료

Topology는 연구를 시작할 충분한 목표·범위·달성 조건을 준비한다. 열린 조사 질문을 사전 지식처럼 확정하지 않는다. 같은 목적의 질문 추가·실패 원인·대안은 메인이 연구를 이어가거나 다음 R을 열고, 목적·중요한 제약·큰 비용·접근 범위 변경만 다시 합의한다.

복수 해법 연구에는 실제 웹과 서로 다른 탐색 질문을 맡은 agent 두 명을 기본으로 쓴다. 좁은 사실 질문은 간소화하고 미지원은 숨기지 않는다. 호출 수와 품질을 구분하며 원천 편중·빠진 중요한 접근·충돌이 남으면 후속 조사한다.

실험은 독립 작업장에서 수행한다. 메인 또는 담당 agent가 코드·의존성·테스트·공개 관찰을 활용하고, 기존 제품과 원본은 보존한다. 같은 목적의 실패는 웹 대안 탐색과 재실행으로 이어간다. 재료는 대화 없이 실행할 수 있는 명령·조건·데이터 의미·테스트를 포함한다.

연구 결론과 작동 기능 확보를 분리한다. 일부 목표가 불가능하다는 충분한 근거가 있어도 해당 기능 구현을 성공으로 바꾸지 않는다. 이후 제작자에게 임시 구조·UI의 보존 의무를 부과하지 않는다. Pro handoff는 요청 시 준비하는 선택적 경로이며 자동 전송하지 않는다.

## 검증과 배포 기준

실제 beta.2 평가 4회(공개 기상 API/SQLite와 로컬 사진 처리 각 2회)를 수행한다. 세션 시간·응답 상한 없이 진행하고 실제 차단은 보존한다. 모델과 도구 조건·입력·소스·평가기준을 실행 전 고정하며 수행자에게 평가표·예상정답을 제공하지 않는다.

빈 컨텍스트의 검토자가 전달된 재료를 재현한다. 실제 호출·파일·출력 증거를 연결하고, native 도구의 전체 trace/토큰이 제공되지 않으면 기록의 한계를 표시한다. 실패·수정·재검증은 별개로 보존한다. 기존 beta.1 평가를 소급 변경하거나 같은 결과로 합산하지 않는다.

실행 도중 사용자가 잔여 실제 평가·독립 검토를 중단하고 식별된 문제와 배포 검사를 마무리해 prerelease·설치까지 진행하도록 범위를 변경했다. 완료·부분·미수행을 [결과 보고서](../tests/research-foundation/RESULTS.md)에 구분한다. 미수행을 통과로 표시하지 않는다. 배포 후에는 게시된 태그 소스·설치 파일·정식 latest를 확인하고 이전 설치본의 백업을 보존한다.
