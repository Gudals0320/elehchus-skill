# Research 단계

## 정체성

`research.md`는 Idea의 주장과 실행 계획을 바꿀 수 있는 외부 사실·데이터·환경 근거를 조사하고 verdict를 만든다. 제품 코드를 구현하지 않는다.

## 진입

Idea closure 뒤 다음 중 하나가 있으면 Research를 제안한다.

- 외부 서비스·API·가격·법·지원 상태가 실행 계획을 바꿀 수 있음
- 선행 사례나 반대 사례가 방향 선택을 바꿀 수 있음
- 데이터·하드웨어·성능을 측정해야 실행 순서를 정할 수 있음
- Idea의 전제가 출처 없는 추정에 의존함

질문 본문에서 왜 조사해야 하는지, 조사하면 어느 Idea 문장이나 Build가 바뀌는지, 조사하지 않을 때 남는 위험을 설명한다. 사용자가 `Research 진행 | 생략`을 선택한다.

## Intake와 모드

Idea의 목표·제약·성공 기준·산출물을 intake로 사용하고 같은 질문을 반복하지 않는다.

모드는 사용자가 선택한다.

```text
web:
웹·문서·선행 사례만 조사

mixed:
웹 근거와 데이터·환경 실험을 함께 사용

data:
로컬 데이터·환경 실험을 중심으로 사용
```

`./.elenchus/research.md`에 다음을 기록한다.

```markdown
# Research: {주제}

- 상태: 작성 중
- 모드: web | mixed | data
- 기준: idea.md
- 확인 날짜: {날짜}

## 조사 목표
## 제약
## 산출물
## 시험할 주장
## 반증 조건
## 필요한 증거
## 실행 기록
## Verdict
```

## 증거 루프

Web 자료와 데이터·환경 실험은 필요에 따라 번갈아 사용한다.

1. 시험할 주장과 반증 조건을 적는다.
2. 기준선 또는 현재 알려진 근거를 기록한다.
3. 다음 조사·실험 하나를 선택한다.
4. 예상 방향과 채택·폐기 기준을 먼저 적는다.
5. 결과를 기록하고 반대 근거와 caveat를 갱신한다.
6. 결과가 Idea와 충돌하면 사용자에게 변경 선택을 받는다.
7. 다음 조사·실험이 verdict를 바꿀 수 있는지 다시 판단한다.

### Web 근거

- 기술 사실은 공식 문서와 원문 연구를 우선한다.
- 가격, 지원 범위와 유지 상태에는 확인 날짜를 붙인다.
- 현재 주장과 반대되는 자료를 찾는다.
- 자료의 사용자·언어·데이터·하드웨어·기간이 현재 상황과 같은지 비교한다.

### 데이터·환경 실험

기존 성능 측정 명령이나 연구 전용 harness가 있을 때만 사용한다.

- 같은 workload와 고정 seed를 사용한다.
- 성공·실패 종료코드를 구분한다.
- 측정값 이름과 방향을 먼저 정한다.
- 제품 코드, manifest와 의존성을 변경하지 않는다.

실행 상태는 다음을 사용한다.

```text
기준선
채택
폐기
실패
검증 실패
제외
```

측정값이 좋아져도 검증 실패, 범위 밖 변경이나 성능 측정 편법이 있으면 채택하지 않는다.

## 내부 검토 관점

- researcher: 출처, 반대 자료와 적용 범위를 확인한다.
- contrarian: 반대 결과가 사실일 때 verdict가 바뀌는지 본다.
- simplifier: 추가 조사 없이 결론 가능한지, 조사 범위를 줄일 수 있는지 본다.
- architect: 근거가 Idea나 Execution의 구성요소·책임·연동을 바꾸는지 본다.

## Verdict

```text
판정: 결론 가능 | 결론 보류
근거
반대 근거
한계
신뢰도: 높음 | 중간 | 낮음
Idea에서 바꿀 내용
Execution에서 바꿀 내용
```

- 근거가 부족하면 결론을 강제하지 않고 `결론 보류`로 둔다.
- 반대 근거와 제외한 실행을 숨기지 않는다.
- 결론 보류의 공백이 Execution을 바꾸면 연구를 계속하거나 Idea를 다시 연다.
- Execution에 영향을 주지 않는 한계만 사용자 동의 후 보류한다.

## 종료 차단 조건

- 조사 목표·제약·산출물 중 하나가 비어 있다.
- 시험할 주장과 반증 조건이 연결되지 않는다.
- 사용한 사실에 출처나 확인 날짜가 없다.
- 반대 자료를 찾지 않았고 검색 범위도 적지 않았다.
- 실험 기준선·측정 방향·판정 기준이 없다.
- Idea와 충돌한 근거에 대한 사용자 결정이 없다.
- verdict에 근거·반대 근거·한계·신뢰도 중 하나가 없다.
- 결론 보류가 Execution을 바꾸는데 다음 행동이 없다.

## 문서 구조

```markdown
# Research: {제목}

- 상태: 확정
- 모드: web | mixed | data
- 확인 날짜: {날짜}

## 조사 목표·제약·산출물
## 시험한 주장과 반증 조건
## 기준선
## Web 근거와 반대 근거
## 데이터·환경 실험 기록
## 제외한 실행과 이유
## Verdict
## Idea 변경
## Execution 변경
## 출처
## 보류
```
