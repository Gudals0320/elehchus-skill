# Topology: 사진 원본을 보존하며 동일 바이트 파일 찾기

- 상태: 작성 중 — 현재 요청의 Topology 정리까지 작성. 새 조사·실험은 미착수이며 연구 기준의 제안과 미확인을 포함한다.
- 현재 범위: 기존 문서를 바탕으로 목적·기능·입출력·제약·다음 연구 질문·달성 조건을 정리한다. 실제 조사·실험은 사용자의 후속 요청 때 시작한다.
- 원요구: “원본 삭제·이동 없이 동일 바이트 파일을 찾아야 한다.” ([기존 Idea](idea.md))
- 이번 사용자 결정: 과거 문서와 번호를 보존하고, 최종 화면은 지금 확정하지 않는다.

## 목적과 범위

사진 원본을 보존하면서 바이트 내용이 동일한 파일을 식별할 기능적 재료를 준비한다. 동일성의 기준은 원요구의 **동일 바이트**다. 이름이 같거나 시각적으로 비슷한 사진이라는 이유만으로 동일하다고 판정하는 기준으로 바꾸지 않는다.

후속 연구에서는 파일 입력, 동일성 판정, 검사 중 변경·접근 실패 처리, 결과 전달을 검증할 수 있어야 한다. 이번에는 그 질문과 판정 기준만 준비한다. 장기 제품 방향, 최종 화면·종합 동선·전체 개발 순서는 정하지 않는다.

## 필요한 기능적 재료와 기대 입출력

아래 기능 분해와 결과 항목은 원요구를 검증하기 위한 **에이전트 제안**이다. 구현·파일 형식·화면은 미정이다.

| 기능적 재료 | 기대 입력 → 출력 | 의미와 열린 선택 |
|---|---|---|
| 검사 대상 수집 | 사용자가 지정할 파일 집합 또는 경로 → 검사 대상 목록, 접근 불가·제외 대상 | 입력 방식, 하위 폴더 포함 여부, 사진 형식 범위, 링크·동일 경로 처리 정책은 미확인이다. |
| 동일 바이트 판정 | 읽을 수 있는 대상 파일 → 동일 내용 그룹과 판정 근거 | 서로 다른 파일의 동일 바이트 여부를 다룬다. SHA256은 기존 실험에 사용된 방법이며 필수 제약은 아니다. 후보 추리기와 최종 동일성 확인 방식을 연구한다. |
| 검사 상태·실패 처리 | 파일 읽기와 변경·접근 오류 → 대상별 성공·실패·보류 상태와 이유 | 검사 중 변경된 파일을 확정 결과에 포함할 수 있는 조건, 재시도·보류 방식은 연구 질문이다. |
| 결과 전달 | 대상별 판정 → 동일 파일 그룹, 처리 범위, 미판정 대상과 이유 | 경로 등 식별 정보와 필요한 검증 근거를 제공하는 재료를 제안한다. 저장 형식·함수·CLI·UI는 확정하지 않는다. |

기대 결과의 구분도 후속 검증 기준으로 제안한다.

- **정상:** 합의한 검사 범위에서 판정이 끝나고, 동일 바이트 파일 그룹과 검사 범위를 확인할 수 있다.
- **빈 결과:** 입력이 없거나, 검사를 끝냈지만 동일 파일 그룹이 없는 경우다. 두 이유를 구분한다.
- **부분 성공:** 일부 파일은 판정했지만 접근 실패·변경 등으로 미판정 대상이 있다. 확인된 결과와 공백을 함께 남긴다.
- **실패·보류:** 입력을 읽을 수 없거나 일관된 내용을 검사했는지 판단할 근거가 부족하다. 이를 “중복 없음”으로 표시하지 않는다.

| 구분 | 현재 기준 |
|---|---|
| 사용자 결정 | 원본 파일을 삭제·이동하지 않는다. 동일 바이트 기준을 유지한다. 이번 작업은 Topology까지이며 조사·실험과 최종 화면 결정은 이후에 남긴다. |
| 확인된 현재 작업 환경 | 제공된 독립 작업장의 `project/`가 사용자 프로젝트다. `skill/`은 읽기 전용이다. 다른 작업·평가 파일과 개인 설정은 이번 작업의 열람 범위에 포함하지 않는다. |
| 현재 환경과 대상 환경의 구분 | 현재 작업 셸은 Windows PowerShell이다. 실제 사진 검사 기능의 대상 OS·파일시스템·저장장치는 기존 문서에서 확인되지 않았으므로 Windows 전용 요구로 확정하지 않는다. |
| 원본 보존을 위한 에이전트 제안 | 후속 구현은 원본 내용에 쓰지 않는 읽기 중심 처리를 기본으로 검토한다. 실패·재실행 때도 도구가 원본을 삭제·이동하거나 내용을 변경하지 않는지 확인한다. 보존해야 할 메타데이터 범위는 미확인이다. |
| 방법의 분류 | SHA256은 `기존 실험 방법 / 후속 후보`. 라이브러리·API·언어는 미정이다. 세 탭 화면은 `과거 미승인 제안`으로 남긴다. |
| 미확인 조건 | 입력 개수·크기·형식, 로컬/외장/네트워크 저장소, 접근 권한, 동시 수정 가능성, 처리 시간·메모리 기대치, 비용·외부 서비스·데이터 반출 허용 범위. 허용이나 불가능을 미리 단정하지 않는다. |

## 다음 연구 질문·달성 조건·조사와 실험 방향

| 연구 질문 | 필요한 근거·실행과 달성 조건 | 반증·실패·보류 기준 | 조사·실험 방향과 의존 관계 |
|---|---|---|---|

| 사용하려는 자료 규모와 저장 환경에서 어떤 방식이 실용적인가? | 실제로 필요한 파일 개수·크기 분포·저장 환경과 허용 시간·메모리 기준을 확인한 뒤 대표 자료로 시간·메모리·I/O를 측정한다. 재현 조건과 정확성 유지 여부를 함께 제시한다. | 성능 기준이 없으면 측정 사실까지만 보고하고 충족 판정을 보류한다. 빨라지기 위해 동일 바이트 기준이나 원본 보존 조건을 완화하면 달성으로 인정하지 않는다. | 정확성 기준을 먼저 세우고 크기로 후보 줄이기, 스트리밍 처리 등 복수 접근을 비교한다. 성능 수치나 필수 캐시는 지금 정하지 않는다. |

권장 선행 관계는 입력·환경과 검증 자료 확인 → 실제 바이트 동일성 및 검사 중 변경 의미 검증 → 오류를 포함한 기능 연결 검증 → 합의된 규모의 성능 판정이다. 이는 연구를 준비하기 위한 관계이며 Phase·Build 계획이나 최종 제품 개발 순서가 아니다.

## 현재 판단과 재개 조건

- **사용자 결정:** 사진 원본 삭제·이동 금지, 동일 바이트 판정, 과거 문서·번호 보존, 이번에는 Topology만 정리, 최종 화면은 미확정.
- **확인된 사실:** R004는 index에서 `확정`, 본문 판정은 `결론 가능`이며, 기록된 검증 범위는 합성 입력의 SHA256 동일성이다. 실제 사진과 파일 경주는 미검증이다.
- **에이전트 제안:** 위 기능 분해·입출력·달성 조건·연구 선행 관계. 사용자 승인이나 검증 완료로 표시하지 않는다.
- **미확인:** 실제 대상 환경과 자료, 성능·비용·접근 범위, 원본 메타데이터 보존 의미, R004 재현 재료의 위치와 실행 가능성.

이번에 확보한 재료는 이 Topology와 기존 근거 연결이다. 새 코드·데이터·테스트·실험 결과는 확보하지 않았다. R004의 기존 결론은 보존하며, 예정 연구의 달성 조건 충족으로 확대하지 않는다.

후속 조사·실험 요청이 오면 관련 질문과 R004의 직접 근거부터 확인한다. 같은 질문의 후속 검증은 기존 R에서 이어가고, 독립 질문은 실제 착수할 때 기존 번호를 보존한 다음 R로 기록한다. 현재는 [research/index.md](research/index.md), R004, Idea, Execution의 원문·상태·번호를 수정하지 않는다.

이번 정리는 Elenchus 세션 종료를 뜻하지 않는다. 다음 연구 요청까지 조사·실험을 보류한다. 이후 제작자에게는 기능적 입출력과 검증 근거를 넘기고, 최종 화면·탭 수·종합 동선·구현 구조는 열린 선택으로 남긴다.
