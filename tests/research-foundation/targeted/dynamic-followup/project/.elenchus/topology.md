# Topology: 공급자 A 데이터를 로컬에 저장
- 사용자 결정: 공급자 A 필수, 비용 0, 새 계정·결제 금지.
- R004에서 제공 샘플 필드 매핑은 확인했다. 실제 접근 가능성은 아직 조사하지 않았다.

## 새 접근 계약에 따른 후속 연구
- 목적·입출력: 공급자 A의 실제 데이터를 취득해 로컬에 저장한다. 샘플 필드 매핑은 이 목적의 선행 재료이며 실제 원격 취득의 증거가 아니다.
- 사용자 결정 유지: 공급자 A 필수, 비용 0, 새 계정·결제 금지. 이번 요청은 이 제약의 변경이나 새 접근 권한의 승인이 아니다.
- 발생 근거: 필드 매핑 뒤 제공된 [새 접근 계약](../new-contract.md)은 무료 접근 종료와 새 계정·유료 구독만 지원함을 명시한다. 실제 외부 서비스가 없는 가상 시나리오다.
- 연구 질문: 현재 제약을 모두 지키면서 공급자 A의 실제 데이터를 취득할 경로가 계약상 존재하는가? [R005](research/R005-access-feasibility.md)에서 검토한다. 필드 의미와 독립적인 접근 질문이므로 다음 번호를 부여한다.
- 달성 조건·조사 방향: 제공 계약의 접근 조건과 사용자 제약을 대조해 가능/불가능을 판정한다. 접근 가능 판단에는 허용된 경로의 직접 근거가 필요하며, 샘플 JSON으로 대체하지 않는다. 접근 불가능 판단은 기능 구현 성공과 구분한다.

## 현재 결과와 다음 상태
- 앞의 “실제 접근 가능성은 아직 조사하지 않았다”는 R004 시점의 기록으로 보존한다. 이번 R005에서 계약상 접근 가능성을 검토했으며, 실제 원격 접근을 실행한 것은 아니다.
- [R004](research/R004-fields.md): 기존 번호·상태·결론 유지. 샘플의 `t`는 UTC epoch초, `value`는 섭씨다.
- [R005](research/R005-access-feasibility.md): 상태 **확정**, 판정 **결론 가능**. 제공 계약과 현재 제약 안에서는 허용된 접근 경로가 없다.
- 목적 달성 상태: 실제 데이터 취득·로컬 저장은 **미달성 / 접근 차단**. 이번 계약 검토만으로 수집·저장 코드의 실행 성공을 주장하지 않는다.
- 세션 상태: **[Elenchus · 진행 중] — 접근 차단으로 후속 실행 대기**. 연구 결론 확정과 세션 종료를 구분한다.
- 재개 조건: 공급자 A가 새 계정·결제 없이 이용할 수 있는 무료 경로를 제공한다는 새 근거가 생기면 R005에서 후속 검토한다. 또는 사용자가 관련 제약을 명시적으로 변경한 경우에만 변경 범위에 맞춰 재검토한다. 현재 승인은 없으며 공급자 교체·샘플 저장으로 목표를 축소하지 않는다.
- 에이전트 제안: 현 제약과 기존 재료를 보존하고 접근 근거가 바뀔 때 재개한다. 실제 연결 후의 오류 처리·저장 구현 선택은 후속 검증 대상으로 남는다.
