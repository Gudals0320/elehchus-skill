# Topology: 로컬 사진 정리의 기능적 재료
- 상태: 확정(현재 연구 범위), 재료 확보 후 세션 종료 검토 대기
- 기준: 작업 input.md 및 inputs/README.md, 2026-09-08

## 목적과 범위
사진 메타데이터 읽기, 동일 바이트 파일 판별, 근거가 있는 정리 후보 데이터를 만든다. 실제 라이브러리와 다른 접근을 조사하고 입력의 형식·날짜·회전·손상 문제를 실행으로 확인한다. 최종 화면·종합 동선·제품 구조는 정하지 않는다.

## 입출력과 제약
입력은 제공된 합성 JPEG·PNG·TIFF·손상 JPG·텍스트 8개 파일이다. 출력은 파일별 형식/크기/방향/원시 날짜/해석된 날짜와 출처·불확실성, SHA-256 및 동일 파일 그룹, 실행하지 않는 정리 후보 JSON이다. 파일별 실패는 다른 파일 처리를 막지 않는다. 원본과 existing-product.txt 및 inputs.sha256.json을 보존한다. 개인 사진·로그인·비밀키·유료 서비스는 사용하지 않는다. 구현/환경/추가 fixture는 .elenchus/lab에 작성한다. 원본 보호는 역할상 경계와 읽기 동작 및 전후 해시 검증이며 기술적 격리라고 주장하지 않는다.

## 결정의 출처
- 사용자 결정: 로컬 기능적 재료, 실제 조사/실험, 원본 삭제·이동 실행 금지, 이후 제작자 인계, 최종 UX 이후 결정.
- 확인된 사실: Python 3.12.10과 pip 25.0.1 사용 가능; exiftool/perl 명령은 PATH에서 발견되지 않음. 추가 설치 가능성은 미확인.
- 에이전트 제안: JSON은 실험 교환 형식이며 최종 계약이 아님. 날짜 누락 시 파일 시스템 날짜를 촬영 시각으로 대신하지 않는다. 메타데이터와 디코드 성공을 분리한다.
- 미확인: HEIC/RAW 실제 지원, 대규모 성능, 실제 카메라/손상 다양성, 시간대 없는 날짜의 실제 시간대.

## 수행 방향
직접 메타데이터 해법과 인접 중복 탐지 접근을 웹에서 살폈다. 서로 다른 질문을 맡은 무이력 독립 조사자 두 명을 순차 실행했다. 두 번째 최초 생성은 슬롯 한도로 실패한 뒤 첫 조사 종료 후 생성에 성공했다. 메인은 환경/기준선·코드·통합 테스트·원문 재검토·복제 재현을 담당했다.

## 현재 결과와 판정
| 목적 | 확보한 재료·직접 판정 | 범위 |
|---|---|---|
| 메타데이터 | Pillow12.3.0/ExifRead3.5.1 실제 비교, 원시 날짜·IFD 출처·offset·방향·크기·검증/디코드 오류 분리 | R001 결론 가능. 제공 정상 사진5개·손상 이미지1개·텍스트2개 처리, 추가 합성 반례와 회귀 테스트 |
| 같은 파일 판별 | 크기+SHA-256+메모리 스냅샷 bytes 비교, 경로/파일 객체 수 구분 | R002 결론 가능. dated.jpg/duplicate.jpg 그룹1, 같은 픽셀·지각 해시를 정확 동일 파일로 혼동하지 않음 |
| 후보의 기능적 재료 | 정확중복 검토1·날짜 bucket2·날짜 메타 검토3·입력 검토3, 총9개 JSON 후보 | 실행하지 않는 데이터, 보존본·목표 파일명·최종 화면/동선 미선택 |
| 실행·인계 | 메인 테스트22개 및 사본 프로젝트 재현22개 통과, 독립 대안 실험10개 통과와 메인 재실행 | 고정 환경/코드/fixture/실패 로그/명령을 [인계 안내](lab/R001/README.md)에 연결 |

실제 시행착오에서 TIFF 자동 방향 처리, verify를 통과하는 잘린 JPEG, 중첩 EXIF 날짜, 달력 검증 누락, Windows stat/fstat ctime 계약 차이를 확인했다. 마지막 문제는 사본 재현 실패를 계기로 수정하고 테스트를 추가했다. 독립 보고서의 fdupes 오류 처리 주장은 원문 재검토 후 정정했다.

## 미확인과 이후 재량
HEIC/RAW·실제 카메라/색관리·XMP/IPTC/sidecar 충돌·대량 성능·네트워크 FS·모든 동시 변경/적대적 입력은 검증하지 않았다. ExifTool/fdupes/restic의 실행 통합은 하지 않았다. 이는 작은 입력을 사용한 기반 기능 검증의 한계이며 전체 사진 제품 지원을 선언한 것이 아니다. 사용자에게 새 비용·접근 범위나 제품 선택을 요구할 차단은 없었다.

현재 Python 모듈·함수·폴더·JSON·날짜 bucket은 에이전트의 가역적 재료 선택이다. 이후 제작자는 이를 재구성할 수 있고 실제 사진 범위·저장 정책·유사도 기준·파일명 충돌 처리·전체 UX를 별도 결정한다. 사용자 원본 보존·개인 자료/계정/키/유료 서비스 금지 조건은 유지한다. 원본과 기존 제품 파일은 내용 해시를 전후 대조했다. 역할상 작업장과 전후 검사이며 기술적 격리를 주장하지 않는다.
