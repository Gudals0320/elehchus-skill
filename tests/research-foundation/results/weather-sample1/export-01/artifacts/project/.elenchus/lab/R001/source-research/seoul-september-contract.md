# 서울 2026-09-01~02 현지 날짜: ERA5 문서 계약 재확인

- 기준: 메인이 전달한 최신 사용자 확정 범위. 서울 37.5665/126.9780, 시간별 기온·강수, 서울 현지 날짜 2026-09-01~02, SQLite 및 원본 보존. 기존 2024년 예시는 새 날짜의 실행 증거가 아니다.
- 확인 시각: 2026-09-08 08:26:24 UTC (clock 도구).
- 범위: 공개 공식 본문 확인과 시간 경계 계산만 수행. 새 weather API GET·구현·새 날짜 SQLite 실행은 메인 소유.

## 확인한 사실과 해석

[Open-Meteo Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api)의 Data Sources 표는 ERA5가 전세계 0.25도·시간별 자료이며 매일 5일 지연으로 갱신된다고 명시한다. API Documentation의 `timeformat=unixtime`은 **UTC epoch 초**, `timezone`은 **현지 00:00부터 날짜 구간**을 선택하는 계약이다. 두 옵션을 함께 쓸 때 날짜 범위는 서울 기준이고 저장값은 UTC epoch라는 해석으로 검증한다. hourly epoch에 `utc_offset_seconds`를 더해 저장하지 않는다. 문서의 offset 재적용 주의는 daily Unix 값의 날짜 해석에 관한 것이며 이번 시간별 저장의 지시가 아니다.

같은 문서의 Hourly Parameter Definition에서 `temperature_2m`는 시점 기온(섭씨), `precipitation`은 직전 1시간 강수합(mm)이다. 서울 시각 라벨을 사용해도 강수 구간의 방향은 바뀌지 않는다. 요청은 `models=era5`, `hourly=temperature_2m,precipitation`, `timezone=Asia/Seoul`, `timeformat=unixtime`을 명시하는 것이 현재 목적에 맞는다. 이는 문서상 기대이며 응답 계약 검증을 대신하지 않는다.

[원 제공기관 CDS의 ERA5 공식 개요](https://cds.climate.copernicus.eu/datasets/reanalysis-era5-single-levels?tab=overview)도 모델과 관측을 자료동화로 결합한 **재분석**이며, 약 5일 지연의 일별 갱신을 설명한다. 초기 배포 ERA5T는 중대한 문제 발견 시 2~3개월 뒤 최종판과 달라질 수 있다. 이번 최근 날짜의 결과에는 수집 시각·원본·해시를 보존하고 최종 확정된 관측자료라고 부르지 않는다. 페이지는 Update date를 2026-09-08로 표시하지만, 이것만으로 특정 좌표·시간의 API 응답 존재를 확정할 수 없다.

[Open-Meteo Model Updates](https://open-meteo.com/en/docs/model-updates)의 본문은 서버 사이 갱신 시점 차이와 지연 가능성을 설명한다. 이번 Web 읽기는 설명 본문을 확보했지만 동적 모델 테이블의 ERA5 최신 가용 시각은 표시되지 않았다(Last refresh 00:00 shell). 이 화면을 실시간 ERA5 가용 확인으로 기록하지 않는다. 별도 metadata 또는 weather API 호출은 메인 작업과 겹치므로 실행하지 않았다.

## 이번 날짜의 문서상 기대와 판정 기준

**문서상 기대:** 확인 시각 기준 요청의 마지막 UTC 날짜인 2026-09-02는 약 5일 지연창보다 과거다. 따라서 서울 9월 1~2일을 ERA5로 요청할 합리적인 기대가 있다. 실제 제공 성공·48개 유효값·무결측은 미확인이고 메인 새 GET에서 판정한다. 실패하면 HTTP 오류와 실제 가용 범위를 기록하며 오래된 2024 fixture 성공으로 대신하지 않는다.

서울 UTC+09:00 기준 경계를 계산했다. 아래는 실제 응답 관찰값이 아닌 **예상 시각 라벨 범위**다.

| 경계 | 서울 현지 시각 | UTC | epoch seconds |
|---|---|---|---|
| 첫 라벨 | 2026-09-01 00:00 +09:00 | 2026-08-31 15:00Z | 1788188400 |
| 마지막 라벨 | 2026-09-02 23:00 +09:00 | 2026-09-02 14:00Z | 1788357600 |
| 조회 상한(미포함) | 2026-09-03 00:00 +09:00 | 2026-09-02 15:00Z | 1788361200 |

완전한 응답이면 3,600초 간격의 48개 라벨이 기대된다. 첫 라벨의 강수는 그 직전 1시간이므로 이 48개 강수값 합을 서울 9월 1~2일의 물리적 일 강수합이라고 바로 부르면 안 된다. 요청이 시간별 기온·강수이므로 시각 라벨과 강수 구간을 함께 보존하는 현재 계약으로 충분하며, 별도 일 집계 정책을 이 문서에서 새로 확정하지 않는다.

판정: 좁은 문서 계약은 재확인 완료. 새 날짜·현지 구간의 실행 판정은 메인 GET/SQLite 검증에 남아 있다. 원 제공기관과 Open-Meteo는 자료 계보가 연결돼 있으며 재인용을 서로 독립된 관측 데이터로 계산하지 않는다.
