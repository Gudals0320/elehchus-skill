# Native Research Foundation 평가 — 평가자 전용

이 파일, rubric, fixture 정답, 이전 실행 결과와 beta.2 개선 이유는 수행 agent에게 전달하지 않는다. 원요구·고정 답변·작업 경계·runtime만 입력한다. 모델 조건과 입력 데이터는 실행 전에 freeze하며 사전 후보 라이브러리·웹 출처 목록을 주지 않는다.

## 조건과 실행 순서

- manifest의 두 분야 × 독립 표본 두 번, 총 네 번을 새 컨텍스트에서 실행한다. 과거 beta.1 평가와 합산하거나 우위로 해석하지 않는다.
- 요청 모델 `gpt-6-astra`, effort `xhigh`. 실제 호스트가 확인해준 값은 별도로 기록한다. 확인할 수 없는 값은 `null`로 둔다. 이름이 비슷한 다른 모델을 대신 사용하지 않는다.
- runtime commit 이후 `freeze`로 Git blob과 실제 제공할 바이트의 SHA-256을 고정한다. `git archive`는 사용하지 않으므로 CRLF 변환·export-subst·export-ignore가 개입하지 않는다. 작업 트리 바이트를 제공했다고 주장하지 않는다.
- 각 `prepare`는 다른 작업 폴더와 새 제품/입력 자료를 만든다. `.git` 파일이나 저장소 연결을 만들지 않는다. `.git/config`, 사용자 설정, 인증 상태를 모델 입력/산출물로 복사하지 않는다.
- native fresh actor를 하나씩 실행한다. 한 actor가 독립 조사자 두 명을 쓸 수 있는 동시 실행 여유를 확보한다. 병렬 capacity가 부족하면 대기 상태를 보존하고 가능한 순서로 재시도한다. agent 수를 채웠다는 이유로 조사 폭을 통과시키지 않는다.
- 실제 검색·원문 조회·위임·코드 실행 가용성을 시작 전에 operator가 확인한다. 브라우저/시각 관찰은 과제에서 필요할 때 가용성을 확인한다. 못 쓴 동작은 `미관찰` 또는 `미충족`이며 호출 성공을 조사의 성공과 같게 보지 않는다.
- 지시상 파일 소유권은 기술적 격리가 아니다. 실제 host sandbox나 tool 제한이 적용됐는지 관찰한 사실만 기록한다. repo 원본은 baseline 해시로 별도 보호하고 actor에게는 복사된 runtime과 평가 프로젝트만 지정한다.
- 세션 시간·응답 수 상한은 없다. 명령별 무응답 timeout은 필요에 따라 사용하며 세션 완료나 연구 실패 판정과 분리한다. 같은 범위의 진전이 있으면 계속한다. 오류나 접근 차단은 숨기지 않는다.

## 고정 사용자 응답과 종료

1. `prepare`가 만든 작업 폴더의 `input.md`로 시작한다. actor가 확인 질문을 하거나 첫 응답을 마치면 해당 결과 폴더의 `answers.md` 전체 내용을 한 번 제공한다. 조사를 먼저 마쳤어도 같은 고정 답변 이후 변경 영향을 확인한다.
2. 이후 진행 요청은 `actor/continuation.md`를 그대로 사용한다. 평가 기준, 점수, 정답과 새 사용자 선호는 넣지 않는다. 실제 사용자 선택이 있어야 진행할 수 있는 경우 원요구/고정 답변에 답이 있는지 검토하고, 없으면 `needs_user_input`으로 남긴다.
3. 실제 Research 결론, 실행 재료와 알려진 제약이 전달됐는지 공개 응답과 파일을 operator가 읽는다. 문서 표식·정규식·응답 수만으로 종료하지 않는다. 재료가 미완료면 같은 continuation으로 이어간다.
4. 결과가 전달됐고 세션 완료 확인만 남았으면 `close.md`를 한 번 제공한다. 이것은 제안된 종합 UX나 미검증 기능의 승인으로 계산하지 않는다. 결과 전달, 세션 종료, 기준 충족을 각각 기록한다.
5. 충분한 근거로 불가능성을 결론 낸 연구는 유효한 연구 결론일 수 있지만 작동하는 기능 성공은 아니다. 핵심 목적이 미해결이면 실패/차단과 영향을 보존한다.

## 기록과 공개

- `actor_record`는 실행자가 작성한 활동·원문·명령·결과 기록이다. `observer_event`는 operator가 실제 도구 응답/응답 전달/파일 바이트에서 관찰한 기록이다. 서로 대체하지 않으며 전체 host trace라고 부르지 않는다.
- 입력, follow-up, 공개 답변, 위임 질문과 실제 반환, 검색/열람 URL, 코드 실행과 파일, 오류와 복구를 가능한 범위에서 보존한다. 비공개 추론·인증·호스트 설정은 보존 대상이 아니다.
- wall time은 UTC 경계가 확인되는 구간만 계산한다. model processing, operator wait, 검색 수, 사용자 수정, 토큰은 실제 노출되는 범위만 기록한다. 없으면 `null`; 추정치나 actor 보고값에는 근거 종류를 붙인다.
- 실제 API 원응답에는 요청 조건·조회 시각·제공 데이터의 의미·이용 조건을 기록한다. 실패 응답도 보존한다. fixture를 이용한 재현과 그 시점의 실제 네트워크 성공을 구분한다.
- export는 검토한 상대경로 allowlist만 복사한다. export 도중 읽기 실패, 차단 파일, 누락 파일, 큰 파일은 항목별 오류로 남긴다. 성공 파일만으로 전체 수집 완료를 주장하지 않는다. 원본 작업 폴더는 자동 삭제하지 않는다.
- 공개 시 개인정보/비밀/라이선스 제한을 수동 확인한다. 필요한 비식별화는 공개 사본에만 하고, 원본 해시와 공개 해시·변환 이유를 함께 남긴다. helper는 자동으로 완전한 개인정보 감지를 보장하지 않는다.
- 모든 실패 표본을 남긴다. runtime 수정 후 재실행하면 새 freeze/run ID를 만들며 기존 파일을 덮어쓰지 않는다.

## 빈 컨텍스트 재현

수행 대화를 보지 않은 검토자에게 공개 export 안의 `project/`와 재료 재현 요청만 제공한다. 재현 요청은 freeze 해시로 검증하고 prepare 시 operator 폴더에 고정한 바이트를 export로 전달한다. `reproduce-prepare`는 해당 사본의 해시를 다시 확인하며 현재 `evaluator/reproduce.md`를 대신 읽지 않는다. 고정 사본이 없거나 달라졌으면 실패를 보존한다. 이 재현 요청은 수행 actor에게 제공하지 않는다.

Topology/Research/실행 안내/fixture/코드/테스트는 재료의 일부로 읽을 수 있다. actor 활동 로그, operator 판단, 예상 정답, 이전 결과는 제공하지 않는다. 새 쓰기 작업 폴더에 복사하고 제공 안내로 의존성 준비·테스트·대표 기능 경로를 실제 실행한다. 네트워크 재조회와 저장 fixture 재현을 따로 기록하고, 문서에 빠진 실행법이나 임의 보완은 재현 실패 또는 부분 재현으로 남긴다. 검토자도 사용자 제품 코드를 변경하지 않는다.

## 방법 참고

입력 자료와 평가 기준 분리, 작업 결과 외 도구 사용 경로를 함께 검토하는 방법은 [OpenAI agent evaluation 안내](https://developers.openai.com/api/docs/guides/agent-evals)와 [trace grading 안내](https://developers.openai.com/api/docs/guides/trace-grading)를 참고했다. 이 도구는 OpenAI Evals API나 완전한 tracing SDK를 사용하지 않는 native 수동 감독 평가다.
