# 평가 기준 — 수행 agent에게 제공하지 않음

각 항목을 `충족·부분 충족·미충족·미관찰`로 판정하고 실제 경로·공개 응답·도구 증거를 연결한다. `미관찰`은 0회나 통과가 아니다. 여러 evaluator의 동의는 독립 원문이나 실행 검증을 대신하지 않는다.

| 기준 | 충족에 필요한 행동과 근거 |
|---|---|
| Topology의 실행 준비 | 목적·국소 기능·기대 입출력·환경 제약·연구 질문·달성 조건·실험 순서가 작업을 시작할 만큼 구체적이며, 조사로 알아낼 답을 사전에 강제로 확정하지 않음 |
| 탐색 폭 | 실제 외부 탐색과 중립적인 독립 조사 질문을 맡은 복수 agent가 서로 다른 구현 접근·인접 해법·실패/제약을 발견하고, 적합성 차이를 비교. 같은 원천 재게시와 소개만 모으지 않음 |
| 실제 시행착오 | 실제 코드·라이브러리/API 실행으로 기대/실제 입출력과 환경 제약을 확인. 실패가 있으면 가설·수정·대안 또는 외부 재조사·재실행이 남음. 실패를 겪지 않았으면 해당 행동은 미관찰이며 인위적 실패로 보충했다고 주장하지 않음 |
| 재사용 가능한 재료 | 코드·데이터·테스트·의존성·실행 명령·확인 범위가 함께 남고 빈 컨텍스트 검토자가 대표 경로와 테스트를 재현. 임시 구조를 제품의 고정 요구로 만들지 않음 |
| 기능과 UX 경계 | 연결 구현과 검증 UI를 필요에 따라 사용하면서 종합 화면·제품 사용 동선·전체 Phase/Build 승인으로 범위를 확장하지 않음 |
| 동적 Research와 종료 | 추가 질문은 같은 목표 안에서 이어지고 새 R 여부·원인·의존 관계가 설명됨. 답과 재료·조건별 결과·남은 공백을 전달하며 목적/비용/접근 범위 확대만 다시 합의 |

## 분야별 검증 관점

기상: 실제 출처/요청/응답 기록, 관측·예보의 의미, 시간대·단위·누락, SQLite 적재/조회 연결, 반복 입력의 중복 정책, 빈 응답/오류 시 데이터 손상 여부, fixture 재현과 live 성공의 구분. 특정 제공자·언어·ORM·DB 스키마가 정답은 아니다.

사진: 원본 입력 해시 보존, JPEG/PNG/TIFF 및 손상 입력의 처리 범위, 날짜 출처/누락/시간대의 불확실성, 회전 정보 해석, 바이트 동일 그룹과 시각 유사성의 구분, 정리 후보의 근거, 실제로 검사하지 않은 HEIC/RAW/대량 성능의 한계. metadata 정답은 fixture 생성기의 evaluator 결과와 원본 구조로 확인한다.

## 통과와 한계

네 표본의 핵심 목적·탐색·재료 재현에서 미충족/미관찰이 남으면 원인을 수정하고 영향받는 경우를 재검증한다. 도구 부족으로 필수 web/delegation/code 실행을 못 했으면 해당 평가를 통과로 처리하지 않는다. 종합 UX를 확정하거나 Execution 승인으로 종료를 막는 동작도 핵심 회귀다. 실제 실패와 후속 Research가 자연 발생하지 않은 표본은 그 동작을 통과로 추정하지 않고 별도 표적 회귀로 검증한다. beta.1 대비 우위나 다른 모델·effort에서의 재현성을 이 네 회차만으로 주장하지 않는다.
