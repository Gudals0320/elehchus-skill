# Issue #12 평가 결과와 인계

> 2026-09-07 후속: 사용자가 시간 제한 제거를 요청한 새 기본 비교 8회는 모두 Research 결과 전달까지 완료했다. [무제한 비교 결과](untimed/RESULTS.md)를 별도로 추가했다. 아래 내용은 당시 제한 조건의 기록이며 소급 통과로 바꾸지 않는다.

## 결론

탐색·벤치마킹의 조기 진입, 실제 근거의 비교, 범위 내 자율 위임과 목적별 완료 판정을 구현했다. 실제 웹 세션에서 공개 화면·코드·실패 경험을 조사해 적용 판단으로 연결하는 동작을 관찰했다. 그러나 **합의한 시간 안에 Research 결과를 안정적으로 전달한다는 근거는 아직 부족하다. 이 변경은 Draft PR로 제안하며 이슈 해결·전체 효율 개선을 주장하지 않는다.**

기준은 `132eea5`, 최초 후보는 `0217658`, 중복 기록을 줄인 최종 후보는 `655f1c5`다. 버전 표기는 3.0.0으로 유지했다. 입력과 실행 조건은 [protocol](README.md), [스냅샷](snapshots/candidate-v2.json), [실행·수집 현황](infrastructure/core-status-final.json)에 연결한다.

## 다섯 기준에 대한 의미 검토

판정은 `충족·부분 충족·미충족·미관찰`로 구분한다. 아래 의미 검토는 기준 카지노 첫 표본의 Research 문서, 후보 v2 사진 첫 표본의 공개 응답, 완료된 카지노 단계 진단, 실제 웹 사진·카지노의 응답과 관찰 기록을 중심으로 한 대표 자료 검토다. 모든 표본의 모든 문장을 독립 검증하거나 표본별 다섯 기준을 전부 통과시켰다는 뜻이 아니다. 주 비교 전체의 실행·수집·최종 응답 상태는 확인했으며, 최종 결론 전달·사용자 선택 지원은 시간 초과로 미완료다.

| 기준 | 관찰과 판정 근거 |
|---|---|
| 접근법 비교 | **대표 자료 범위에서 충족.** 카지노에서 3D+UI·CSS/이미지·공간형·인접 보드게임, 사진에서 폴더 스캔·복사 보관함·참조 카탈로그·수동 비교가 구분됐다. 기준 버전도 고정 자료가 있을 때 유효한 비교를 작성했으므로 후보만의 발견 성과로 계산하지 않는다. |
| 적합한 직접 근거 | **부분 충족.** 통제 자료는 합성 문서이며 실제 시각 자료가 없다. 완료된 카지노 진단은 재게시·서로 다른 시간 단위·Wheelkit 버전 차이를 구분하고 시각 판정을 보류했다. 실제 웹 사진 세션은 공개 화면과 코드의 확인을 기록했다. 카지노의 연속 움직임 관찰은 미완료다. |
| 적용 가능성 | **대표 비교 범위에서 충족.** 자료의 기능을 그대로 채택하지 않고 원본 유지·오프라인 조건, 6덱의 논리/그림 분리, 블랙잭 판단 구간, 룰렛 포켓·버전 제약을 연결했다. 실제 제품 성능·구현 성공은 검증하지 않았다. |
| 결정 영향 | **부분 충족.** 미승인 권고와 열린 선택을 구분한 응답은 제공됐다. 최종 후보 카지노 진단과 실제 사진 응답에서 사용자가 선택할 수 있는 결과를 확인했다. 주 비교는 최종 응답 전달까지 마치지 못했고 실제 사용자의 채택 결과도 없다. |

실제 웹 사진 세션의 [응답](live/photo-organizer/artifacts/response-2.md)은 기존 폴더를 유지하는 카탈로그, 동일 파일과 닮은 이미지의 별도 처리, 이동 실패의 확인 단계를 제안했다. 평가자가 Microsoft의 `MOVEFILE_COPY_ALLOWED` 설명과 Czkawka의 `check_files_hash`/`compute_hashes_for_image` 경로를 원문에서 다시 확인했다. 이는 실제 파일 이동·성능 실험을 수행했다는 뜻은 아니다.

카지노의 [첫 웹 결과](live/casino/artifacts/response-2.md)는 실제 공개 이미지 비교와 구현 접근 비교를 제시했지만 카드·공의 연속 움직임을 미확인으로 남겼다. [v2 종료 후 보관본](live/casino-v2/artifacts/post-timeout-archive.md)은 이미 확보한 근거를 정리한 자료이며, 제한 내 완료 응답으로 계산하지 않는다. 별도의 Lab 실험은 이 평가에서 실행하지 않았다.

## 수집·판정기 수정과 한계

- Windows sandbox 생성 폴더의 host 읽기 문제를 실제 도구·한글·파일 roundtrip으로 진단했다. 새 평가 루트에 host 읽기 ACE만 준비했으며 모델 권한·사용자 설정은 바꾸지 않았다. 초기 4개의 빈 artifacts는 문서 부재 증거가 아니다.
- 읽을 수 없는 문서를 빈 목록으로 삼지 않게 strict 수집을 적용했다. 수집 실패는 작업장을 보존하고, 정리 실패는 결과 저장 후 별도로 기록한다. 임시 경로 밖의 권한이나 소유권은 변경하지 않았다.
- 종료 판정기의 enum/TODO 오인과 목적별 선택 판정 처리를 결정적 회귀로 검사했다. 자동 종료 신호는 품질 판정이 아니며, 기존 core 기록에는 자동 종료된 실행이 없다.
- 공개 파일 해시는 실제 게시 bytes와 Git 보존 정책에 맞춰 감사·보정한다. 기존 input/answer text digest는 전송 전·공개 전 텍스트의 의미로 유지하며 정확한 stdin bytes나 모델 내부 정규화로 표현하지 않는다.
- native 제품 비교의 초기 false는 LF와 CRLF 비교 오류였다. [정정 감사](infrastructure/native-product-comparison-correction.json)에 원래 판정과 해시를 남겼다. 최초 두 세션의 초기 hash는 기록된 생성 코드에서 재구성한 값이며, v2는 시작 전에 실제 측정했다.
- native 시각 관찰은 수행 agent의 기록과 파일 산출물이며 완전한 host trace가 아니다. 실제 사용자 탭·원본 사진·계정은 평가 자료로 사용하지 않았다. CLI의 대화 텍스트 복원은 native 대화 상태와 다르다.
- 일부 CLI 실행의 stream 재연결, 동시에 진행한 평가와 도구 대기, 기록 작성 비용이 시간에 섞여 있다. 단일 변경의 인과 효과·일반적인 비용 우위를 주장하지 않는다.

## Issue #12 완료 조건과 남은 작업

최종 확인에서 기존 Python 검사 16개, 평가 실행기·패키징·기록 검사 28개와 skill validator가 통과했다. 이는 실제 모델 평가의 시간 초과를 상쇄하지 않는다. 독립 검토자는 판정기·수집·공개 해시 문제의 수정을 재검증했고 보고서의 수치·28개 로컬 링크와 대표 검토의 한계를 확인했다. 최종 검토 범위에서 추가 actionable finding은 없으며 Draft PR을 권고했다. 실제 브라우저 관찰의 재실행이나 모든 문장의 의미 검증을 수행한 검토는 아니다.

| 항목 | 상태와 근거 |
