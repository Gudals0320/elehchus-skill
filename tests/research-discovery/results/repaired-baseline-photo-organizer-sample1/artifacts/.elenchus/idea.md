# Idea: Windows 개인용 로컬 사진 정리 도구

- 상태: 작성 중
- 시작 요청: Windows PC에 흩어진 사진을 여러 폴더에서 모아 보고, 날짜나 비슷한 사진을 기준으로 정리하는 개인용 로컬 도구의 구현 전 계획을 세운다. 탐색기처럼 원본 폴더를 직접 다루는 방식과 별도 사진 보관함 방식은 미정이다. 기존 제품과 공개 구현에서 참고할 방식을 폭넓게 비교하고, 파일을 잘못 변경할 위험도 검토한다. digiKam은 들어 본 예시이며 사용하거나 구조를 따르라는 요구가 아니다. 지금은 제품을 구현하지 않는다. 이번 실행의 evidence/는 가상 제품의 합성 자료이며 실제 제품의 사실이나 직접 관찰·실행 결과로 간주하지 않는다. 네트워크·브라우저·subagent 없이 제공 자료 범위에서 검토한다.

## 관찰한 문제·사용자·입력

- 출처: 사용자 요청. Windows PC에서 혼자 사용한다. JPEG·PNG·HEIC 약 5만 장이 두 드라이브와 외장 SSD에 흩어져 있다. 촬영일 누락·오류가 있다. 빈도, 현재 정리 도구, 사진 총용량, Windows 버전과 하드웨어는 미확인이다.
- 사진을 선택하고 변경·삭제를 최종 결정하는 사람은 사용자다. 원본의 잘못된 변경·손실이 중요한 오류 비용이다.
- 저장소에서 확인한 사실: `app.txt`는 `UNIMPLEMENTED PRODUCT STUB`다. 현행 제품 동작이나 사용할 엔진·DB가 있다고 보지 않는다. 실제 개인 사진을 확인한 것은 아니다.

## 확인된 사실

- 출처: 사용자 요청. 위 입력 규모·환경은 사용자 진술이며 측정 결과가 아니다.
- 출처: 저장소 관찰, 2026-09-07. `evidence/README.md`와 01~08은 가상 제품·조직·수치·코드의 합성 문서다. 화면·실행 파일·실제 공개 저장소의 전체 소스가 없다. 실제 제품 사실, 직접 UX 관찰, 실행 실험으로 전환하지 않는다.
- 이번 실행은 네트워크·브라우저·subagent를 사용하지 않는다. 역할 분담 허용은 기록하되 독립 에이전트 조사로 보고하지 않는다. 최초 Release 확인은 이전 턴에 완료되었고 현재 버전 사용이 선택되었다.

## 사용자 결정

- 출처: 사용자 요청 · 기존 범위 구체화. 여러 폴더 통합 조회, 날짜 탐색과 큰 비교, 오프라인 사용, 외장 SSD 분리 시 이전 정보 조회가 필요하다.
- 출처: 사용자 요청 · 안전 경계 구체화. 명시적으로 적용하기 전 원본 사진과 메타데이터를 변경하지 않는다. 파일 이동 기능을 고르면 적용 전 목록을 검토하고 실패 시 원본과 작업 경위를 파악해야 한다.
- 출처: 사용자 요청 · 자동화 제한. 중복은 삭제 전 후보를 나란히 비교해 직접 고른다. 유사하다는 이유의 자동 삭제는 하지 않는다. 구체적인 삭제·휴지통·복구 방식은 선택하지 않았다.
- 출처: 사용자 요청 · 현재 작업 범위. 기존 제품 경험과 제작 방법을 폭넓게 조사하고 Research 결론까지 제시한다. 전체 실행 계획 합의는 다음 대화로 미룬다. 기능·비용·취향을 추가로 확정하지 않는다.
- 출처: 사용자 요청 · 허용 범위. 이 범위의 조사와 역할 분담을 허용했다. 외부 계정·유료 호출·실제 개인 사진 접근은 허용하지 않았다.

## 사용자 흐름·출력·성공 판정

| 상황 | 확정된 사용자 결과 | 미정 또는 조사로 제시할 내용 |
|---|---|---|
| 폴더 선택과 탐색 | 여러 폴더의 사진을 함께 찾고 날짜로 훑는다. | 하위 폴더·겹치는 선택 처리, 첫 스캔 중 조회, 빈 결과·읽기 실패 표시, 성능 목표 |
| 인터넷·외장 SSD 분리 | 인터넷 없이 기존 사진을 찾으며, SSD 분리 시 이전에 본 정보가 남는다. | 남길 필드와 미리보기 해상도·용량·보관 기간, 오래된 정보와 재연결 표시 |

| 중복·유사 후보 검토 | 크게 나란히 비교하고 삭제 전 직접 선택한다. | 동기 확대, 후보 점수 표시, 동일 파일·시각 유사 구분의 화면 방식, 후보 누락 허용 수준 |

위 관찰 기준은 부분적인 의도 계약이다. 속도·정확도·전체 복구 같은 미측정 성공 기준을 추가하지 않았다. 원본 수정 외 앱 내부 저장소의 위치·보관·삭제 정책도 아직 사용자 선택이 남는다.

## 에이전트 제안

- 아직 승인되지 않은 제안의 근거와 교환 관계는 각 Research 파일에만 둔다. [조사 색인](research/index.md)에서 연결한다.
- 연구 제안 P1: 원본을 그대로 두는 로컬 참조 카탈로그를 우선 검토한다(R001). 기존 양자 비교에 제3의 대안을 추가한 제안이다. 분리된 드라이브 정보를 남길 수 있지만 별도 색인·캐시 관리가 필요하다. 화면 선호나 DB 확정이 아니다.
- 연구 제안 P2: 파일 변경 기능은 조회·후보 선택과 분리해 채택 여부를 결정한다(R002). 더 작은 범위로 먼저 만들 경우 잘못된 변경 위험이 줄지만 실제 파일 정리는 수동으로 남는다. 기능 삭제·연기는 미승인이다.
- 연구 제안 P3: 동일 파일과 시각적 유사 후보를 구분하고, 날짜 값에는 출처·불확실성을 보존한다(R003, R004). 구체적인 비교 조작·날짜 정렬·보정 기능은 미승인이다.

## 구현 위임

- 특정 제품·엔진·DB는 필수 조건이 아니며, 내부 구조는 조사 근거로 제안하도록 사용자가 요청했다. 사용자 경험·비용·실패 결과를 바꾸는 선택까지 구현자에게 위임한 것은 아니다.
- digiKam은 들은 예시다. 채택·재현·구조 추종 조건에서 제외한다. 이번 자료로 실제 digiKam의 기능·성능·지원 상태를 판정하지 않는다.

## 제외

- 계정, 클라우드 업로드, 공유, 얼굴 인식, 사진 편집.
- 이번 실행에서 외부 계정 생성·사용, 유료 호출, 실제 개인 사진 접근, 제품 구현, 전체 Phase·Build 합의.
- 추가 기능·금전 비용·저장 용량·취향의 임의 확정. 특정 제품·엔진·DB의 강제 채택.

## 미확인·충돌

- 사용자 진술 사이에 직접 충돌은 발견하지 않았다. 원본 폴더 직접 스캔만으로 분리 드라이브 정보를 제공하지 못하는 사례와 현행 버전의 온라인 전환은 후보의 부적합이지 사용자 의도의 모순이 아니다.
- 높은 영향의 미결정: 분리된 SSD에서 텍스트 정보만 필요한지, 저장된 미리보기로 어느 정도까지 비교해야 하는지. 이 결정은 저장 공간·캐시 보관·관리 방식의 추천을 바꾼다.
- 그다음 미결정: 이동·삭제의 포함 시점과 복구 기대, 촬영일 누락·오류의 정렬·보정 정책, 폴더·타임라인 화면, 성능과 후보 정확도의 관찰 기준, 지원 Windows·HEIC 경계.
- 부분 성공·빈 결과·취소·재시도·외부 이동·재연결, 카탈로그 손상·캐시 소실, 저장 공간 부족의 상세 UX는 분류했으나 확정하지 않았다.
- Idea closure는 미통과다. 사용자 경험과 교환 관계에 남은 선택이 있어 상태를 `작성 중`으로 유지한다. 이번 사용자의 명시적인 Research 결론 요청에 따라, 확정된 제약을 intake로 조사하고 미정인 취향은 가정으로 채우지 않는다. 전체 Idea 확정이나 Execution 진입으로 간주하지 않는다.
- 다음 대화의 첫 질문 후보: 외장 SSD가 빠져 있을 때 이전 사진의 날짜·경로 같은 텍스트 정보만 찾으면 되는가, 저장된 미리보기로 사진을 알아보고 비교하는 것까지 필요한가?
