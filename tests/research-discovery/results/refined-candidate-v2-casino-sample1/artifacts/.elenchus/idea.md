# Idea: 룰렛·바카라·블랙잭 싱글 카지노와 3D 웹앱

- 상태: 작성 중
- 시작 요청: 룰렛·바카라·블랙잭 세 게임을 할 수 있는 게임을 만든다. 룰을 적당히 합의한 뒤 터미널 기반 카지노 로직을 먼저 만들고, 애니메이션이 구현된 웹앱 게임으로 이어간다. 사용자가 가장 어렵게 보는 부분은 3D 애니메이션이며 디자인 고찰과 레퍼런스 탐색이 많이 필요하다. 게임 시작 시 초기 자금을 정하고, 파산하면 게임 오버, 그렇지 않으면 계속 진행한다. 현재는 싱글을 먼저 구현하며 나중에 멀티로 확장할 계획을 고려해 카드 게임은 6덱으로 생각한다. 저장 등의 기능은 현재 필요 없다.

## Topology

현재 사용자 응답으로 세 게임·세션 자금·터미널·웹 표현의 상위 구성을 확인했다. 기존 분류를 아래 네 제품 구성요소로 정리하고, 디자인 조사는 웹 표현과 제작 방법을 결정하기 위한 작업으로 둔다. 새로운 기능은 추가하지 않는다.

| 구성요소 | 상태 | 목표·사용 표면·근거 |
|---|---|---|
| 세 게임의 규칙과 판정 | 활성 | 룰렛·바카라·블랙잭. 카드게임은 각각 독립된 6덱, 룰렛은 싱글 제로. 바카라 플레이어/뱅커/타이와 뱅커 5% 커미션, 블랙잭 더블·스플릿. 세칙은 구현 전에 별도 합의한다. 출처: 사용자 요청. |
| 세션 자금 | 활성 | 사용자가 초기 자금을 입력하고 세 게임에서 공유한다. 파산하면 게임 오버, 아니면 계속 진행하며 세션 종료 후 보관하지 않는다. 실제 현금·결제는 없다. 출처: 사용자 요청. |
| 터미널 싱글 플레이 | 활성 | 혼자 Windows PC에서 먼저 플레이한다. 세 게임과 세션 자금의 동작을 터미널에서 구현한다. 출처: 사용자 요청. |
| 애니메이션 웹 표현 | 활성 | 터미널 이후 데스크톱 Chrome에서 플레이한다. 테이블 주변 여유 공간과 카드·숫자 가독성을 함께 원한다. 실사보다 애니메이션에 가까운 3D 느낌. 화면·조작 사례와 제작 방법을 조사한 뒤 미정 선택을 검토한다. 출처: 사용자 요청. |
| 멀티 플레이 | 보류 | 이후 확장 의도를 보존하되 현재 구현 범위에 포함하지 않는다. 근거: “나중에 멀티로 확장”, “아직은 아니고”. |

조사 자체와 그 범위 내 역할 분담은 허용됐다. 이번 실행에서는 네트워크·브라우저·subagent를 사용할 수 없어 메인이 로컬 원자료를 조사한다. 새로운 외부 계정·유료 서비스 사용과 제품 구현은 요청하지 않았다. 이번 대화는 Research 결론 검토까지이며 전체 Build 계획은 다음 대화로 미룬다.

## 미확인·충돌

- 세 게임의 나머지 규칙 변형, 베팅 범위·금액 단위·정산·커미션 반올림, 6덱의 셔플 조건. 구현 전 별도 합의로 보류한다.
- 초기 자금 입력 범위, 게임 선택·전환·자발적 종료, 파산의 정확한 판정과 잘못된 입력의 처리.
- 기존 제품 코드와의 연결 여부는 현재 디자인 문서 조사에 필요하지 않아 조사하지 않았다. 터미널과 웹의 구체적 입력·오류·복구·취소 동작은 미정이다.
- 웹앱의 조작 방식·카메라·구도·색·재질·애니메이션 범위·실패 시 표시, 제작 비용·자산 조건과 관찰 가능한 성공 기준.
- 문서 근거 비교는 가능하지만 시각·상호작용 체감과 실행 성능은 현재 자료로 검증할 수 없다. [R001](research/R001-table-interaction.md)과 [R002](research/R002-animation-production.md)에서 비교와 미확인을 분리한다.
- 향후 멀티는 미래 맥락만 보존한다. 네트워크 기반 구조나 멀티 대비 계층은 현재 합의에 포함하지 않는다.
