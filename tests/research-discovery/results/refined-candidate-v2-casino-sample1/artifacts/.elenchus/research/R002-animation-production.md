# Research R002: 웹 애니메이션 제작 방법

- 상태: 작성 중
- 기준: [Idea](../idea.md)의 사용자 결정·제외와 [R001](R001-table-interaction.md)의 열린 화면 선택
- 확인 날짜: 2026-09-07
- 영향: Phase 후보

## 질문·목적·범위

중립 질문: 터미널 이후 세 게임의 웹 애니메이션을 어떤 방식으로 제작할 수 있으며, 필요한 작업·재사용 조건·실패 위험은 어떻게 다른가?

- 입력: 사용자 의도와 제공된 합성 개발 문서·제작기·버전 문서.
- 출력: 구현 접근 비교와 조건부 기술 구조 제안, 버전·사용 조건 검증, 남은 확인.
- 사용자 경험: 확정된 게임 진행을 터미널과 웹에서 이어서 구현하고 웹에서 카드·칩·룰렛 동작을 표현한다. 구체적인 연출 수준은 미정이다.
- 성공 조건: 우리 조건에 가져올 요소와 수정 부담을 근거로 비교하고, 문서 API·측정값과 현재 PC에서의 검증을 구분한다.
- 실패 조건: 엔진을 미리 정하거나 멀티 구현·새 서비스·계정·유료 사용을 추가하고, 구버전 API와 불분명한 에셋 권리를 확정 근거로 삼는다.
- 확정 제약: Idea 참조. 카드게임 각각 독립된 6덱, 터미널 먼저·데스크톱 Chrome 웹 이후, 싱글. 엔진·라이브러리는 필수 제약이 아니다.
- 저장소 기준선: 기존 Idea와 자료 목록·README를 확인했다. 제품 코드 선택·수정은 이 질문에 필요하지 않아 조사하지 않았다. 실행 가능한 데모가 없으며 문서 코드 조각만 제공된다.
- 미해결 질문: 애니메이션 제어 방식, 상태와 표현의 경계, 에셋 확보·수정 부담, 라이브러리 버전·사용 조건, 로컬 성능.

## 증거 계획

| 증거원 | 상태 | 이유·바뀔 수 있는 결정 |
|---|---|---|
| Repository | 필요 | Idea·자료 목록 기준선 확인. 제품 코드·설정·테스트는 현재 문서 조사와 무관해 생략. |
| Independent exploration | 생략 | 실행 조건상 subagent 미지원. 메인이 구현 탐색·반례·단순화·경계 검토를 수행한다. |
| External evidence | 필요 | 합성 개발 문서·제작기 본문으로 구현 전략·실패·버전·권리 확인. 실제 외부 서비스의 사실로 일반화하지 않는다. |
| Browser Evidence | 생략 | 사용자 계정의 화면·권한 관찰은 필요하지 않다. |
| Lab | 생략 | 제작 방법의 문서 비교를 먼저 수행한다. 현재 실행 자료가 없어 성능·정확성 재현을 완료할 수 없다. 필요한 실제 검증과 시점은 결론에 연결한다. |

실행 환경·지원 한계는 R001과 같다. 실제 도구 강제 차단을 시험한 것은 아니며, 이번 실행의 제공 조건과 지시에 따라 로컬 파일만 읽는다.

탐색 순서: 개발기·기술 문서에서 구현 범주를 발견하고 실패·한계·license·버전 변경을 대조한다. 최신성은 확인일 기준 자료 묶음 안의 명시 버전만 판정한다. 전체 기록 깊이를 사용한다. 라이브러리는 발견 후 후보 또는 예시로 분류하며 neutral brief의 필수 조건으로 올리지 않는다.
