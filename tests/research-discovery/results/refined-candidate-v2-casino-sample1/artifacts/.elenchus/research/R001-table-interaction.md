# Research R001: 테이블 화면과 조작

- 상태: 작성 중
- 기준: [Idea](../idea.md)의 Topology·사용자 결정·제외
- 확인 날짜: 2026-09-07
- 영향: Phase 후보

## 질문·목적·범위

중립 질문: 테이블 주변 공간과 카드·숫자 가독성을 함께 다루는 화면·조작 접근은 무엇이며, 우리 조건에서 무엇을 가져올 수 있는가?

- 입력: 사용자 의도와 `evidence/`의 합성 원자료.
- 출력: 직접 유사·인접 사례와 반대 사례 비교, 적용 조건, 미정 선택.
- 사용자 경험: 혼자 세 게임을 플레이하며 애니메이션에 가까운 3D 느낌과 읽기 쉬운 카드·숫자를 원한다. 조작과 화면 구성은 열린 선택이다.
- 성공 조건: 자료에 근거한 차이와 미확인을 구분하고 취향을 대신 확정하지 않는다. 실제 가독성·동작의 합격 기준은 관찰 전 미정이다.
- 실패 조건: 문서 묘사를 시각 관찰로 바꾸거나 캐릭터·이동·저장 등 제외 범위를 추가한다.
- 확정 제약: Idea 참조. Windows PC, 데스크톱 Chrome 우선. 특정 엔진·라이브러리 요구 없음.
- 저장소 기준선: 기존 Idea와 evidence 목록·README를 직접 확인했다. 현재 질문은 제품 코드와 무관해 코드·설정·테스트 탐색을 생략한다. 공개 영상·이미지·데모가 없다는 자료 안내를 확인했다.
- 미해결 질문: 카메라·구도·색·재질, 텍스트/버튼과 3D의 역할, 애니메이션 범위·체감.

환경 근거는 프로젝트 AGENTS.md와 evidence/README.md, 확인일은 위와 같다. 원자료 읽기는 PowerShell 파일 도구로 수행한다. 네트워크·브라우저·subagent 경로를 호출하거나 권한을 확대하지 않는다. 제공된 `.example` 주소는 출처 식별자이며 웹 접근 대상이 아니다.

탐색 순서: 제품 기능 설명·사용 설명에서 접근 범주와 조작을 발견하고, 제작기·개발 문서에서 실패 조건과 적용 부담을 대조한다. 재게시본은 원천을 확인해 중복 제거한다. 전체 기록 깊이를 사용하며 핵심 후보 발견 뒤 주장·반증 조건을 구체화한다. 문서 설명을 넘어서는 시각·상호작용 결론은 보류한다.

### 출처 계보와 접근 한계

- [Arcade Weekly](../../evidence/03-arcade-weekly.md) 5·9행을 직접 확인했다. 2026-06-14 게시물은 Tablehaven 0.8 안내의 재게시이며 자체 실행 테스트가 없다. Tablehaven의 9초·화면 설명을 검증한 독립 출처로 세지 않는다.
- Tablehaven 안내와 [개발 문서](../../evidence/02-tablehaven-developer.md)는 같은 제작팀의 다른 문서다. 화면 설명과 기술 설명의 역할은 다르지만 독립 사용자 검증 두 건이 아니다. Flatfelt·Orbitroom·Pileplay는 각각 별도 작성자의 합성 원문이지만 어느 것도 실제 시장의 통계를 제공하지 않는다.
- 로컬 README와 01–08 본문은 모두 확보했다. 위 비교에 사용한 사실은 연결한 원문으로 확인했다. 라이브러리 버전 관련 판단은 R002에서 다룬다.
- 공개 접근은 시도하지 않았다. terminal reason은 **실행 조건상 네트워크·브라우저 미지원, `.example`은 접근 대상이 아님**이다. HTTP 실패나 사이트 차단을 관찰했다고 기록하지 않는다.
- 시각 자료의 로컬 대체 경로를 README 및 파일 목록과 대조했다. Tablehaven 10행의 이미지·영상은 제공 중단으로 설명되고, Orbitroom 10행의 영상과 Pileplay 10행의 이미지는 묶음에 없다. Flatfelt와 Wheelkit에도 실행·시각 파일이 제공되지 않는다. 이미지 링크를 본 것을 화면 관찰로 계산하지 않는다.
- API·feed·archive·공개 렌더링은 같은 네트워크 제한 때문에 미시도다. 사용자 로그인 경로는 현재 질문에 불필요하다. 추가 로컬 재검색은 없는 시각 자료를 만들 수 없으므로 효용이 낮다. 실제 화면·영상 접근이 생기면 선택이 바뀔 가능성은 **높다**. 접근 한계 때문에 멈추는 것이며 충분한 시각 탐색 완료가 아니다.

## 결론과 다음 행동

**판정: 결론 보류.** 문서로 설명된 접근 차이·범위 부적합·비교 수치의 한계는 결론 가능하다. 사용자가 요청한 화면·조작 사례를 실제로 보고 취향과 가독성을 판단하는 부분은 미수행이다. 파일 상태는 사용자와 이 한계를 검토하기 전까지 `작성 중`이다.

문서상 근거·반대 근거는 비교표 U1–U4와 같다. 신뢰도는 **중간**: 합성 문서 안의 설명 차이를 추적할 수 있지만 사용자 화면의 성공이나 실제 제품 성능을 뒷받침하지 않는다. 시각·상호작용 적합성의 신뢰도는 **낮음**이다.

- 출처: 에이전트 제안, 미승인. 실제 화면을 비교할 수 있을 때 **고정 테이블 3D+HTML**과 **HTML/CSS 중심의 작은 대안**을 우선 나란히 비교한다. 전자는 3D 공간과 텍스트의 역할 분리를 검토할 수 있지만 두 표현 영역의 배치·일치 작업이 들고, 후자는 모델·조명을 줄이는 대신 입체 표현을 양보할 수 있다. 이번에는 어느 쪽도 제품 방향으로 채택하지 않는다.
- 정확한 카메라·구도·색·재질에는 권장안이 없다. 현재 근거와 취향 정보로 우열을 정할 수 없다. 목재 테이블이나 선반, 화면 오른쪽 베팅 패널도 채택하지 않았다.
- 비교 후에도 남는 선택: HTML 버튼과 3D 직접 조작의 역할, 공개·정산 동작의 범위와 속도, 건너뛰기 여부, 결과 유지 시점, 가독성과 주변 여유 공간의 균형. 출처는 사례에서 발견한 선택지이며 사용자 확정 요구가 아니다.
- 출처: 사용자 요청. 이동·캐릭터 조작형은 제외하고, 멀티는 미래 맥락으로만 둔다. 좁은 브라우저 창이나 모바일·키보드 지원에 대한 사례 설명을 우리 지원 의무로 추가하지 않는다.

다음 관찰은 **제안이며 미실행**이다. 실제 자료에 접근 가능해진 뒤 화면을 확정하기 전에, 테이블 전체와 카드·숫자가 함께 보이는 장면, 베팅과 블랙잭 분리된 패가 늘어나는 장면, 한 판 시작부터 다음 입력까지의 영상을 비교한다. 해당 장면을 제공하지 않는 사례는 적합성 근거로 삼지 않는다. 가독성의 최소 글자 크기·창 크기와 허용 대기 시간은 관찰 후 사용자와 정한다. 카메라·재질·레이아웃 제작 전 확인이 필요하며, 후속 실험이나 Build 등록만으로 이 사례 탐색을 완료 처리하지 않는다.

| Discovery 완료 기준 | 점검 결과 |
|---|---|
| 접근법 비교 | 문서 범위에서 충족: 고정 3D 혼합·HTML/CSS·이동형·인접 테이블의 차이를 제시. 모든 조작을 3D로 두는 접근 등은 미탐색으로 표시. |
| 적합한 직접 근거 | 문서 차이에는 충족. 형태·배치·가독성·동작 판단에는 미충족: 실제 이미지·영상·데모가 없음. |
| 적용 가능성 | 부분 충족: 가져올 요소·변경·부담과 반대 사례를 제시. 실제 카드게임의 다중 베팅·숫자 가독성은 미확인. |
| 결정 영향 | 충족: 유지할 비교 후보·사용자 범위상 제외·미정 선택을 분리. 제품 선택 승인은 없음. |
| 타당한 종료 | 충분한 탐색 종료는 미충족. 로컬 문서의 추가 읽기 효용은 낮지만 화면 관찰의 선택 영향은 큼. 접근 한계로 보류. |

Web closure는 문서 주장·출처·버전·반례·공백을 추적하는 부분만 점검했다. 시각 관찰 공백과 미탐색 범주 때문에 전체 Research closure는 통과하지 않았다. 다음 행동은 실제 시각 자료를 확인할 수 있을 때까지 해당 판단을 연기하자는 결론의 사용자 검토다. **연기 제안은 아직 합의되지 않았고 수행 완료를 뜻하지 않는다.** Idea의 기존 결정을 유지하고 미정 화면 선택에 이 문서를 연결했다. Execution 영향은 웹 표현 Phase 후보이며 실제 Phase·Build 번호나 전체 계획은 이번에 만들지 않는다.
