# Research R001: 테이블 화면과 조작

- 상태: 작성 중
- 기준: [Idea](../idea.md)의 Topology, 사용자 결정, 제외, 미확인·충돌
- 확인 날짜: 2026-09-07
- 영향: Phase 후보
- 판정: 결론 보류. 문서상의 접근 차이는 비교 가능하나 실제 시각·동작 적합성은 판단할 근거가 부족하다. 사용자 결론 확인 대기다.

## 질문·목적·범위

목적은 탐색·벤치마킹이다. 테이블 주변 공간과 카드·숫자 가독성을 함께 다룰 화면·조작 방식을 비교한다. 제품 기능과 규칙을 추가하거나 엔진을 먼저 정하지 않는다. 확정 제약은 Idea를 따른다.

| Neutral brief 항목 | 내용 |
|---|---|
| 입력 | 사용자 요구, 제공된 합성 사례의 화면·입력 설명, 저장소 기준선 |
| 출력 | 접근별 차이·적용 부담·한계를 비교하고 미정 선택과 다음 관찰 대상을 제시한 Research 결과 |
| 사용자 경험 | 혼자 데스크톱에서 세 게임을 하며, 주변 여백이 있는 테이블과 읽기 쉬운 카드·숫자, 애니메이션에 가까운 3D 표현을 경험하려 함 |
| 성공 조건 | 근거 수준을 구분한 비교가 사용자의 후속 선택에 도움을 줌. 실제 시각 선택에는 화면, 속도·연속 조작 선택에는 영상·동작 근거가 필요함. 정확한 구도·가독성 기준은 아직 미정 |
| 실패 조건 | 소개 문장을 실제 화면 관찰로 바꾸거나, 카메라·색·재질·새 기능·체감 기준을 대신 확정함 |
| 확정 제약 | Idea의 Windows/Chrome·싱글·범위 제외·조사 한정 조건. 특정 엔진·라이브러리 필수 조건 없음 |
| 객관적 기준선 | `../../app.txt`는 `UNIMPLEMENTED PRODUCT STUB`. 기존 렌더러를 유지해야 한다는 근거 없음. `../../evidence/README.md`와 `../../AGENTS.md`가 로컬 합성 문서·접근 한계를 명시함 |
| 미해결 | 카메라·구도·색·재질, HTML/3D 역할, 베팅 입력, 공개/결과/다음 행동의 흐름, 실제 가독성·체감 |

사용자가 언급한 기술의 분류: Windows PC와 데스크톱 Chrome은 사용 환경이고, 엔진·라이브러리 지정은 없다. 자료에서 발견한 HTML/CSS·3D 결합은 비교 후보다. 사례의 목재·카메라·공개 속도는 예시이며 제약으로 승격하지 않는다.

## 증거 계획과 접근 범위

| 증거원 | 상태 | 이유와 실제 수행·한계 | 바뀔 수 있는 결정 |
|---|---|---|---|
| Repository | 필요 | Idea, AGENTS, app.txt, evidence 안내를 읽음. 인증정보·사용자 설정은 접근하지 않음 | 기존 구현과 조사 범위 |
| Independent exploration | 생략 | 역할 분담 이점은 있지만 이번 실행은 AGENTS상 subagent 미제공. 메인이 사례·반례·작은 대안을 나눠 검토했으며 독립 에이전트 검증으로 보고하지 않음 | 대안 누락 가능성 |
| External evidence | 필요 | 로컬 원문 01~06을 읽고 비교. 공개 시각 관찰도 필요하나 파일·연결이 없음 | 화면·조작·제작 부담 |
| Browser Evidence | 생략 | 사용자 로그인·개인화 화면이 질문에 필요하지 않음. 공개 화면 관찰 불가는 위 External evidence 공백임 | 해당 없음 |
| Lab | 생략 | 현재는 사례 비교이며 렌더러·에셋·실행 데모가 없음. 문서나 대체 mock으로 실제 사례의 체감을 재현했다고 주장할 수 없음 | 향후 우리 환경의 가독성·속도 |

접근 순서는 저장소 기준선과 자료 목록 → 직접 유사 사례 01/04 → 03의 원천 확인 → 인접 사례 06과 반대 사례 05 → 제작 문제 02 대조였다. 파일 본문은 모두 확보했다. 재검토 대상어는 `카메라`, `HTML`, `결과`, `가리`, `시간`, `이미지`, `영상`, `재게시`이며 해당 문단을 직접 확인했다. 실제 웹 검색은 수행하지 않았다.

원천 URL·버전·작성자는 각 링크의 머리말에 있다. `.example`은 예약 도메인이므로 웹 접근 대상이 아니다. 01의 이미지/영상은 원문에서 제공 중단, 05의 영상과 06의 이미지는 묶음에서 누락으로 명시됐다. 로컬 대체 문서 02~06을 읽었지만 그림·움직임을 제공하지 않는다. 다른 공개 경로(API/feed/archive/브라우저)는 네트워크·연결 미제공 조건 때문에 미시도다. HTTP 오류나 브라우저 실패를 실제 관찰했다고 기록하지 않는다. 현재 경로의 종료 사유는 자료 부재와 제공 범위 제한이며, 시각 자료의 추가 효용이 낮다는 뜻은 아니다.

## 비교와 근거

아래 모든 화면·동작 설명의 관찰 수준은 **자료의 설명**이다. 직접 확인한 것은 문서 본문이며, 적용 판단은 **추론**이다. 실제 화면·영상·조작·측정은 **미확인**이다. 비교 대상은 모두 가상 제품으로 실제 제품 추천이나 시장 일반화의 근거가 아니다.

### 선택을 바꾸는 주장과 공백

전체 기록을 사용한다. 여러 후보·적용 범위·반례가 있어 단일 Claim 간소화 조건에 맞지 않는다. 최신성은 각 보관 문서 버전에 한정하고 다른 버전이나 실제 제품으로 확대하지 않는다.

| 주장 | 필요한 근거·반증 조건 | 현재 근거와 판정 | 다음 공백 |
|---|---|---|---|
| 화면의 숫자/조작과 3D 소품을 나누는 접근이 문서에 존재함 | 제작자 화면/입력 설명. 실제로 분리되지 않는다면 반박 | 01 6행, 독립된 인접 사례 06 6행: 확인(문서 설명 한정) | 우리 구도에서 가독성·몰입감을 동시에 만족하는지는 별도 |
| 이 접근이 원하는 애니메이션풍과 여백·가독성을 충족함 | 같은 장면의 실제 화면, 카드/숫자 크기·가림 확인. 공간을 확보하면 패/베팅이 읽히지 않으면 반박 | 화면 부재: 근거 부족. 05의 가림 문제, 06의 작은 토큰 문제는 위험을 보여 주지만 우리 결과의 증명은 아님 | 베팅 전 전체 화면, 카드 공개, 블랙잭 스플릿 화면, 룰렛 숫자판·공 정지 장면을 관찰 |
| 제공 속도 수치로 쾌적한 공개 속도를 고를 수 있음 | 영상/연속 조작과 사용자 선호. 단위·조건이 다르거나 불편하면 반박 | 01의 약 9초는 베팅 클릭→다음 베팅, 04의 180ms는 카드 한 장. 직접 속도 비교·최적값 채택은 근거 부족 | 시작→공개→결과→다음 베팅의 전체 흐름과 반복 플레이 관찰. 건너뛰기·결과 유지도 열린 선택 |
| HTML/CSS 대안이 실제 제작 시간을 얼마나 줄이는지 알 수 있음 | 같은 조건의 작업/성능 기록. 비교 환경 차이면 범위 제한 | 04의 제작자 설명만 있음: 범위 제한. 05의 기간은 팀·구매 범위가 달라 비교 불가 | 실제 에셋 범위와 작업 조건이 정해지기 전 시간·비용 수치 보류 |

전부 3D 장면 안에서 숫자·버튼까지 조작하는 방식, 사용자에게 맞는 여러 카메라/스타일 변형은 관련 대안이지만 제공 자료에 충분한 비교 사례가 없다. 이를 불가능·열등으로 배제하지 않는다. 공간 이동의 제외와 테이블 내부 3D 직접 조작의 보류는 다른 판단이다.

## 결론과 다음 행동

**문서 비교의 부분 결론:** 3D 테이블+HTML 조작을 우선 비교 후보로 제안하고 HTML/CSS 중심 대안도 유지한다. 근거는 01의 직접 유사 조건과 06의 주변 공간/정보 분리 설명이다. 반대 근거는 05의 가림 실패, 04의 더 작은 제작 범위, 실제 시각 자료의 부재다. 특정 카메라·색·재질에는 권장안이 없다. 모든 제안은 에이전트 제안이며 미승인이다. 원요청 대비 기능 추가는 없고 사례의 건너뛰기·확대·입력 잠금도 자동 채택하지 않는다.

**판정: 결론 보류.** 문서상의 차이에 대한 신뢰도는 중간(원문은 확인했으나 합성 제작자 설명), 우리 시각·동작 적합성은 낮음이다. 실제 제품의 품질·효과에 관한 결론은 내리지 않는다. 소품 과장이나 고정 사선 구도를 애니메이션풍의 검증으로 대체할 수 없다.

다음 관찰은 실제 화면/영상이 가능한 환경에서 위 Claim 표의 장면들을 같은 용도로 나란히 비교하는 것이다. 이는 미완료한 사례 탐색이며 우리 제품 Lab으로 대신 완료할 수 없다. 그 뒤 우리 환경에서 창 크기·카드/숫자 가독성·연속 입력을 확인하는 별도 검증이 필요하다. 자료가 없는 현재는 관찰 결과를 보류하고, 이 비교 결과와 보류 범위를 사용자에게 확인받는다. 관찰 연기를 이미 승인받았다고 기록하지 않는다.

| Discovery 완료 조건 | 이번 판정과 근거 |
|---|---|
| 1. 접근법 비교 | 부분 충족: 직접 유사·작은 대안·인접·반대 사례 비교. 테이블 내 전부 3D 조작과 시각 변형은 미탐색 |
| 2. 적합한 직접 근거 | 문서적 차이에는 충족; 시각·속도 판단에는 미충족. 실제 화면/동작 관찰 없음 |
| 3. 적용 가능성 | 부분 충족: 가져올 요소·변경·부담을 명시. 가독성·시간·성능·에셋 사용권 미확인 |
| 4. 결정 영향 | 충족: 우선 비교/유지/제외/보류와 이유를 제시하고 사용자 선택과 분리 |
| 5. 타당한 종료 | 미충족: 시각·동작 자료는 선택을 바꿀 효용이 큼. 현재 자료를 다시 읽어도 그 공백은 해결되지 않아 접근 한계에서 멈춤 |

Web closure도 전체 질문에서는 미통과다. 원문·날짜·중복·반대 근거·접근 제한·다음 행동은 추적 가능하지만 필수 시각 관찰과 미탐색 대안이 남는다. 좁은 문서 비교를 마친 사실로 Research 전체 완료를 주장하지 않는다.

Idea 영향: 열린 제품 선택과 위 미승인 제안을 연결했다. 사용자 요구·제약·제외는 유지한다. Execution 영향: 향후 웹 표현 관련 Phase 후보에 근거가 되지만 전체 Phase·Build와 번호는 이번 턴에 만들지 않는다. 사례 관찰은 시각 방향 채택 전에, 우리 환경의 표현 검증은 그 결과에 의존하는 본 제작 전에 필요하다. 상세 비교는 이 문서에만 둔다.
