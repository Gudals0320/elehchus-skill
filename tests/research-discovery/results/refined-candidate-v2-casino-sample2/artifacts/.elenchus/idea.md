# Idea: 룰렛·바카라·블랙잭 카지노 게임

- 상태: 작성 중
- 시작 요청: 룰렛·바카라·블랙잭을 할 수 있는 게임. 규칙을 적당히 합의한 뒤 터미널 기반 카지노 로직부터 구현하고, 이후 애니메이션이 구현된 웹앱 게임으로 확장한다. 핵심 고민은 3D 애니메이션이며 디자인 고찰과 레퍼런스 탐색이 필요하다. 싱글 구현이 우선이고 멀티는 나중이다. 향후 멀티를 고려해 카드게임은 6덱으로 생각한다. 게임 시작 때 초기자금을 정하고, 파산하면 게임오버이며 그렇지 않으면 계속 진행한다. 저장 기능은 현재 필요 없다.

## Topology

2026-09-07 사용자 응답으로 세 게임·세션 자금·터미널·웹 표현의 상위 구성을 확인했다. 아래 결정의 출처는 사용자 요청이다. 이전 묶음에서 게임 규칙과 자금을 구분하고 디자인·3D 탐색은 웹 표현의 조사 활동으로 정리했다. 새로운 제품 기능은 추가하지 않았다.

| 구성요소 | 상태 | 목표·산출물 | 요청 근거 |
|---|---|---|---|
| 세 게임 | 활성 | 싱글 제로 룰렛, 독립된 6덱의 바카라·블랙잭 | “카드게임은 각각 독립된 6덱”, “룰렛은 싱글 제로” |
| 세션 자금 | 활성 | 사용자가 입력한 초기자금을 세 게임에서 함께 쓰고, 파산하면 게임오버; 세션 종료 후 보관하지 않음 | “초기 자금을 입력하고 세 게임에서 함께”, “세션이 끝나면 보관하지 않습니다” |

## 사용자 결정

모두 출처는 사용자 요청이며 원요청의 범위 보존이다.

- 룰렛·바카라·블랙잭 세 게임만 포함한다. 룰렛은 싱글 제로다.
- 바카라와 블랙잭은 각각 독립된 6덱을 사용한다. 바카라 베팅은 플레이어/뱅커/타이, 뱅커 커미션은 5%다. 블랙잭은 더블·스플릿을 포함한다. 세칙과 베팅 단위는 구현 전에 따로 합의한다.
- 혼자 Windows PC에서 사용하며 웹은 데스크톱 Chrome을 우선한다. 싱글 구현이 먼저이며 멀티는 미래 맥락이다.
- 실제 현금이나 결제는 없다. 사용자가 시작할 때 초기자금을 입력하고 세 게임에서 함께 쓴다. 파산하면 게임오버이며 그렇지 않으면 계속 진행한다. 세션 종료 후 자금을 보관하지 않는다.
- 터미널 기반 구현 다음에 애니메이션 웹앱 게임을 구현한다.
- 디자인 고찰과 레퍼런스 탐색이 필요하며 3D 애니메이션 구현 방법이 핵심 고민이다.
- 테이블 주변에 여유 공간이 보이면서 카드와 숫자를 알아보기 쉬워야 한다. 실사보다 애니메이션에 가까운 3D 느낌을 원한다. 정확한 카메라·구도·색·재질은 사례를 보고 선택한다. 텍스트/버튼과 3D의 역할도 열려 있다.
- 특정 엔진·라이브러리는 필수가 아니다. 기술 구조는 조사 근거를 보고 제안받는다.
- 현재 조사는 디자인·상호작용 사례와 이 조건의 제작 방법에 집중한다. 조사와 그 범위 내 역할 분담은 허용했으나 이번 환경에서는 메인이 조사한다. 제품 구현과 새로운 외부 계정·유료 서비스 사용은 요청하지 않았다.
- 이번 대화에서는 사례 비교 결과와 미정 선택을 확인한다. 전체 Build 계획은 다음에 이어간다.

## 에이전트 제안

- 이전 상위 구성 확인 대기는 해소했다. 유효한 구성은 위 Topology를 따른다.
- 출처: 에이전트 제안 / 미승인. 웹의 3D 테이블과 HTML 숫자·버튼 결합을 우선 비교 후보로 두고 HTML/CSS 중심의 작은 대안을 함께 유지한다. 원요청 대비 기능 추가는 없다. 가독성과 공간 표현을 따로 조정할 여지가 생기지만 두 표현의 배치·상태를 맞출 부담이 있다. 후보 비교 근거와 시각적 한계는 [R001](research/R001-table-presentation.md)에 있다. 특정 카메라·색·재질을 권장하거나 확정하지 않았다.
- 출처: 에이전트 제안 / 미승인. 공통 규칙 처리와 터미널·웹 표현을 분리하고, 룰렛은 목표 결과를 표현하는 보간 경로를 검토한다. 터미널→웹에서 규칙을 재사용할 여지가 생기지만 사건 순서·포켓 좌표 검증이 필요하다. 새 서버나 멀티 기능을 추가하는 제안은 아니다. [R002](research/R002-animation-production.md)에 반대 근거와 적용 조건을 남겼다. 엔진·라이브러리·에셋 채택은 보류다.
- 건너뛰기, 확대, 입력 잠금, 결과 유지 등 사례의 기능은 비교 대상이며 제품에 추가하기로 합의하지 않았다.

- 카지노 공간 이동·캐릭터 조작은 필요 없고 플레이어·딜러 캐릭터도 요구하지 않았다. 이번 계획에 기능으로 추가하지 않는다.
- 현재 턴의 제품 구현, 새로운 외부 계정·유료 서비스 사용, 전체 Phase·Build 계획 작성은 범위 밖이다. 단, 계획·조사 문서는 현재 단계의 기록이다.

## 미확인·충돌

- 다음 질문: 문서 비교 결과와 시각·동작·실행 검증의 보류 범위를 이번 Research 결론으로 확정할지 확인한다. 제품 선택 승인과 조사 결과 확인은 구별한다.
- 문서 비교는 수행했지만 실제 화면·영상·조작 사례 관찰은 미수행이다. 해당 탐색을 완료로 계산하지 않는다. 관찰 재개·연기의 합의는 아직 없으며 Research 전체 closure도 통과하지 않았다.
- 카메라의 투영·각도·움직임, 구도·색·재질, 주변 여백과 카드·숫자 크기, HTML/3D의 역할, 베팅 조작, 공개 속도·건너뛰기·결과 유지·입력 잠금은 미정이다. 실제 사례의 같은 장면을 비교한 뒤 선택해야 한다.
- 에셋 제작·재사용 방식, 사용권·수정 부담, 엔진·라이브러리, Chrome에서의 성능과 지원 창 크기는 미확인이다. 합성 자료만으로 제작 시간이나 성능을 확정하지 않는다.
- 초기자금의 유효 범위·최소 베팅·잔액 부족·정산 반올림, 게임 선택·전환 시점, 자발적 종료·재시작·잘못된 입력·중단 후 동작은 구현 전 합의가 필요하다. 공통 자금 사용과 세션 종료 후 비보관은 확정이다.
- 세칙은 후속 합의다. 예: 바카라 제3카드·타이 배당·커미션 처리, 블랙잭 소프트 17·배당·더블/스플릿 허용 조건·재스플릿, 룰렛 베팅 종류·단위·한도, 독립 슈의 재셔플 시점. 예시를 새 규칙으로 확정하지 않았다.
- 터미널의 명령·표시·실행 방법, 웹의 로컬 실행 방식과 오류 복구도 후속 합의다. 부분 성공·빈 결과·취소가 게임별로 적용되는지는 이 동작들과 함께 분류한다.
- 전체 Build 계획과 사용자 경험의 성공 판정 세부는 다음 대화에서 이어간다. 현 단계의 목표 관찰은 세 게임의 공통 자금 반영·파산 종료·읽기 쉬운 카드/숫자이나, 수치·조작 기준은 대신 정하지 않았다.
- 확정 요청 사이에서 확인된 직접 충돌은 없다.
