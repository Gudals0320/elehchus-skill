# Idea: 룰렛·바카라·블랙잭 카지노 게임

- 상태: 작성 중
- 시작 요청: 룰렛·바카라·블랙잭을 즐기는 싱글 게임을 만든다. 먼저 터미널 기반 카지노 로직을 구현하고, 이후 애니메이션이 구현된 웹앱 게임으로 확장한다. 시작 시 초기 자금을 정하고, 파산하면 게임 오버, 아니면 계속 진행한다. 카드게임은 향후 멀티를 고려해 6덱 구성으로 생각한다. 저장 기능은 현재 필요 없다. 룰은 적당히 합의하되 3D 애니메이션의 구현 방식, 디자인 고찰과 레퍼런스 탐색에 특히 집중하고 싶다.

## Topology

사용자가 상위 구성을 확인했다. 출처: 사용자 요청. 활성 범위는 세 게임·세션 자금·터미널·웹 표현이며 추가 기능은 포함하지 않는다.

| 구성요소 | 상태 | 범위와 근거 |
|---|---|---|
| 카지노 로직·세션 | 활성 | 룰렛·바카라·블랙잭이 사용자가 입력한 초기 자금을 공유한다. 파산하면 게임 오버, 아니면 계속 진행한다. 카드게임마다 독립된 6덱이다. |
| 터미널 게임 | 활성 | “터미널 기반 작동하는 카지노 로직”, 첫 번째 구현 산출물. |
| 웹앱·3D 애니메이션·디자인 | 활성 | “애니메이션 구현된 웹앱 게임”, 3D 애니메이션 방법과 디자인·레퍼런스 탐색이 주요 고민. |
| 멀티플레이 | 보류 | 미래 맥락으로만 유지한다. 현재 구현·네트워크·서버 범위가 아니다. |

구성 확인은 완료되었지만 Idea 전체 closure는 하지 않았다. 룰·입력 실패 처리·시각 선택 등이 남아 있다. 사용자가 이번에는 디자인·상호작용·제작 방법 Research를 먼저 하고 세칙과 전체 Build 계획은 나중에 합의하도록 명시했으므로 그 순서를 따른다. 이 보류를 구현 위임이나 암묵적 합의로 취급하지 않는다.

## 확인된 사실

- 작업 조건: 현재 프로젝트의 `skill/SKILL.md`를 사용한다. 최초 Release 확인과 현재 버전 선택은 앞서 완료되었다.
- 이번 실행에는 네트워크·브라우저 연결·subagent가 제공되지 않는다. `evidence/` 자료는 가상 제품의 합성 문서이며 실제 제품의 사실로 취급하지 않는다.
- 2026-09-07 읽기 전용 기준선: `app.txt`는 `UNIMPLEMENTED PRODUCT STUB`이다. 확인한 루트 항목에는 제품 소스·manifest·lockfile이 없다. 기존 엔진·렌더러·규칙 구현을 전제로 할 근거가 없다. 인증정보와 사용자 설정은 읽지 않았다.
- 제공 자료에는 스크린샷·영상·실행 가능한 데모가 없다. 문서 본문 검토와 실제 화면·조작 관찰을 구별한다.

## 사용자 결정

- 출처: 사용자 요청. 게임은 룰렛·바카라·블랙잭 3개다.
- 출처: 사용자 요청. 혼자 Windows PC에서 사용하며 웹은 데스크톱 Chrome을 우선한다. 싱글을 먼저 만들고 멀티는 미래 맥락으로만 둔다.
- 출처: 사용자 요청. 사용자가 초기 자금을 입력하고 세 게임에서 함께 쓴다. 파산하면 게임 오버, 아니면 계속 진행한다. 세션 종료 후 자금을 보관하지 않는다. 실제 현금이나 결제는 없다.
- 출처: 사용자 요청. 바카라와 블랙잭은 각각 독립된 6덱이다. 룰렛은 싱글 제로다. 바카라는 플레이어/뱅커/타이와 뱅커 5% 커미션, 블랙잭은 더블·스플릿까지 포함한다. 세칙과 베팅 단위는 구현 전에 별도로 합의한다.
- 출처: 사용자 요청. 구현 순서는 터미널 기반 → 애니메이션 웹앱이다.
- 출처: 사용자 요청. 룰 합의보다 3D 애니메이션 방법·디자인 고찰·레퍼런스 탐색이 핵심 고민이다.
- 출처: 사용자 요청. 카지노를 돌아다니거나 캐릭터를 조작할 필요가 없고 플레이어·딜러 캐릭터도 없어도 된다. 테이블 주변에 여유 공간이 보이고 카드·숫자는 읽기 쉬워야 한다. 실사보다 애니메이션에 가까운 3D 느낌을 원한다.

- 출처: 사용자 요청. 이번에는 디자인·상호작용 사례와 제작 방법을 조사하고 근거를 보고 기술 구조를 제안한다. 연구 자체와 범위 내 역할 분담은 허용되지만 현재 환경에서 subagent는 사용할 수 없다. 제품 구현과 새 외부 계정·유료 서비스 사용은 요청하지 않았다.
- 출처: 사용자 요청. 이번 대화는 Research 결론 확인까지, 전체 Build 계획은 다음 대화로 미룬다. 원자료에 없는 취향·기능을 대신 확정하지 않는다.

## 미확인·충돌

- 상위 구성과 Research 진행 의사는 답변으로 확인되었다. 같은 범위를 다시 승인받지 않는다.
- 구현 전 합의: 게임별 세칙·베팅 단위·커미션의 금액 정밀도와 반올림·셔플 시점·블랙잭 더블/스플릿 제한, 자금 입력과 게임 전환·종료·실패 동작. 구체적 값을 대신 정하지 않는다.
- 화면을 보고 합의: 카메라 각도·구도·테이블 주변 여백·색·재질·소품 크기·HTML과 3D의 조작 분담·애니메이션 속도 및 생략 여부·결과 유지 방식. 원자료의 설정은 사용자 선호가 아니다.
- 근거가 더 필요한 항목: 대상 PC/GPU와 창 크기·Chrome 버전별 성능/가독성, 에셋 제작·사용권, 실제 사용할 언어·엔진·라이브러리, 휠의 공·회전판·번호 정합성. 각각 관련 Research에 보류와 다음 검증을 연결한다.
- Idea의 전체 종료 확인과 Execution의 Phase·Build 합의는 후속 대화 대상이다.
- 현재 확인된 충돌 없음.
