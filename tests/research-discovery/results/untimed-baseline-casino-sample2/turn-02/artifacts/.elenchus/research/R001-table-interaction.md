- 상태: 작성 중
- 기준: [idea.md](../idea.md)

- 영향: Phase 후보
- 판정: 결론 보류 — 문서에 서술된 사례 비교는 가능하지만, 실제 화면·조작 관찰과 사용자 취향을 요하는 디자인 채택은 보류한다. 이번 Research 결과 확인 전이다.

## Repository 기준선과 Neutral brief

관찰: `app.txt`의 본문은 `UNIMPLEMENTED PRODUCT STUB`다. 기존 화면·구현 스택·에셋의 기준선은 없다. `.elenchus/idea.md`에는 현재 사용자 결정이 반영됐다. `evidence/README.md`와 아래 원문 본문을 읽었다. 모든 사례는 가상 제품의 합성 문서이며 실제 제품 사실이나 관찰 결과가 아니다.

| 항목 | 중립 조사 조건 |
|---|---|
| 질문 | 테이블 주변 공간과 카드·숫자 가독성을 함께 다룰 화면·상호작용 방식은 무엇인가? |
| 입력 | 사용자가 합의한 세 게임·세션 자금·터미널 이후 웹 표현, 제공된 문서형 사례 |
| 출력 | 화면·정보 배치·입력·라운드 흐름별 비교, 조건부 후보와 부적합 사례, 선택에 부족한 증거 |
| 사용자 경험 | 혼자 Windows PC에서 사용. 데스크톱 Chrome 우선. 테이블 주변에 여유가 보이고 카드·숫자를 읽을 수 있는, 실사보다 애니메이션에 가까운 3D 느낌 |
| 성공 조건 | 문서의 설명과 해석을 구분하고 각 사례의 적용 가능 부분·손실·미정 선택을 제시한다. 이것은 조사 성공 기준이며 제품 가독성 검증 완료를 뜻하지 않는다. |
| 실패 조건 | 문서를 화면 관찰로 보고함, 재게시를 독립 검증으로 셈, 설정값을 사용자 선호로 확정함, 이동·캐릭터 등 새 기능을 추가함 |
| 확정 제약 | 싱글 우선, 게임 간 공유하는 세션 자금·미보관. 현금·결제·저장·계정·공유·통계 제외. 멀티는 미래 맥락. 이동·캐릭터 조작 불필요. 캐릭터 제작을 범위에 넣지 않음. 새 계정·유료 서비스·제품 구현 없음 |
| 환경 사실 | Windows/PowerShell, 2026-09-07. 프로젝트 지침상 네트워크·브라우저·subagent 사용 불가. 스크린샷·영상·데모 없음. 로컬 문서 본문만 접근 가능 |
| 미해결 | 시점·구도·색·재질, HTML/3D의 역할, 베팅 조작, 진행 속도·애니메이션 중 입력, 가독성 판정 화면 크기 |

사용자 기술 언급 분류: Windows는 현재 사용 환경, 데스크톱 Chrome 우선은 지원 제약이다. ‘애니메이션에 가까운 3D 느낌’은 경험 목표이며 특정 렌더러가 아니다. 엔진·라이브러리 필수 지정은 없다. 아래 제품 이름과 HTML/CSS 구성은 자료 속 사례/후보다.

## 사례 비교와 후보의 핵심 차이

다음은 문서가 설명하는 화면·행동이다. 직접 보거나 조작한 사례가 아니다.

| 사례 | 화면·정보 배치 | 조작·진행 | 우리 조건에 활용할 점 | 손실·반대 근거 |
|---|---|---|---|---|
| Tablehaven 0.8 | 캐릭터 없는 고정 사선 테이블, 3D 목재·카드·칩, HTML 점수·잔액·버튼. 룰렛은 오른쪽 2D 베팅판 [E1] | 카드 라운드 약 9초, 공개 건너뛰기, 다음 입력 전까지 결과 유지 | 단일 테이블과 별도 숫자/입력 영역을 비교할 가장 가까운 문서 사례 | 목재·고정 사선·패널 위치는 사용자 취향이 아님. 기본 1600×900과 1024px 분기 또한 우리 기준으로 미채택. 키보드만으로 전체 플레이 미지원 |
| Flatfelt 2.1 | HTML 카드 이미지, 약한 CSS 원근, 이미지 휠과 별도 공 레이어 [E4] | 카드당 180ms 설정 예시, 승패·판 전체 금액 한 줄, 즉시 다음 베팅 | 가독성과 입력을 레이아웃 안에서 다루는 축소 대안 | 장면 조명·3D 모델·입체 재질 없음. 원하는 3D 느낌을 충족할지는 미확인. 제작 파일 감소는 작성자 설명이며 비교 측정 아님 |
| Pileplay | 테이블 전체와 주변 선반 일부, 하단 행동 띠. 토큰 색·높이를 과장 [E6] | 정산 후 다음 행동. 확대 중 게임 입력 차단과 닫기. 변경된 토큰만 이동 | 주변 여유 공간을 보이면서 중요한 소품을 과장하는 디자인 참고 | 보드게임으로 다중 베팅·작은 숫자 밀집 사례 없음. 확대·선반·입력 차단은 우리 기능으로 추가하지 않음 |
| Orbitroom | 이동하는 아바타와 홀, 테이블 도착 후 근접 카메라. 참가자·딜러 표시 [E5] | 멀티 중심, 로컬 싱글 모드 없음. 캐릭터 가림을 외곽선·패널로 보완 | 불필요한 공간·캐릭터가 작업과 가림 문제를 늘리는 반례 | 현재 목표와 불일치. 홀·이동·좌석·캐릭터·외곽선 기능을 가져오지 않음 |

출처 관계: E1·E2는 같은 제작팀이고 E3는 E1 재게시다. 셋을 독립 제품 세 개나 세 번의 UX 검증으로 세지 않는다. E4·E5·E6은 묶음 안에서 다른 작성자의 사례이지만 모두 합성 자료이며 실제 시장 관행을 증명하지 않는다.

| C3 | E1·E4의 진행 방식 설명 | 전체 라운드와 카드당 시간은 비교 불가, 선호 조사 없음, E2 빠른 넘김 직후 경계 | 없음 | 설정·동작 설명에 한정 | 범위 제한 | 속도·건너뛰기·입력 잠금 미정. 후보 화면의 반복 플레이 관찰로 연기 |
| C4 | E4 기능 축소, E5 별도 공간 작업·로컬 미지원 | 비용의 동일 조건 측정 없음; CSS가 3D 목표를 충족한다는 증거 없음 | 없음 | 범위 손익 비교 | 범위 제한 | Orbitroom 방식은 현재 범위에서 제외. CSS는 요구 완화 시 대안으로만 유지 |

공백 갱신: 최초 기능 설명 비교 뒤 C2의 실제 시각 근거와 C3의 속도 의미를 우선 점검했다. 재게시 E3와 누락 매체 표기를 확인해 시각 증거가 늘지 않음을 확인했고, E4·E5·E6 및 E2에서 한계·반례를 보완했다. 로컬 검색 범위는 `evidence/` 8개 원문과 README이며 관련 없는 자료나 사용자 설정은 조사하지 않았다. 같은 텍스트를 더 읽어도 구도·화풍·조작감 판단은 바뀌기 어렵다. 실제 매체가 추가되면 결론이 바뀔 가능성이 크다.

## 조건부 제안과 미정 선택

모두 출처: 에이전트 제안, 미승인이다. 사용자가 얻는 것과 부담을 비교한 후보이며 제품 요구 추가가 아니다.

| 제안 | 원계획 대비 변화·얻는 것 | 부담·사라지는 것 | 권장 여부 |
|---|---|---|---|
| 단일 3D 테이블 + 화면상의 숫자·버튼을 먼저 시각 비교 후보로 둠 | 기능 추가 없음. 주변 공간 연출과 읽는 영역을 따로 검토 가능 | 3D 장면과 화면 레이아웃 두 영역의 연결·공간 배분 필요 | 후보 비교의 출발점으로 권장. E1과 E6의 문서 패턴, 사용자 가독성 목표에 근거. 최종 선택 아님 |
| CSS 원근·이미지 표현 | 제작 대상을 줄이는 요구 축소 후보 | 진짜 장면 조명·입체 재질을 잃음. 제작 시간이 얼마나 줄지는 모름 | 3D 목표를 완화할 때만 동등한 대안. 자동 대체하지 않음 |
| 베팅까지 3D 장면에서 직접 입력 | 테이블을 직접 다루는 느낌을 비교할 미검증 후보 | 작은 클릭 영역·가림·텍스트 판독을 확인해야 함 | 현재 자료로 권장안 없음. 별도 기능/구조로 확정하지 않음 |
| 카메라·색·재질·속도·건너뛰기 선택을 미룸 | 근거 없는 취향 확정을 피하고 현재 범위 보존 | 시각 설계의 최종 결론은 이번에 얻지 못함 | 실제 매체가 없는 현재 조건에서 권장 |

목재, 선반, 고정 사선 각도, 밝은 색, 특정 재질, 확대, 공개 건너뛰기, 자동 진행, 효과음·음악을 사용자가 정한 취향/기능으로 기록하지 않는다. 키보드·접근성·모바일 지원도 타 제품의 지원/미지원을 그대로 채택하지 않는다.

후속 관찰 항목은 검증 요구만 남긴다. 같은 데스크톱 창에서 테이블 주변과 카드 랭크·무늬·잔액·현재 베팅·가능한 행동을 함께 판독할 수 있는지, 룰렛 숫자 밀집과 블랙잭 스플릿 패에서도 가능한지 확인해야 한다. 화면 크기·속도·입력 방식의 수치는 사용자 선택 전 설정하지 않는다. 실제 이미지·영상 확보 또는 추후 별도 합의한 시각 시안 비교가 필요하며 이번에는 생성하거나 구현하지 않았다.

## Web closure·Verdict·후속 영향

- 접근·출처 점검: 사용한 본문·날짜·버전·중복 관계를 연결했고 반대·실패 자료를 확인했다. C2는 근거 부족을 유지하며 실제 시각 선택을 연기한다. Browser/Lab은 수행하지 않았다. 문서 검토의 종료를 실제 UX 검증 완료로 바꾸지 않는다.
- 판정: **결론 보류**. 화면·상호작용 방식의 비교 결과는 제시 가능하나 특정 디자인의 적합성·채택은 미결정이다.
- 근거: E1의 가까운 화면 구성, E6의 주변 공간·가독성 조정, E4의 단순 표현 대안.
- 반대 근거: E5의 가림·공간 작업, E6의 카지노 적용 한계, E1/E4의 비교 불가능한 속도 설정, 시각 매체 결손.
- 후보·채택/제외: 3D 테이블+별도 텍스트/입력을 우선 비교 후보로 제안. CSS 축소와 3D 직접 입력은 위 손익으로 남김. 이동·캐릭터·멀티 중심 구성은 사용자 범위에 따라 제외. 디자인 채택은 없음.
- 신뢰도: 문서 내용과 범위 비교는 중간, 실제 시각 적합성·조작감은 낮음. 실제 제품 효과·성능에 대한 근거는 아님.
- Idea 변경: 사용자 결정·제외를 유지하고 시각 선택과 애니메이션 조작을 미확인으로 남김. 상세 제안은 이 문서에만 둠.
- Execution 영향: 웹 표현 Phase 후보에 후속 시각 비교가 필요하다. 실제 Phase/Build ID·전체 계획·일정은 이번에 만들지 않음.
- 다음 확인: 이 문서의 비교 결과와 디자인 채택 보류를 이번 Research 결과로 남길지 사용자 확인이 필요하다. 구현·새 기능·기술 선정 승인을 묶지 않는다.
