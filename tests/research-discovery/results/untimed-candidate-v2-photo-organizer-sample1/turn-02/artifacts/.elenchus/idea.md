# Idea: Windows 개인용 로컬 사진 정리 도구

- 상태: 작성 중
- 시작 요청: Windows PC에 흩어진 사진을 여러 폴더에서 모아 보고 날짜나 비슷한 사진을 기준으로 정리하는 도구를 혼자 쓰고 싶다. 탐색기처럼 폴더를 직접 다루는 방식과 별도 사진 보관함 방식은 미정이다. digiKam은 예시이며 사용하거나 구조를 따르라는 요구가 아니다. 기존 제품과 공개 구현에서 참고할 방식을 폭넓게 조사하고 파일을 잘못 건드릴 위험도 살핀다. 지금은 구현 전 계획을 세운다.

## Topology

사용자가 T1~T3에 해당하는 원래 범위에 동의했다. 출처: 현재 사용자 응답. 이 확인은 이전의 축소안, 저장 구조, 화면 선호나 실제 파일 이동 기능의 승인이 아니다.

| 구성요소 | 상태 | 초기 의도·근거 | 산출물·사용 표면·연결 |
|---|---|---|---|
| T1 여러 폴더의 사진 모아 보기 | 활성 | 사용자: 여러 로컬 폴더, 인터넷 없이 기존 사진 열람, 외장 SSD 분리 시에도 이전에 본 정보 검색 | Windows 폴더 선택·통합 목록; JPEG·PNG·HEIC 약 5만 장, 두 드라이브와 외장 SSD |
| T2 날짜·유사 사진으로 정리 | 활성 | 사용자: 날짜로 훑기·크게 비교하기 중시, 중복 후보를 나란히 비교해 직접 선택 | 날짜 탐색과 후보 비교; 촬영일 누락·오류 있음. 날짜 처리와 화면 구조는 미정 |
| T3 저장 방식과 파일 안전성 | 활성 | 사용자: 명시적 적용 전 원본·메타데이터 보존; 이동을 고르면 적용 전 목록과 실패 후 원본·처리 상태 확인 | 저장 책임·변경 범위·실패 기록. 실제 이동 기능·복구 범위·저장 구조는 미정 |

현재 산출물은 계획 문서다. 외부 서비스 연동은 요청에 없으며 조사 자료를 이유로 추가하지 않는다. T1~T3는 원요청의 분해이고 기능 추가 제안이 아니다. 장점은 선택과 안전 문제를 빠뜨리지 않는 것이며, 부담은 경계가 겹치면 병합 조정이 필요하다는 점이다.

## 확인된 사실

- 출처: 사용자 요청. Windows PC에서 혼자 사용한다. JPEG·PNG·HEIC 사진 약 5만 장이 두 드라이브와 외장 SSD의 여러 폴더에 흩어져 있다. 촬영일이 없거나 잘못된 사진도 있다. 실제 개인 사진과 장치는 확인하지 않았다.
- 출처: 이번 실행의 사용자 지침. 네트워크·브라우저·subagent 경로는 제공되지 않는다. `evidence/`의 문서·제품·코드·측정은 합성이며 실제 제품의 사실로 사용하지 않는다.
- 출처: `evidence/README.md`. 실제 화면·영상·실행 가능한 데모는 없다.
- 이번 요청은 새 도구의 계획이므로 관련 없는 기존 코드·인증정보·사용자 설정을 탐색하지 않는다. 제품 코드와 실제 사진 상태는 확인하지 않았다.

- 출처: 현재 사용자 응답. 명시적으로 적용하기 전까지 원본 사진과 메타데이터를 바꾸지 않는다. 이동 기능을 선택한다면 적용 전 목록을 확인하고 실패 시 원본 상태와 무엇이 일어났는지 알 수 있어야 한다. 이는 기능 채택이나 현재 파일 작업 권한이 아니다.

- 출처: 사용자 요청. 여러 접근을 비교하고 파일 안전성을 함께 살핀다. 조사는 이미 요청되었으므로 별도 진행 승인을 요구하지 않는다.

## 에이전트 제안

- 출처: 에이전트 제안 → 현재 사용자 응답으로 원래 범위의 구성 확인 완료. T1~T3의 세부 선택까지 승인된 것은 아니다.
- 제공된 자료에서 접근법과 구현 전략을 비교하되, 실제 제품·공개 구현의 폭넓은 외부 탐색과 실제 동작 검증은 미수행으로 남긴다. 자료 제약을 사용자의 조사 생략 합의로 바꾸지 않는다.
- [R001 조사 결론](research/R001-photo-organization-approaches.md)에 현재 조건의 비교·반대 근거·검증 공백을 반영했다. 출처: 에이전트 제안, 미승인. PC의 로컬 참조 카탈로그를 우선 검토하고, 실제 파일 변경을 뒤로 미루는 작은 범위를 대안으로 유지한다. 저장 구조 제안은 SSD 분리 중 정보 검색을 돕지만 카탈로그·캐시 관리와 재연결 부담이 생긴다. 축소안은 원본 변경 위험을 줄이지만 실제 폴더 정리는 남는다. 비교 상세는 R001에만 둔다.

## 구현 위임

사용자는 내부 구조의 근거 기반 제안을 맡겼다. 조사·제안의 위임이며 기술 스택·DB·저장 구조·파일 변경 정책의 채택 승인은 아니다. 사용자 결과와 무관한 구체적인 기술 선택도 이번에는 확정하지 않는다.

## 제외

- 제품 범위 제외: 계정·클라우드 업로드·공유·얼굴 인식·사진 편집. 유사성에 의한 자동 삭제도 제외한다.
- 이번 실행 제외: 제품 구현, 실제 개인 사진 접근·원본 변경, 외부 계정·유료 호출, 실제 제품 사실로의 합성 자료 일반화.
- digiKam 사용 또는 구조 모방을 필수 전제로 삼는 것.
- 인증정보·사용자 설정 열람, 네트워크·브라우저·subagent 사용, Release 재확인·설치·별도 업데이트.
- 실행상의 제외와 사용자가 명시한 제품 범위 제외를 구별한다. 자료에서 본 계정·CSV 내보내기·즐겨찾기·휴지통 보관 기간 등을 새 기능으로 추가하지 않는다.

## 미확인·충돌

- 다음 대화의 첫 질문: 첫 범위에 적용 전 목록을 검토하는 실제 파일 이동을 포함할까요, 앱 안의 정리·비교·선택까지만 할까요? 저장 책임·실패 복구와 후속 작업을 크게 바꾸므로 먼저 다룬다. 이번에는 Research 결과를 전달하고 이 선택을 요구하지 않는다.
- 폴더 화면·타임라인 등 화면 구성과 원본 저장 구조는 각각 미정이다. SSD 분리 시 필수는 이전 정보 검색이며, 미리보기의 크기·보관량·기간과 원본 해상도 비교 여부는 미정이다.
- 날짜 누락·오류·시간대 미상의 표시·정렬·보정 저장 방식, 실제 이동·복사·이름 변경·삭제의 포함 여부와 실패·복구 기대가 남아 있다. 동일 파일과 시각 유사 후보를 구별하고 사용자가 삭제 전 직접 선택한다는 원칙은 확인됐다.
- 사진 형식·규모·디스크 구성은 확인됐다. Windows 세부 버전·HEIC 실행 지원, 외부 이동의 재연결, 성능 허용치·공간·비용, 부분 성공·빈 결과·실패·취소의 표시와 성공 판정은 미확인이다. 성능 수치나 저장 예산을 임의로 만들지 않는다.
- 자료의 가상 사례 비교는 가능하나 실제 제품·공개 구현을 폭넓게 조사하라는 요청은 현재 환경에서 완료할 수 없다. 후속 자료 조사 또는 범위 조정은 미합의다.
