# Research R001: 사진 정리 접근법과 적용 조건

- 상태: 작성 중
- 기준: [idea.md](../idea.md)의 시작 요청·사용자 결정·미확인 항목. Topology는 확인 대기 중이다.
- 확인 날짜: 2026-09-07
- 영향: Phase 후보
- 판정: 결론 보류. 제공된 합성 문서 안의 접근법 비교는 가능하나 실제 제품·공개 구현의 폭넓은 탐색과 우리 환경의 검증은 완료하지 못했다.

## 질문·목적·범위

목적은 탐색·벤치마킹이다. 먼저 다른 접근을 발견하고, 발견한 후보의 선택을 바꾸는 주장과 실패 조건을 문서로 검토한다. 사용자 선택이나 실제 안전성·성능을 확정하는 조사가 아니다.

| 중립 brief | 내용 |
|---|---|
| 중립 질문 | 흩어진 사진을 함께 보고 날짜·유사성을 이용해 정리하려면 원본 위치와 정리 정보를 어떻게 다루는 접근들이 있으며, 각각 어떤 부담과 실패 조건이 있는가? |
| 입력 | 사용자가 고른 여러 로컬 폴더의 사진. 형식·규모·볼륨 구성은 미확인 |
| 출력 | 접근법·구현 전략·안전 경계 비교와 사용자 선택에 필요한 조건. 제품의 최종 출력과 실제 파일 변경은 미정 |
| 사용자 경험 | 혼자 Windows PC에서 사진을 모아 보고 정리. 폴더 직접 관리와 보관함 사용 사이에서 미정 |
| 성공 조건 | 서로 다른 접근과 더 작은 대안을 근거·적용 조건과 함께 비교하고, 자료 설명과 검증 결과를 구별한다. 제품 성공 기준은 아직 미정 |
| 실패 조건 | 특정 예시에 고정, 원본 손실 위험 누락, 유사성의 동일성 오인, 버전·재게시 혼동, 합성 자료를 실제 제품의 사실로 사용, 계획 중 구현 |
| 확정 제약 | Windows·개인용·로컬이라는 사용자 목적, 파일 안전성 검토, 현재는 계획만. 나머지는 Idea 참조 |
| 객관적인 환경 사실 | 이 실행에서 네트워크·브라우저·subagent는 제공되지 않음. evidence는 읽기 전용 합성 원자료. 화면·영상·실행 데모 없음 |
| 미해결 질문 | 허용할 파일 변경, 로컬 처리·업로드·계정의 정확한 경계, 저장 방식, 날짜·유사성의 사용 목적, 형식·규모·속도·복구 성공 기준 |

digiKam의 분류는 **예시**다. 필수 제약·현재 환경·채택 후보가 아니므로 독립적인 탐색 조건에 넣지 않았다. 이 보고서는 digiKam의 실제 기능·성능·구조를 판정하지 않는다.

Repository 기준선: 이번 질문은 새 도구의 개념 계획이며 관련 제품 구현을 전제하지 않는다. 필요한 `skill/` 단계 지침, `evidence/README.md`와 원자료, 이번에 만든 Idea만 사용했다. 실제 사진·제품 코드·인증정보·사용자 설정은 조사하지 않았다. 기존 구현이 없다고 단정하지도 않는다.

| 증거원 | 상태 | 이유·실제 수행 범위 | 바뀔 수 있는 결정 |
|---|---|---|---|
| Repository | 필요 | 로컬 원자료 본문과 코드 조각을 읽음. 전체 공개 저장소·실행 테스트는 없음 | 구현 전략과 재사용 가능성 |
| Independent exploration | 생략 | 이번 실행에는 subagent 미제공. 메인이 사례 발견→개발 기록 검토→반대 근거 점검을 수행했으며 독립 조사로 계산하지 않음 | 후보 편향·누락 가능성 |
| External evidence | 필요 | 실제 외부 탐색 경로 미제공. 대신 제공된 합성 문서 8개의 본문을 읽음. 이를 실제 웹 조사와 같은 증거로 취급하지 않음 | 접근 범주·현행 지원·실제 제품 적합성 |
| Browser Evidence | 생략 | 개인 계정·로그인 화면을 확인할 질문이 현재 없음. 공개 화면 관찰도 자료·도구 부재로 미수행 | 화면 배치·조작 체감은 미확인 |
| Lab | 생략 | 초기 선택지 비교는 문서로 가능. 실제 사진·실행 구현이 없어 정확도·성능·복구 실험은 별도 선행 검증 필요 | 파일 변경 허용 시점·지원 범위 |

실행 조건은 사용자 제공 환경의 Windows/PowerShell와 프로젝트 안 쓰기 경계에 한정해 확인했다. 호스트의 구체적인 버전은 확인하지 않았다. 파일 읽기와 계획 문서 작성만 수행했고 외부 연결·실험·권한 확대는 시도하지 않았다.

비교 후 제안: 파일 오조작 우려와 아직 열린 저장 방식 때문에, **우선 원본 변경 없이 모아 보기·날짜 출처 표시·유사 후보 검토를 하는 작은 범위**가 되돌리기 쉬운 출발점이다. 출처는 에이전트 제안이며 미승인이다. 원요청에 비해 실제 이동·삭제를 뒤로 미루는 단순화로, 안전 경계를 좁히는 대신 탐색기의 폴더 정리는 끝나지 않는다. 이것만으로 폴더 스캔과 참조 카탈로그 중 하나를 확정하지 않는다. 최종 저장 방식의 우열은 사용자가 원하는 실제 정리 결과와 저장 공간 조건을 확인하기 전에는 정할 수 없다.

기존 탐색기 작업 유지·직접 만들지 않고 기존 도구 사용도 비교에서 제외하지 않는다. 별도 도구를 유지보수하지 않는 이점이 있지만 여러 폴더 통합·유사 후보 검토가 충족되는지는 미확인이다. 실제 제품 추천은 외부 근거가 필요하다. 모든 방식을 동시에 지원하는 혼합 구조는 비용이 큰 추가 범위이며 제안·확정하지 않았다.

### 핵심 주장 검토와 반증 조건

복수 후보·파일 위험·버전 차이가 있어 전체 기록 깊이를 적용한다. 아래 표는 Claim map과 Evidence matrix를 합친 것이다. 최신성은 해당 동작의 버전을 기준으로 하며 실제 현행 제품 여부는 미검증이다.

| 주장·결정 영향 | 필요한 출처·반증 조건 | 확인한 근거·반대 근거 | 판정·남은 공백 |
|---|---|---|---|

### 접근 기록·공백에 따른 후속 확인

첫 자료 묶음은 폴더형·보관함형·참조형 설명(S1·S3·S4)과 재게시(S5)였다. 여기서 ‘참조 카탈로그’ 범주, 현행 로컬 지원, 파일 이동 복구, 날짜·유사성 판정이 선택을 바꿀 공백으로 드러났다. 이에 따라 같은 범위의 개발·변경 자료(S2·S6·S7·S8)를 후속 확인했다. 마지막으로 `rg -n`으로 인용 위치·버전·반대 조건을 대조했다. 동일 원문의 재게시를 합쳤으며 제품팀 문서와 같은 제품 개발기의 동의를 독립 실험으로 세지 않았다.

본문 확인과 반대 근거 탐색은 제공된 전체 원자료에서 `sidecar`, `분리`, `이동`, `원자성`, `복구`, `계정`, `온라인`, `동기화`, `hash`, `누락률`, `시간대`, `HEIC`에 해당하는 설명·제약을 대상으로 했다. 화면이 편하다거나 속도가 빠르다는 직접 관찰은 없다. HTTP 요청·공개 브라우저·저장소 실행은 시도하지 않았으므로 HTTP 성공·실패나 실험 결과를 기록하지 않는다.

외부 경로의 중단 사유는 **이번 실행의 네트워크·브라우저 경로 미제공**이다. 개별 `.example` 주소를 실제 접속 실패로 기록하지 않는다. 사용한 대체 경로는 로컬 원자료 본문이며 여기에는 접근이 성공했다. 실제 공식 문서·변경 기록·공개 저장소·라이선스·독립 후기·화면·데모·공개 아카이브는 현재 실행에서 확인하지 못한 경로다. 확인해도 가치가 없다는 뜻이 아니며, 이 경로들의 부재가 탐색 전체의 결론 보류 이유다. 접속 우회나 새 도구·권한 요청은 하지 않는다.

## 결론과 다음 행동

- **판정: 결론 보류.** 합성 자료 내부에서는 폴더형·복사 보관함형·참조형·후보 검토 중심의 작은 대안을 비교할 근거가 있다. 실제 제품 채택, 공개 구현 재사용, Windows 지원·성능·파일 복구 보장에는 근거가 부족하다.
- 근거: S1~S4의 서로 다른 저장 책임, S7의 인접 사례, S8의 날짜 출처 분리. 반대 근거: S2의 불완전한 복구 경계, S6의 버전 변경, S7의 오탐·누락 측정 부재, S8의 날짜·형식 공백.
- 신뢰도: **중간** — 제공 문서 안의 개념 비교와 적용 추론에 한정한다. 실제 제품 추천·우리 환경의 동작 보장은 **낮음**이다. S5는 독립 근거에서 제외하고 S4는 2.8에 한정하며, 어떤 후보도 사용자 채택으로 기록하지 않는다.
- 코드·에셋 재사용: S8의 짧은 반환 구조만 읽었다. 전체 공개 코드·라이선스·의존성·유지 상태·Windows 테스트가 없으므로 복사 사용이나 재사용 가능성을 확정하지 않는다. 기술 설명에서 패턴을 참고하는 것과 코드를 재사용하는 것은 별도 판단이다.
- Idea 영향: 저장 방식에 참조 카탈로그와 더 작은 후보 검토 도구를 비교 대상으로 제시한다. 세부 결론은 이 문서에만 두며, 실제 폴더 정리가 필요한지와 허용 변경은 사용자 결정으로 남긴다.
- Execution 영향: 아직 Execution 단계가 아니므로 파일·Phase·Build ID를 만들지 않는다. 파일 변경이 범위에 포함되면 해당 기능보다 먼저 복사 확인·충돌·중단·재개·외부 변경·재실행의 안전 검증이 필요하다. 형식 지원·날짜 정확도·유사 후보 품질·규모 검증 역시 그 전제를 사용하는 기능보다 먼저 둬야 한다. 이는 미승인 후속 계획이며 실험 완료가 아니다.

### 완료 기준 점검

1. 접근법 비교: 제공 자료 범위에서는 서로 다른 저장 방식과 인접·단순화 대안의 조건을 비교했다. 실제 제품 생태계 전체를 탐색한 것은 아니다.
2. 적합한 직접 근거: 문서 본문·S8의 작은 코드 조각은 확인했다. 실제 제품·전체 공개 코드·화면·실행 근거는 충족하지 못했다.
3. 적용 가능성: 가져올 패턴과 재연결·공간·안전·메타데이터·정확도 부담을 연결했다. 재사용 라이선스·성능·지원은 열린 상태다.
4. 결정 영향: 비교와 미승인 권장 초안을 제시한다. 사용자의 미응답을 저장 방식·기능·탐색 축소의 동의로 바꾸지 않는다.
5. 타당한 종료: **미충족**. 같은 로컬 문서를 반복해 읽을 효용은 낮지만, 실제 제품·공개 구현·화면·실패 근거를 더 확인하면 선택이 바뀔 수 있다. 접근 제한에 따른 보류이며 충분한 탐색 완료가 아니다.

Web closure는 외부 탐색·시각 관찰·주요 근거 공백 때문에 미통과다. Idea closure도 Topology와 제품 선택이 미확정이므로 진행하지 않는다. 현재 사용자가 답할 질문은 Idea에 기록한 큰 구성 확인 하나이며, 그 답 뒤 안전 관련 세부 질문으로 이어간다.
