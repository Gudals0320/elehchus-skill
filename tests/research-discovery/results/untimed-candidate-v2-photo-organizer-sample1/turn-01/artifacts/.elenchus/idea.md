# Idea: Windows 개인용 로컬 사진 정리 도구

- 상태: 작성 중
- 시작 요청: Windows PC에 흩어진 사진을 여러 폴더에서 모아 보고 날짜나 비슷한 사진을 기준으로 정리하는 도구를 혼자 쓰고 싶다. 탐색기처럼 폴더를 직접 다루는 방식과 별도 사진 보관함 방식은 미정이다. digiKam은 예시이며 사용하거나 구조를 따르라는 요구가 아니다. 기존 제품과 공개 구현에서 참고할 방식을 폭넓게 조사하고 파일을 잘못 건드릴 위험도 살핀다. 지금은 구현 전 계획을 세운다.

## Topology

다음은 에이전트의 구성 제안이며 사용자 확인 대기 중이다. 구성을 확인해도 제품의 세부 동작을 승인한 것으로 보지 않는다.

| 구성요소 | 상태 | 초기 의도·근거 | 산출물·사용 표면·연결 |
|---|---|---|---|
| T1 여러 폴더의 사진 모아 보기 | 활성 제안 | 사용자: “여러 폴더를 골라 사진을 모아 보고” | Windows의 폴더 선택과 사진 목록; 로컬 파일을 입력으로 사용 |
| T2 날짜·유사 사진으로 정리 | 활성 제안 | 사용자: “날짜나 비슷한 사진을 기준으로 정리” | 정리 기준과 비교 결과; 실제 파일 변경 여부는 미정 |
| T3 저장 방식과 파일 안전성 | 활성 제안 | 사용자: 폴더 직접 관리와 별도 보관함 사이에서 미정, “파일을 잘못 건드리면 곤란” | 저장 책임·변경 범위·실패와 복구; 참고 사례의 장단점을 선택 근거로 연결 |

현재 산출물은 계획 문서다. 외부 서비스 연동은 요청에 없으며 조사 자료를 이유로 추가하지 않는다. T1~T3는 원요청의 분해이고 기능 추가 제안이 아니다. 장점은 선택과 안전 문제를 빠뜨리지 않는 것이며, 부담은 경계가 겹치면 병합 조정이 필요하다는 점이다.

- 출처: `evidence/README.md`. 실제 화면·영상·실행 가능한 데모는 없다.

## 미확인·충돌

- 현재 질문: T1~T3 구성이 맞는지, 추가·삭제 또는 병합·분리가 필요한지, 구성을 보류할지.
- 구성 확인 뒤 우선 다룰 공백: “정리”가 화면상의 분류인지 실제 파일 이동·복사·이름 변경·삭제까지인지, 허용되는 변경과 복구 기대.
- 저장 방식, 날짜가 없거나 충돌할 때의 기준, 동일 파일과 비슷한 사진의 구분 및 결과 활용.
- 사진 형식·규모·디스크 환경, 외부 이동 감지, 성능·비용, 부분 성공·실패·취소, 성공 판정 행동은 아직 미확인이다. 관련된 시점에 한 질문씩 다룬다.
- 자료의 가상 사례 비교는 가능하나 실제 제품·공개 구현을 폭넓게 조사하라는 요청은 현재 환경에서 완료할 수 없다. 후속 자료 조사 또는 범위 조정은 미합의다.
