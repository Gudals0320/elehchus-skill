# Research R001: 사진 정리 접근법과 적용 조건

- 상태: 작성 중
- 기준: [idea.md](../idea.md)의 사용자 결정·제외·미확인 항목. 현재 사용자 응답으로 원래 범위의 Topology는 확인됐고, 세부 저장·화면·파일 작업 선택은 미정이다.
- 확인 날짜: 2026-09-07
- 영향: Phase 후보
- 판정: 결론 보류. 제공된 합성 사례의 조건부 비교·제안은 가능하다. 실제 제품·공개 구현의 폭넓은 탐색과 HEIC·5만 장·파일 안전성 검증은 미완료다. 아래 결론은 사용자 채택 합의나 Research closure가 아니다.

## 질문·목적·범위

목적은 탐색·벤치마킹과 핵심 주장의 문서 검증이다. 현재 확정된 입력·제외·안전 조건에 따라 기존 비교를 재평가한다. 이번에는 Research 결론까지만 전달하고 전체 실행 계획 합의는 다음 대화로 남긴다. 이전의 읽기 중심 축소안은 승인되지 않았으며, 내부 구조의 조사·제안 위임을 제품 선택의 승인으로 확대하지 않는다.

| 중립 brief | 내용 |
|---|---|
| 중립 질문 | 여러 드라이브의 사진을 원본 적용 전 보존하고 SSD 분리 중에도 정보를 찾으며 날짜·유사 후보를 검토하려면 어떤 접근과 제작 전략이 적합한가? |
| 입력 | 사용자가 고른 로컬 폴더의 JPEG·PNG·HEIC 약 5만 장. 두 드라이브와 외장 SSD, 촬영일 누락·오류 있음. 개인 사진에는 접근하지 않음 |
| 출력 | 현재 조건의 접근법·구현 전략·안전 경계 비교, 조건부 권장안, 반대 근거와 미검증 범위. 실행 계획·제품·기능·비용의 확정은 아님 |
| 사용자 경험 | Windows에서 혼자, 인터넷 없이 기존 사진 탐색. SSD 분리 중 이전 사진 정보 검색. 날짜로 훑기·큰 비교, 중복 삭제 전 나란히 보고 직접 선택. 화면 선호와 실제 이동 기능은 미정 |
| 성공 조건 | 원본·메타데이터는 명시적 적용 전 보존; SSD 없이 저장된 정보 검색; 이동을 채택한다면 적용 전 목록과 실패 후 원본·처리 상태 확인; 자동 삭제 없이 직접 후보 선택. 속도·공간·지원 실패·복구의 세부 판정은 미정 |
| 실패 조건 | 요구한 오프라인 검색이 연결에 의존함, 검토 전 원본 변경, 유사성을 동일성으로 오인해 삭제, 형식·규모·복구를 근거 없이 보장, 버전·재게시 혼동, 합성을 실제 제품 사실로 사용, 계획 중 구현 |
| 확정 제약 | Idea의 사용자 결정·제외 참조. 계정·클라우드 업로드·공유·얼굴 인식·사진 편집 제외; 외부 계정·유료 호출·개인 사진 접근 불허; 새 기능·비용 미확정 |
| 객관적인 환경 사실 | 이 실행에서 네트워크·브라우저·subagent는 제공되지 않음. evidence는 읽기 전용 합성 원자료. 화면·영상·실행 데모 없음 |
| 미해결 질문 | 첫 범위의 실제 파일 작업, 화면·저장 구조, SSD 분리 시 미리보기·확대 범위, 날짜 대체·보정 정책, HEIC 실행 지원, 5만 장 성능·공간·실패 복구의 세부 기준 |

digiKam의 분류는 **예시**다. 필수 제약·현재 환경·채택 후보가 아니므로 탐색 조건에 넣지 않았다. 특정 제품·엔진·DB는 필수가 아니다. 자료에 등장하는 SQLite는 사례의 구성 요소이며 우리 도구의 선택이 아니다. 이 보고서는 digiKam의 실제 기능·성능·구조를 판정하지 않는다.

비교 후 제안: **원본 위치는 유지하고, SSD가 빠져도 사용할 정보를 PC의 로컬 참조 카탈로그에 보관하는 방식을 우선 검토한다.** 출처: 에이전트 제안, 미승인. 사용자 응답으로 새로 확인된 SSD 분리 요구 때문에 이전의 동등 비교에서 우선순위가 바뀌었다. 정보 보관은 필요하지만 미리보기의 크기·보관량이나 특정 DB까지 필수가 되는 것은 아니다. 현재 자료 안의 적합성 추론이며 실제 구현 검증은 아니다.

별도로 **실제 이동·삭제를 연기하고 정보 탐색과 수동 비교·선택까지만 만드는 작은 범위**를 대안으로 유지한다. 출처: 에이전트 제안, 미승인. 이는 원요청 대비 단순화다. 파일 변경 위험과 제작 부담을 줄이지만 탐색기의 실제 폴더 정리는 끝나지 않는다. 사용자의 원래 범위 동의를 이 축소안의 승인으로 바꾸지 않는다. 전체 복사·CSV 내보내기·즐겨찾기·동기 확대·휴지통 기간·새 비용은 추가 확정하지 않았다.

폴더 화면·타임라인은 사진을 찾아보는 방식이고, 참조·복사 보관함은 원본을 어디에 두고 관리할지의 선택이다. 두 축을 구별하는 것은 에이전트의 설계 해석이다. 참조 카탈로그 제안으로 타임라인이나 폴더 화면의 선호가 결정되지는 않는다. S3·S4는 날짜 타임라인을 설명하고 S7은 나란히 확대 비교를 설명하지만, 실제 화면·영상·데모가 없어 배치·가독성·조작 속도는 **미확인**이다. 날짜 탐색과 큰 비교가 중요하다는 사용자 의도만 확정한다.

기존 탐색기 작업 유지·직접 만들지 않고 기존 도구 사용도 비교에서 제외하지 않는다. 별도 도구를 유지보수하지 않는 이점이 있지만 여러 폴더 통합·유사 후보 검토가 충족되는지는 미확인이다. 실제 제품 추천은 외부 근거가 필요하다. 모든 방식을 동시에 지원하는 혼합 구조는 비용이 큰 추가 범위이며 제안·확정하지 않았다.

### 제작에 가져올 패턴과 경계

아래는 자료의 패턴을 현재 요구에 적용한 **에이전트 제안**이다. 제품 코드·모듈·DB를 구현하거나 선택한 결과가 아니다. 내부 책임을 나눠 안전 경계를 검토하는 수준이며 기능·저장 비용 증가는 미승인이다.

| 책임·근거 | 현재 조건의 제작 제안 | 얻는 것·부담·남은 선택 |
|---|---|---|
| 입력 읽기와 지속 정보 보관 / S4 6·8행 | 원본 읽기와 PC의 정보 저장을 분리. 볼륨 식별자·상대 경로·날짜 출처·마지막 확인 시각을 저장하는 패턴을 검토 | SSD 분리 시 검색 가능. 연결 안 됨·오래된 정보임을 구별하고 원본 작업을 막는 방식 참고. 외부 이동·드라이브 문자 변경 시 재연결 검증 필요. 보관할 정보·미리보기 정책과 DB는 미정 |

| 파일 작업 계획과 적용 / S2 6·8·10행 | 이동을 선택한 경우에만 목록 생성·검토와 실행을 분리. 원본/대상 경로·충돌·공간 확인, 적용 시 원본 변경 여부 재확인, 항목별 작업 기록. 드라이브 간에는 복사→확인→원본 제거 패턴 검토 | 실패 후 각 원본·대상 상태와 완료 단계를 설명할 근거를 남김. 외부 변경 항목 보류와 재실행 중복 삭제 방지가 필요. 확인 방식·취소·재개·부분 복구 정책은 미정. journal이나 rename으로 일괄 원자성·완전 복구를 보장하지 않음 |

원본 제거를 이미 승인받은 작업으로 취급하지 않는다. 사용자가 이동 기능을 선택하고 실제 목록을 명시적으로 적용할 때의 미래 동작을 검토한 것이다. 디코더는 OS 기능 사용과 앱 동봉의 대안을 C7처럼 비교하며, 라이선스·설치 부담·오프라인 동작이 확인되기 전 비용 없는 선택으로 단정하지 않는다. 로컬 카탈로그 패턴을 택하더라도 특정 엔진·DB가 필수라는 근거는 없다.

자료 설명으로 안전 계획에 가져올 후보는 작업 전 원본/대상 경로 확인, 충돌·여유 공간 확인, 외부 변경 시 보류, 항목별 진행 기록, 복사 확인 뒤의 원본 제거 경계다(S1·S2). 앱이 앞으로 이를 정확히 수행하거나 어떤 실패든 되돌릴 수 있다고 주장하지 않는다. 카탈로그·sidecar·사진 복사본의 저장 위치도 각각 사용자 데이터 처리 선택이다(S1·S3·S4·S8).

### 접근 기록·공백에 따른 후속 확인

이전 비교는 폴더형·보관함형·참조형 설명(S1·S3·S4)과 재게시(S5)에서 출발해 개발·변경 자료(S2·S6·S7·S8)로 공백을 보완했다. 이번에는 최신 사용자 조건을 intake로 먼저 대조하고, 그 결과 선택을 바꾸는 SSD 분리·원본 기록·온라인 의존·HEIC·규모·날짜 오류를 중심으로 8개 원문의 본문을 직접 재확인했다. `rg -n`으로 인용 위치·버전·반대 조건을 대조했다. 동일 원문의 재게시를 합쳤으며 제품팀 문서와 같은 제품 개발기의 동의를 독립 실험으로 세지 않았다.

본문 확인과 반대 근거 탐색은 제공된 전체 원자료에서 `sidecar`, `분리`, `이동`, `원자성`, `복구`, `계정`, `온라인`, `동기화`, `hash`, `누락률`, `시간대`, `HEIC`에 해당하는 설명·제약을 대상으로 했다. 화면이 편하다거나 속도가 빠르다는 직접 관찰은 없다. HTTP 요청·공개 브라우저·저장소 실행은 시도하지 않았으므로 HTTP 성공·실패나 실험 결과를 기록하지 않는다.

외부 경로의 중단 사유는 **이번 실행의 네트워크·브라우저 경로 미제공**이다. 개별 `.example` 주소를 실제 접속 실패로 기록하지 않는다. 사용한 대체 경로는 로컬 원자료 본문이며 여기에는 접근이 성공했다. 실제 공식 문서·변경 기록·공개 저장소·라이선스·독립 후기·화면·데모·공개 아카이브는 현재 실행에서 확인하지 못한 경로다. 확인해도 가치가 없다는 뜻이 아니며, 이 경로들의 부재가 탐색 전체의 결론 보류 이유다. 접속 우회나 새 도구·권한 요청은 하지 않는다.

## 결론과 다음 행동

- **판정: 결론 보류.** 합성 자료 내부의 접근 비교와 현재 조건에 따른 제안은 가능하다. 그러나 요청된 실제 제품·공개 구현의 폭넓은 탐색은 미완료이며, 실제 제품 채택·코드 재사용·Windows의 HEIC 지원·5만 장 성능·파일 안전성은 결론을 보류한다. 사용자가 이번에 Research 결론을 요청한 사실을 조사 축소·생략 합의나 완료 승인으로 바꾸지 않는다.
- 근거: S1~S4의 서로 다른 저장 책임, S7의 인접 사례, S8의 날짜 출처 분리. 반대 근거: S2의 불완전한 복구 경계, S6의 버전 변경, S7의 오탐·누락 측정 부재, S8의 날짜·형식 공백.
- 신뢰도: **중간** — 합성 문서 안의 비교와 현재 조건의 적용 추론에 한정한다. **낮음** — 실제 제품 추천·재사용·우리 환경의 동작 보장. 원문 확인은 직접 수행했지만 제품·화면·실행은 직접 관찰하지 않았다. S5는 독립 근거에서 제외하고 S4는 2.8에 한정하며, 어떤 후보도 사용자 채택으로 기록하지 않는다.
- 코드·에셋 재사용: S8의 짧은 반환 구조만 읽었다. 전체 공개 코드·라이선스·의존성·유지 상태·Windows 테스트가 없으므로 복사 사용이나 재사용 가능성을 확정하지 않는다. 기술 설명에서 패턴을 참고하는 것과 코드를 재사용하는 것은 별도 판단이다.
- 선택별 결론: **참조 카탈로그 방식은 우선 제안**, 복사 보관함은 전체 복사본이 필요한 경우의 대안, 수정 없는 폴더 스캔만으로 분리된 SSD 정보를 찾는 구성은 부적합, 비교 중심의 작은 범위·기존 도구 사용은 대안으로 유지한다. Indexlens 3.0은 확정 제외와 충돌하고 2.x는 패치 중단이므로 제품 채택을 권장하지 않는다. 날짜 출처 분리·수동 후보 검토·작업 기록은 참고 패턴이며 새 기능·엔진·DB·비용을 확정하지 않는다.
- Idea 영향: 원래 범위의 구성 동의, 오프라인·SSD 분리·형식·규모·안전·직접 선택·제외를 반영했다. 저장·화면·실제 파일 작업·보관 비용은 미정이고 참조 카탈로그와 축소안은 에이전트 제안으로 구별한다. 새로운 제안에 대한 사용자 확인은 다음 계획 대화에서 다룬다.
- Execution 영향: 아직 Execution 단계가 아니므로 파일·Phase·Build ID를 만들지 않는다. 파일 변경이 범위에 포함되면 해당 기능보다 먼저 복사 확인·충돌·중단·재개·외부 변경·재실행의 안전 검증이 필요하다. 형식 지원·날짜 정확도·유사 후보 품질·규모 검증 역시 그 전제를 사용하는 기능보다 먼저 둬야 한다. 이는 미승인 후속 계획이며 실험 완료가 아니다.

### 완료 기준 점검

1. 접근법 비교: 제공 자료의 저장 방식·인접 사례·단순화·기존 유지 대안을 현재 조건으로 재평가했다. 실제 제품 생태계 전체를 탐색한 것은 아니다.
2. 적합한 직접 근거: 문서 본문·S8의 작은 코드 조각은 확인했다. 실제 제품·전체 공개 코드·화면·실행 근거는 충족하지 못했다.
3. 적용 가능성: 가져올 패턴과 재연결·공간·안전·메타데이터·정확도 부담을 연결했다. 재사용 라이선스·성능·지원은 열린 상태다.
4. 결정 영향: 참조 방식 우선 제안과 폴더형의 분리 검색 한계, 복사 보관함의 공간 부담, 버전별 제외 근거를 제시했다. 사용자의 미응답을 저장 방식·기능·탐색 축소의 동의로 바꾸지 않는다.
5. 타당한 종료: **미충족**. 같은 로컬 문서를 반복해 읽을 효용은 낮지만, 실제 제품·공개 구현·화면·실패 근거를 더 확인하면 선택이 바뀔 수 있다. 접근 제한에 따른 보류이며 충분한 탐색 완료가 아니다.

Web closure와 Research closure는 실제 외부 탐색·시각 관찰·주요 검증 공백 때문에 미통과다. Topology 확인은 완료됐지만 Idea closure는 세부 제품 선택·성공 기준이 남아 진행하지 않는다. index와 이 문서의 상태는 `작성 중`, 영향은 `Phase 후보`로 일치한다. 이 턴은 Research 결론 전달까지다. 전체 실행 계획 합의는 사용자가 요청한 다음 대화로 남기며, 외부 탐색의 충분성이나 미실행 검증을 완료로 기록하지 않는다. 다음 질문은 Idea의 실제 파일 이동 포함 여부 하나로 연결한다.
