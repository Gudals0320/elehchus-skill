# Idea: 룰렛·바카라·블랙잭 싱글 카지노

- 상태: 작성 중
- 시작 요청: 룰렛·바카라·블랙잭을 할 수 있는 카지노 게임을 만든다. 게임 시작 시 초기자금을 정하고, 파산하면 게임오버이며 그렇지 않으면 계속 진행한다. 터미널 기반 카지노 로직을 먼저 구현한 뒤 애니메이션이 구현된 웹앱 게임으로 발전시킨다. 카드게임은 6덱으로 생각하며 향후 멀티 확장을 고려하되 현재는 싱글이 먼저다. 현재 저장 기능은 필요 없다. 핵심 고민은 3D 애니메이션이며 디자인 고찰과 레퍼런스 탐색이 많이 필요하다.

## Topology

사용자가 세 게임·세션 자금·터미널·웹 표현에 동의했다. 아래는 그 답을 반영한 구성이다. 디자인·레퍼런스 조사는 웹 표현과 제작 방법을 위한 조사이며 별도 제품 기능이 아니다.

|---|---|---|
| 세 게임 | 활성 | 룰렛·바카라·블랙잭. 카드게임은 각각 독립된 6덱. 출처: 사용자 요청 |
| 세션 자금·진행 | 활성 | 사용자가 입력한 초기자금을 세 게임이 공유. 파산 시 게임오버, 그전까지 계속 플레이. 출처: 사용자 요청 |
| 터미널 게임 | 활성 | 혼자 Windows PC에서 사용할 싱글 카지노 로직을 먼저 구현. 출처: 사용자 요청 |

사용 표면은 터미널과 이후 웹앱이다. 외부 연동 요구는 없다. 조사와 그 범위의 역할 분담은 허용됐지만, 이번 환경에서는 subagent가 미제공이므로 메인 세션이 조사한다. 제품 구현·새 외부 계정·유료 서비스 사용은 요청되지 않았다.

## 확인된 사실

- 2026-09-07 `app.txt`를 읽어 `UNIMPLEMENTED PRODUCT STUB`를 재확인했다. 이 파일에서 재사용할 게임 코드·렌더러·테스트는 확인되지 않았다. 관련 없는 설정은 조사하지 않았다.
- 프로젝트 지침에 따라 이번 실행에서는 네트워크·브라우저·subagent를 사용하지 않는다. `evidence/`는 가상 제품에 관한 합성 원자료다. 원문 8개와 README를 읽었으며 실제 제품의 사실이나 실측 결과로 취급하지 않는다.
- 원자료에는 스크린샷·영상·실행 데모가 없다. 화면 관찰·성능 측정·실제 사용성 검증은 수행하지 않았다. `.example` 주소는 원천 식별자이며 접속 대상이 아니다.
- 최초 Release 확인과 현재 버전 사용 선택은 이미 완료되었다는 사용자 지침에 따라 반복하지 않는다.

## 사용자 결정

- 출처: 사용자 요청. 세 게임과 세션 자금·터미널·웹 표현의 범위에 동의했으며 그 밖의 기능은 제외한다.
- 출처: 사용자 요청. 룰렛은 싱글 제로. 바카라는 플레이어/뱅커/타이, 뱅커 5% 커미션. 블랙잭은 더블·스플릿 포함. 바카라와 블랙잭은 각각 독립된 6덱. 세칙·베팅 단위는 구현 전 별도 합의한다.
- 출처: 사용자 요청. 혼자 Windows PC에서 사용하며 웹은 데스크톱 Chrome을 우선한다. 싱글을 먼저 만들고 멀티는 미래 맥락으로만 둔다.
- 출처: 사용자 요청. 실제 현금·결제는 없다. 시작 시 사용자가 초기자금을 입력하고 세 게임에서 공유하며 파산하면 게임오버다. 세션 종료 후 자금을 보관하지 않는다.
- 출처: 사용자 요청. 터미널 기반 구현 → 애니메이션이 구현된 웹앱 게임 순서다. 현재는 디자인·상호작용 사례와 제작 방법의 조사에 집중하며 기술 구조는 조사 근거를 보고 제안한다.
- 출처: 사용자 요청. 카지노 이동·캐릭터 조작은 필요 없으며 플레이어·딜러 캐릭터는 없어도 된다. 테이블 주변 공간과 카드·숫자의 가독성을 원하고, 실사보다 애니메이션에 가까운 3D 느낌을 선호한다.

- 출처: 사용자 요청. 이번 대화에서는 Research 결론까지 확인하고 전체 Build 계획은 다음 대화로 미룬다. 조사 진행을 다시 승인받지 않는다.

## 에이전트 제안

- 기존 구성 제안은 사용자 답에 따라 위 Topology로 대체됐다. 기능 추가는 없다.
- 조사 결과의 화면·구조 후보는 사용자 선택 전까지 미승인이다. 상세 근거와 제안은 [Research Index](research/index.md)에 연결한다. 취향·애니메이션 시간·건너뛰기·확대·입력 방식 등을 합의 없이 확정하지 않는다.

## 사용자 흐름과 성공·실패 관찰

- 시작·정상 흐름: 초기자금 입력 → 세 게임을 공유 자금으로 플레이 → 파산 시 게임오버 또는 사용자가 세션 종료. 세션 후 자금은 보관하지 않는다. 게임 선택·전환 화면과 진행 중 종료 방식은 미정이다.
- 성공 기준 중 합의된 의미: 세 게임을 싱글로 진행하고 자금 변화를 확인할 수 있어야 하며, 웹은 테이블 주변 공간을 보여 주면서 카드와 숫자를 알아볼 수 있어야 한다. 구체적인 관찰 과제·화면 크기·성능 허용값은 구현 전 합의 대상이다.
- 부분 성공·빈 결과·실패·복구: 빈 값/잘못된 금액/잔액 부족 입력, 최소 베팅 미만 잔액과 파산의 관계, 진행 중 종료, 탭 복귀, 3D 로드 실패의 사용자 동작은 미정이다. 조사에서 발견한 실패 위험은 합의된 처리 방식과 구분한다.
- 오류 비용·책임: 사용자는 혼자 플레이하고 결과를 확인한다. 실제 금전 손실은 없지만 잘못된 카드·룰렛 결과·중복 정산은 게임 신뢰를 깨뜨린다. 오류 표시와 복구 정책은 아직 선택하지 않았다.
- 권한·데이터·비용: 세션 자금을 보관하지 않고 저장·계정·공유·통계는 제외한다. 현재 조사는 제공된 합성 파일만 사용한다. 향후 자산·제작 도구의 비용·라이선스는 자료가 없어 미확인이다.
- 교환 관계: 공간감과 읽기 쉬움, 연출 길이와 반복 플레이 속도, 진짜 3D와 제작 부담은 Research 비교 대상이다. 사용자가 감수할 정도는 확정하지 않았다.

## 미확인·충돌

- 이번 Research의 결론 확인과 제안 승인 여부. 문서 비교로 가능한 판정과 실제 시각·조작 검증이 필요한 판정을 나눈다.
- 시각 선택: 카메라 각도·고정/제한 조작·구도, 색·재질·조명, 카드 크기와 테이블 주변 여백, HTML과 3D의 역할, 베팅 입력, 연출 길이·건너뛰기 유무. 원자료로 취향을 대신 결정하지 않는다.
- 제작 선택: 렌더러·엔진·라이브러리·언어, 자산 출처와 이용 조건, Windows PC 하드웨어·Chrome 버전·실제 성능. 특정 기술이나 수치를 확정할 근거는 없다.
- 게임 세칙: 셔플/컷카드, 블랙잭의 딜러 소프트 17·배당·스플릿 재분할/에이스/스플릿 후 더블 등, 바카라 타이 배당·커미션 반올림, 베팅 단위·한도·최소 잔액, 라운드 전환·입력 오류·종료 처리. 사용자 요청대로 구현 전 합의로 연기한다.
- 전체 Idea·Execution closure는 미실시다. 다음 대화에서 남은 제품 선택과 전체 Phase·Build를 다룬다. 미래 멀티를 이유로 현재 서버·계정·동기화 기능을 추가하지 않는다.
