# Research R001: 테이블 화면과 상호작용 비교

- 상태: 작성 중
- 기준: [idea.md](../idea.md)
- 확인 날짜: 2026-09-07
- 영향: Phase 후보
- 조사 목적: 탐색·벤치마킹. 문서상 화면·동작 비교를 수행하고 시각적 선택의 근거 공백을 구분한다.
- 판정: **결론 보류** — 제공 문서의 접근법 비교는 가능하지만 실제 화면·움직임을 보고 선택하려는 요청까지 완료하지 못했다. 사용자에게 비교 결과와 이 한계를 제시하고 처리 확인을 기다린다.

## Repository 기준선

`AGENTS.md`, 현재 `idea.md`, `evidence/README.md`를 직접 읽었다. 관련 제품 소스·manifest 탐색에서는 JS/TS/JSX/TSX/HTML/C#/Python 및 `package.json`·`pyproject.toml`이 발견되지 않았다(스킬·원자료 제외). 기존 제품 기반이나 선택된 엔진은 확인하지 못했으며 모든 언어를 포괄한 부재 증명은 아니다. 사용자 설정·인증정보는 열람하지 않았다.

환경은 Windows PowerShell, 사용자 대상은 혼자 쓰는 Windows PC·데스크톱 Chrome이다. GPU·창 크기·Chrome 버전·성능은 미확인이다. `AGENTS.md`에 따라 이번 네트워크·브라우저 연결·subagent는 사용하지 않는다. 이 제한은 문서상의 제공 조건이며 도구 실패나 기술적 격리 실험을 했다는 뜻이 아니다. 제품·원자료를 수정하지 않고 조사 문서만 기록한다.

카드게임별 독립 6덱, 싱글 제로 룰렛, 바카라 플레이어/뱅커/타이·뱅커 5%, 블랙잭 더블·스플릿은 사용자 결정으로 유지한다. 이는 카드 수를 모두 화면에 표시하라는 요구가 아니다. 세칙·베팅 단위는 구현 전 별도 합의하며 이번 조사에서 결정하지 않는다.

## 사용자 기술 언급 분류

Windows PC는 현재 사용 환경, 데스크톱 Chrome은 지원 우선 조건, 터미널 → 웹은 산출물 순서다. 애니메이션에 가까운 3D는 사용자 표현 목표다. 필수 엔진·라이브러리 언급은 없다. 자료에서 발견한 HTML/CSS·모델 기반 3D는 비교 후보이며 neutral brief의 필수 구현 방식으로 넣지 않았다.

## 탐색 과정과 범주

먼저 기존 엔진을 전제하지 않고 직접 카드·휠 사례와 인접 테이블 입력 사례를 읽었다(E1/E4/E5/E6). 여기서 고정 3D+HTML, 이미지/CSS, 공간 이동형 3D, 주변 공간을 포함한 보드게임 구도를 구분했다. 이어 E1의 개발 기록 E2와 소개 재게시 E3을 확인해 동작 근거와 출처 중복을 점검했다. 특정 도구·소재 구매를 탐색 범위로 늘리지 않았다.

E3의 9초·구도·버튼 설명은 E1 재게시이며 독립 실행 후기·사용성 조사로 세지 않는다. E1/E2/E3은 같은 Tablehaven 제작 원천 계열이다. E4/E5/E6은 자료 묶음 안에서 다른 작성자 계열이지만 모두 가상 제품이고 실제 세계의 교차 검증이 아니다. 공개 장면 관찰은 0건이다.

## 사례 비교

아래 화면·동작은 모두 **자료의 설명**이다. 실제 본 화면·영상이 없으며 원문 링크는 문서를 열기 위한 것이다.

| 접근법·대표 사례 | 문서상 장면·동작과 원문 위치 | 우리 조건에 가져올 요소·수정 | 제약·비용·현재 판단 |
|---|---|---|---|
| 고정 테이블 3D + HTML / Tablehaven 0.8 | [E1](../../evidence/01-tablehaven-product.md) 6~10행: 고정 사선, 인물 없음, 목재 테이블·카드·칩은 3D, 점수·잔액·버튼은 HTML, 휠 베팅은 오른쪽 2D 패널. 공개 생략과 다음 입력까지 결과 유지 | 이동 없는 테이블과 읽기·조작 영역의 분리를 비교 후보로 가져올 수 있음. 주변 여백, 블랙잭 분할 패, 룰렛 베팅 밀도에 맞게 구도·패널을 다시 조정해야 함 | 두 레이아웃과 장면의 동기화 부담. 실제 가독성·스타일·분할 패 대응은 미확인. 0.8은 키보드만으로 전 과정 플레이 미지원. **우선 비교 후보 제안, 미승인** |
| 이미지 + CSS 원근 / Flatfelt 2.1 | [E4](../../evidence/04-flatfelt-manual.md) 6~10행: HTML 카드 이미지·약한 perspective, 휠 이미지와 별도 공 레이어, 카드와 버튼이 같은 흐름. 종료 뒤 한 줄 결과·다음 베팅 허용 | 입력과 정보 배치의 비교 기준. 화면 표현을 작게 만들 후보지만 원하는 3D 느낌을 충족할지는 별도 판단 | 전체 조명·카메라·3D 모델·입체 재질 없음. 제작 부담 감소는 작성자 설명이며 동일 조건 측정 없음. **축소 대안 유지; 사용자 동의 없이 3D 목표를 대체하지 않음** |
| 주변 공간을 포함한 보드게임 테이블 / Pileplay | [E6](../../evidence/06-pileplay-devlog.md) 6~10행: 테이블·선반 일부, 하단 행동 띠. 실제 크기 토큰이 안 읽혀 색·높이 과장. 바뀐 토큰만 이동. 확대 중 입력 차단·닫기 | 주변 여백과 정보 띠, 소품의 식별성 조정, 불필요한 반복 동작 축소를 검토할 수 있음. 많은 카드·숫자·베팅 위치에는 별도 검증 필요 | 단일 행동 정산 흐름이며 동시 다중 베팅 경험 없음. 생생함은 제작자 평가, 사용성 실험 없음. **인접 참고; 선반·확대 기능을 새 요구로 추가하지 않음** |
| 공간 이동·다인물 3D / Orbitroom | [E5](../../evidence/05-orbitroom-notes.md) 6~10행: 홀 이동 후 착석 카메라, 멀티·딜러. 인물이 칩을 가려 외곽선·상단 패널 추가 | 가림 문제와 테이블 밖 공간 제작 부담을 반대 사례로 사용 | 복도·캐릭터·이동 경계·좌석의 별도 작업, 혼자 쓰는 로컬 모드 없음. **현재 범위에서 제외: 이동·멀티가 원요청에 불필요**. 개월 수를 우리 비용으로 환산하지 않음 |

장면 내부에 모든 숫자·버튼을 두는 3D 입력 방식은 열린 선택이지만 이 묶음에는 직접 비교할 사례가 없다. 전체 3D UI가 열등하다고 결론 내리지 않는다. 더 가파른/낮은 카메라, 직교/원근, 셀 셰이딩, 색·재질의 구체적 비교 이미지도 없어 권장안을 만들지 않았다. 새 기능 없는 유지·일부 미정·축소를 모두 가능한 처리로 둔다.

Claim·출처·확인일·버전·반대 근거·중복·접근 한계는 기록했다. 개인화 Browser Evidence는 필요 없어 생략했다. 공개 시각 자료의 부재와 관련 후속 관찰의 높은 효용 때문에 전체 Web closure 및 Discovery closure는 통과하지 못한다. 파일 상태는 작성 중으로 유지한다. Lab은 미실행이며 성능·사용성 성공을 보고하지 않는다.

## Verdict와 사용자에게 돌아갈 선택

- 판정: **결론 보류**. 문서 비교 결과는 제시 가능하나 시각·상호작용 레퍼런스 탐색 전체를 완료했다고 할 수 없다.
- 근거: E1/E4는 직접 유사한 서로 다른 표현 방식, E6은 공간·소품 식별의 인접 사례, E5는 현재 제외 범위의 작업·가림 문제를 설명한다.
- 반대 근거: HTML를 쓴 E1도 키보드 전 과정 지원이 없고, E6의 생생함은 사용자 실험이 아니며, E4의 작업 절감은 동일 조건 측정이 없다. 라운드 9초와 카드당 180ms로 속도 순위를 만들 수 없다.
- 에이전트 제안 / 미승인: **3D 테이블·소품 + HTML 정보·버튼을 우선 비교할 후보로 둔다.** 사용자의 입체감·가독성 목표를 분리해서 조정할 수 있다는 설계 추론이다. 두 영역의 크기·위치·동기화 부담을 함께 가진다. 실제 제품 추천이나 효과 검증이 아니다.
- 축소 대안: 이미지/CSS 방식을 비교 기준으로 유지한다. 제작 부담을 줄일 가능성이 있으나 원하는 입체감을 포기해야 할 수 있어 사용자 확인 없이 대체하지 않는다.
- 제외: 공간 이동·캐릭터·현재 멀티는 사용자 범위로 제외한다. 개별 캐릭터의 장단점을 다시 선택하도록 요구하지 않는다.
- 권장안 없음: 카메라 높이·각도·투영, 구도, 색·재질, 모든 입력의 3D화, 연출 시간. 문서에 없는 취향은 채우지 않는다. 공개 생략·확대 등도 기능 채택이 아니다.
- 신뢰도: 문서 내용·중복·범위 구분은 높음. 우리 조건에 대한 개념적 적용 추론은 중간. 실제 스타일·가독성·반복 플레이 체감은 낮음(관찰 없음).
- Idea 변경: 확정 범위는 유지하고 후보 제안과 시각 미관찰을 연결한다. Idea는 작성 중이다.
- Execution 영향: 웹 표현의 Phase 후보에만 연결한다. 전체 Phase·Build 작성·ID 배정·제품 구현은 하지 않는다.

후속 관찰이 가능해지면 테이블과 주변 공간이 함께 보이는 장면, 여러 패가 펼쳐진 블랙잭, 룰렛 베팅·결과 숫자, 공개에서 다음 입력까지 이어지는 동작을 비교해야 한다. 원자료에 이 장면들이 있다고 주장하지 않는다. 그 전까지 시각 선택을 미정으로 남기는 처리에 사용자 확인을 받으며, 연기가 합의돼도 관찰 수행으로 바꾸지 않는다.
