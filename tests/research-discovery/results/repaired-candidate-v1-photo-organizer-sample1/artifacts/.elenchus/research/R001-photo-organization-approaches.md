## Repository 기준선

직접 읽기 확인: 루트의 `app.txt`는 `UNIMPLEMENTED PRODUCT STUB` 한 줄이다. 연결해야 할 기존 제품 구현이나 테스트는 제시되어 있지 않다. 현재 질문에 필요한 `AGENTS.md`, 이 프로젝트의 `skill/SKILL.md`와 Idea·Research·Discovery·Web Evidence 단계 지침, `evidence/README.md`를 읽었다. 인증정보·사용자 설정은 읽지 않는다.

## 사용자 기술 언급 분류

## 증거 계획

| 증거원 | 상태 | 이유 | 바뀔 수 있는 결정 |
|---|---|---|---|
| Repository | 필요 | 관련 기준선과 제공 자료의 성격을 읽기 전용 확인 | 기존 구조 제약 유무, 근거 적용 범위 |
| Independent exploration | 생략 | 이번 실행은 subagent 미제공이라는 사용자 지침. 메인이 사례·구현·반대 근거를 분리해 검토하며 독립 탐색을 수행했다고 하지 않음 | 후보 편향과 누락 가능성 |
| External evidence | 필요 | 접근 범주와 실패 사례 비교. 이번에는 로컬 합성 문서를 대체 자료로만 읽을 수 있고 실제 공개 탐색은 미수행 | 원본 관리 방식과 적용 조건 |
| Browser Evidence | 생략 | 사용자 로그인·개인화 관찰이 필요한 질문이 아니며 연결도 없음 | 현재 선택에는 계정별 관찰 불필요 |
| Lab | 생략 | 실행 가능한 제품·데모·fixture가 없으며 현재는 접근법 문서 비교. 안전성·성능을 검증한 것으로 결론내리지 않음 | 실제 Windows 동작은 후속 검증 필요 |

공개 화면 관찰은 자료에 이미지·영상·데모가 없어 미수행이다. 레이아웃·속도·사용감은 판정하지 않는다. 호스트에서 사용한 기능은 로컬 PowerShell 읽기와 계획 문서 쓰기뿐이다. 파일 diff를 격리 보장의 증거로 삼지 않는다.

## 조사 목적과 범위

상위 구성 확인은 사용자에게 질문한 상태다. 명시적으로 요청된 사례 비교는 그 답과 무관하게 수행할 수 있지만 제품 선택·세부 인터뷰는 앞당기지 않는다.

먼저 제공 자료의 원본 폴더·보관함·참조 카탈로그 설명에서 접근 범주를 찾는다. 이후 문서가 드러내는 버전·출처 관계와 실패 조건을 따라 개발 문서·변경 기록·유사 이미지 비교 제작기·메타데이터 문서로 확장한다. 특정 제품 이름을 검색 조건으로 고정하지 않는다. 중요한 주장이 드러나면 Claim map과 Retrieval plan을 만들고 후속 자료로 검토한다.

전체 기록을 사용한다. 후보 비교, 데이터 손실 위험, 여러 주장과 버전 충돌 가능성이 있어 간소화 요건을 충족하지 않는다. 실제 공개 검색은 불가능하며 제공 자료의 비교가 원요청의 폭넓은 실제 제품 탐색 완료를 뜻하지 않는다.

실제 검색 대신 제공 파일의 본문과 연결 관계를 추적한다. 아래 단서는 로컬 검토용이며 웹 검색을 수행했다는 기록이 아니다.

| 대상 | 원천 역할·다음 자료 | 찾을 단서 / 반대·실패 단서 | 적용·최신성 및 대체 경로 |
|---|---|---|---|
| C1 | `01` 설명 → `02` 개발 문서 | 이동, preview, transaction / 중단, 복수 볼륨, overwrite, rollback | Pathframe 1.7과 코드 설명을 대조. 실제 OS API 문서·이슈는 제공되지 않았고 네트워크로 확인 불가 |

자료의 `.example` 주소는 합성 문서의 출처 표기다. 네트워크 요청하지 않고 로컬 경로로 본문을 검증한다. 실제 공개 원문·저장소·API·feed·archive·렌더링 경로는 이번 실행에서 미시도이며, 네트워크·브라우저 미제공 때문에 사용할 수 없다. 이를 개별 URL의 404나 접근 실패로 꾸미지 않는다.

전체 탐색 범주는 직접 폴더 조작, 복사 보관함, 원본 참조 카탈로그, 서비스 의존 검색이라는 반대 사례, 인접 분야의 후보 검토 전용 도구, 날짜 읽기 모듈이다. ‘앱 안에서 분류해서 보는 것’과 ‘디스크의 실제 배치를 바꾸는 것’을 나누면 더 작게 시작할 선택도 있다. 이는 에이전트 해석이며 어떤 결과를 우선할지는 사용자에게 남아 있다.

실제 제품·추가 공개 구현·라이선스·사용 후기·실제 시각 사례는 미탐색이다. 자료 범위 밖의 다른 구조가 없다고 결론내리지 않는다. 클라우드 제품 전반이나 다른 운영체제 제품 전반으로 범위를 넓히지는 않았으며, 그것이 원요청의 폭넓은 로컬 도구 탐색을 완료했다는 뜻도 아니다.

## Gap loop와 반대·실패 점검

1. **첫 묶음: S1·S3·S4.** 두 가지로 제시된 열린 선택에 원본 참조 카탈로그를 추가했다. 폴더 직접 관리에도 sidecar 쓰기가 있고, 복사 보관함도 기존 폴더를 정리하지 않는 차이를 확인했다. 가장 큰 공백을 최신 버전의 로컬 동작과 실제 파일 변경의 보장 범위로 정했다.
2. **후속 묶음: S2·S5·S6.** S5는 S4의 재게시로 합쳤다. S6으로 2.8의 로컬 특성을 3.0에 적용하는 주장을 반박했다. S2의 드라이브 간 중단·외부 변경·원자성 제한을 파일 변경 계획의 선행 검증 항목으로 옮겼다. ‘원본이 로컬’이라는 사실만으로 온라인 연결과 업로드가 없다고 판단하지 않는다.
3. **인접 구현 묶음: S7·S8.** 유사 후보 검토·선택 내보내기라는 작은 대안과 날짜 읽기·쓰기 분리를 추가했다. 사진 정확도·대규모 성능·메타데이터 형식 지원·코드 재사용 조건이 새 공백이다. 공개 구현의 실체는 S8의 최소 반환 구조뿐이며, S2·S7은 구현 설명이다.
4. **마지막 공백 점검:** evidence/ 전체에서 복구·원자성·중단·온라인·동기화·보안·측정·누락·fixture·재게시·테스트·라이선스/저작권 표현을 다시 검색했다. 결정적 반대 근거는 위 표에 반영했다. 라이선스·저작권 조건은 이 묶음에서 발견하지 못했다. 이것은 권리 부재나 자유 재사용의 증거가 아니다.

이 로컬 묶음의 관련 본문은 모두 읽었고 같은 문서를 재검색해 실제 공개 구현·화면·측정 자료가 생기지는 않는다. **이 묶음의 추가 재독 효용이 낮은 것과 폭넓은 실제 탐색의 추가 효용이 낮은 것은 다르다.** 실제 제품·공개 구현 조사는 선택을 바꿀 수 있어 종료를 선언하지 않는다. 네트워크 제한을 접근법 비교 완료로 대신하지 않는다.

더 적게 만드는 대안도 같은 지위로 유지한다. 후보 검토만 만들면 변경·복구 부담이 줄지만 정리는 외부에서 해야 한다. 기존 도구 사용·개발 연기도 가능하지만 실제 제품 적합성을 확인하지 않았으므로 어느 제품이 충족한다고 말하지 않는다. 여러 저장 방식을 모두 지원하는 혼합 제품을 기본안으로 추가하지 않는다.

## Web closure와 Discovery 완료 판정

Web Evidence 형식은 로컬 대체 자료에 적용했다. 핵심 주장·원문·확인일·버전·반대 근거·접근 경로·남은 공백이 연결되어 있다. 실제 웹 접근과 Browser 관찰은 미수행이며, 실제 공개 근거에 대한 Web closure는 **미통과**다. 공개 경로가 없는 이유와 재개 조건을 명시했을 뿐 충분한 조사 종료를 뜻하지 않는다.

| Discovery 조건 | 현재 판단과 근거 |
|---|---|
| 1. 접근법 비교 | 합성 자료 범위에서는 폴더·보관함·참조 카탈로그와 인접 대안·반대 사례의 차이 및 선택 조건을 비교했다. 실제 solution space의 포괄성은 미확인 |
| 2. 적합한 직접 근거 | 모든 제공 본문과 결정적 버전 변경·재인용·실패 경험을 직접 읽었다. 문서 설명을 비교하는 데는 적합하나 실제 제품·화면·공개 구현·성능 판정에는 부족 |
| 3. 적용 가능성 | 가져올 요소·변경·공간/관리/검증 비용을 구체화했다. 라이선스·지원·실제 재현성은 미확인이라 구현 채택을 승인할 수준은 아님 |
| 4. 결정 영향 | 조건부 후보 유지·채택 근거 제외·작은 대안을 제시했고 사용자 결정과 분리했다. Topology와 저장 방식 모두 아직 사용자 미확인 |
| 5. 타당한 종료 | **미충족**. 제공 묶음의 재독 효용은 낮지만 실제 제품·공개 구현·시각 자료라는 중요한 미탐색 범위가 남음. 연결 제한으로 중단된 탐색이지 충분한 탐색 완료가 아님 |

따라서 요청된 폭넓은 탐색은 완료하지 않았다. Idea closure나 Execution closure로 넘어가지 않는다.

## Verdict

- **판정: 결론 보류.** 제공된 합성 사례의 차이·버전 제한·실패 조건을 문서 수준으로 비교한 범위에서는 설명 가능하다. 실제 제품 선택·코드 채택·원본 관리 모델 확정 및 안전성 검증은 결론 보류다.
- **근거:** S1·S3·S4가 세 저장 접근의 차이를, S2가 작업 기록과 복구의 한계를, S7·S8이 후보 검토·날짜 출처라는 조합 가능한 방식을 보여 준다.
- **반대 근거:** S6은 구버전의 독립 로컬 기능 일반화를 반박한다. S5는 독립 확인이 아니다. 폴더 방식도 sidecar를 쓰고, 보관함은 기존 폴더를 정리하지 않으며, 유사 후보는 오탐·누락·원본 혼합 위험이 있다. 어떤 자료도 완전한 복구를 보장하지 않는다.
- **후보·채택·제외:** 세 저장 방식은 조건부 후보로 유지한다. Indexlens 3.0을 독립 로컬 도구의 근거로 채택하는 것은 배제한다. 구버전 설치·특정 실제 제품 채택·라이선스 미확인 코드 재사용은 추천하지 않는다. 원본 무변경의 보기·후보 검토부터 시작하는 축소안은 에이전트 제안으로만 둔다.
- **한계:** 가상 제품의 텍스트 자료만 있다. 실제 공개 탐색·독립 실사용 검증·화면·실행·사용자 데이터·현재 PC 조건이 없다. 도구 미제공을 탐색 수행 완료로 해석하지 않는다.
- **신뢰도:** 합성 문서의 기술 내용·버전·원천 관계 요약은 높음, 조건부 설계 적용 추론은 중간, 실제 제품 적합성·성능·안전성·코드 재사용 가능성은 낮음 또는 판정 불가.
- **Idea에서 바꿀 내용:** 원래 두 저장 선택 외에 참조 카탈로그·후보 검토 전용 축소안을 미승인 제안으로 추가한다. 원본 위치·앱 데이터 쓰기·검색 실행/외부 전송을 혼동하지 않도록 열린 선택을 보완한다. 사용자 제약은 바꾸지 않는다.
- **Execution에서 바꿀 Phase·Build:** 아직 Execution 단계가 아니므로 파일·번호를 만들지 않는다. 실제 사례 탐색을 먼저 보완하고, 향후 선택한 모델의 검증 및 날짜·유사성 검증을 해당 결과에 의존하는 구현보다 앞에 놓는다. 파일 변경을 선택할 경우 안전성 검증이 실사용 원본 변경에 선행해야 한다는 제안만 남긴다.
