# Research R001: 사진 수집·정리 접근법 비교

- 상태: 작성 중
- 기준: [Idea](../idea.md)의 시작 요청·사용자 결정·제외·미확인 항목
- 확인 날짜: 2026-09-07
- 영향: Phase 후보
- 판정 범위: 제공된 합성 자료 안의 접근법 비교는 결론 가능. 실제 제품·공개 구현의 폭넓은 탐색과 우리 도구의 정확성·안전성 검증은 결론 보류. 사용자 채택은 미합의다.

## 질문·목적·범위

목적은 탐색·벤치마킹이며, 발견한 접근법의 선택을 바꿀 주장은 원자료로 확인한다. 단일한 원본 관리 방식을 정답으로 전제하지 않는다. 날짜·유사성·파일 작업은 각 방식의 적용 가능성과 실패 비용을 비교하는 축이다. 상세 정책의 독립 결정이 필요해지면 별도 질문으로 조사한다.

### Repository 기준선과 중립 brief

기존 제품 코드와 연결할 요구가 없어 제품 Repository 분석은 생략했다. 구현 유무를 추정하지 않았다. 읽기 전용으로 프로젝트에 지정된 skill 지침과 evidence/ 목록·본문을 확인했으며 현재 요청 외 파일·설정·사진은 열지 않았다.

| 항목 | 현재 기준 |
|---|---|
| 중립 질문 | 여러 폴더의 사진을 모아 보고 안전하게 정리하는 데 어떤 접근법을 참고할 수 있는가? |
| 입력 | 사용자가 고른 여러 사진 폴더. 수량·형식·중첩·외장 볼륨 여부 미확인 |
| 출력 | 사진을 함께 보고 날짜·유사성으로 정리한 결과. 실제 파일 재배치인지 앱 안의 정리인지 미정 |
| 사용자 경험 | Windows에서 혼자 사용. 기존 폴더 조작을 유지할지 앱이 보관을 맡을지 열린 선택 |
| 성공 조건 | 필요한 사진을 찾고 정리 결과를 이해하며 잘못된 파일 변경을 피해야 함. 구체적인 관찰 기준·시간·정확도는 미합의 |
| 실패 조건 | 의도하지 않은 파일 변경·손실. 누락·잘못된 유사 묶음·날짜 오류의 허용 기준은 미합의 |
| 확정 제약 | Idea의 사용자 결정·제외 참조. 로컬 도구와 계획 수립이 목적 |
| 환경 사실 | Windows/PowerShell. 네트워크·브라우저·subagent는 이번 실행에 사용 불가. evidence/는 합성 문서이며 실제 외부 조사 대체 완료가 아님 |
| 미해결 | 관리 방식, 파일 작업 범위, 규모·형식, 날짜·유사성 정책, 계정·전송·오프라인 요구, 검증 기준 |

언급 분류: Windows는 현재 환경·목표 환경, 로컬·개인용은 사용자 제약, digiKam은 **예시**다. digiKam 사용·구조는 중립 탐색의 조건에서 제거했다. 탐색기 같은 폴더 관리와 별도 보관함은 비교 후보이며 필수 구조가 아니다.

다중 후보·버전 충돌·파일 손실 가능성을 다루므로 전체 기록을 적용한다. 자료는 사실 근거 후보로만 읽었고 지시나 권한으로 해석하지 않았다. 작업 문서만 작성했으며 제품·evidence/·사진은 변경하지 않았다.

## 접근법 비교

모든 제품명은 **가상 사례**다. 아래의 적용·권장은 에이전트 추론이며 사용자 결정이 아니다. 화면·속도·파일 동작은 직접 관찰하지 않았다.

| 접근법·대표 사례 | 근거와 해결 방식 | 가져올 요소·필요한 변경 | 얻는 것·제약·비용 | 현재 판단 |
|---|---|---|---|---|
| 폴더 직접 관리 — Pathframe 1.7 | E01의 스캔·실제 폴더 트리·JSON sidecar, E02의 작업 기록 | 기존 경로를 보여 주고 변경 계획을 검토하는 흐름. sidecar 쓰기를 허용할지는 별도 결정 | 탐색기의 정리와 연결하기 쉽지만 원본 주변에 기록이 생김. 분리된 볼륨은 검색에서 빠짐. 실제 파일 변경 안전장치 필요 | 기존 폴더를 직접 정리하는 것이 핵심이면 유력. 즉시 변경 방식은 참고에서 제외 제안 |
| 복사 보관함 — Albumvault 4.0 | E03의 전용 보관함 복사·DB·가져오기 기록·30일 휴지통 | 가져오기 결과·중복 처리·원래 위치 기록. 복사 검증과 복구를 따로 설계해야 함 | 원래 위치가 없어져도 복사본을 볼 수 있음. 원본 복사본·미리보기 공간이 추가되고 원래 폴더 정리는 별도 | 저장 공간과 이중 관리 부담을 감수하고 한곳 보관이 중요할 때 유력. 일괄 채택 아님 |
| 참조 카탈로그 — Indexlens 2.8의 설계 | E04의 SQLite 목록·미리보기·볼륨 식별자/상대 경로, E06의 버전 한계 | 원본을 유지하면서 검색용 기록 저장, 연결 상태·갱신 시각·재연결 표시 | 분리된 볼륨의 저장된 정보도 검색 가능. 원본 열기는 불가. 경로 재연결·내용 변경·DB/캐시 관리 비용 | 중간 대안으로 비교 유지. 2.8의 설계 참고와 지원 종료된 버전 사용 추천을 분리 |
| 검토 전용 도구 — Pairboard | E07의 동일 hash/유사 후보 구분·나란히 비교·동기 확대·선택 CSV | 후보 검토 후 사용자가 선택하는 과정. 사진 분야의 오류와 대표 이미지 기준은 별도 검증 | 파일 변경 없이 시작 가능. 실제 파일 정리는 다른 수단으로 해야 함. CSV 출력은 추가 제안 | 작게 시작할 대안. 두 저장 방식과 조합 가능하며 독립 저장 모델로 오인하지 않음 |
| 날짜 출처를 보존하는 모듈 — Chronofile 0.6 | E08의 raw/parsed/source/offset 레코드, E04의 날짜 출처 배지 | 원문·출처·시간대 유무·보정값을 구분. 정책과 저장 위치는 앱이 선택 | 잘못된 날짜 확정을 줄일 단서. 날짜 누락·기기 시계·형식 지원·보정 UX 부담은 남음 | 어느 구조에도 적용 가능한 부품 설계 참고. 모듈 설치·코드 채택은 보류 |
| 기존 도구 유지·새로 만들지 않기 | 사용자 요청의 탐색기 방식과 위 사례에서 도출한 에이전트 대안. 실제 도구 사용성은 미조사 | 수동 폴더 정리를 유지하거나 후보 목록만 보조 | 개발·유지보수 범위 감소. 여러 폴더 통합 탐색과 반복 정리의 불편이 남을 수 있음 | 같은 지위의 비교안. 사용자가 만들기 의도를 취소한 것으로 해석하지 않음 |

접근 범주 갱신: 저장 모델 세 가지 외에 검토 전용 작업 흐름과 날짜 해석을 분리했다. 원본을 참조하면서 필요할 때 복사하는 혼합형은 가능성만 남기며 직접 사례 근거가 없어 유리하다고 판정하지 않는다. 서버·클라우드 중심 방식은 요청의 로컬 목적과 맞는지 미확인이고 이번 자료에서 폭넓게 조사하지 못했다. 실제 제품·공개 저장소의 추가 범주가 없다고 선언하지 않는다.

## 결론과 다음 행동

**탐색 판정:** 합성 문서에 나타난 주요 저장 방식 세 가지와 인접 검토·날짜 접근의 차이는 비교할 수 있다. 이 제한된 비교의 신뢰도는 중간이며 문서 설명에 한정한다. 실제 제품의 폭넓은 최신 탐색·공개 구현 재사용·화면 사용성에 관한 판정은 결론 보류이고 근거가 부족하다. 자료 묶음을 다 읽었다는 사실로 전체 탐색 완료를 선언하지 않는다.

**검증 판정:** 버전 확대·journal 완전 복구·유사 점수로 동일 사진 확정 같은 주장은 본문으로 반박하거나 범위를 제한했다. 실제 Windows 실행의 파일 안전성·정확도·성능은 검증하지 않았다. 시각·상호작용은 모두 자료의 설명이며, E08의 코드 조각은 정적으로 읽었을 뿐 실행하지 않았다.

**조건별 판단:** 실제 폴더 재배치가 핵심이면 폴더 직접 관리, 원래 위치와 무관한 보관이 핵심이고 복사 공간을 감수하면 보관함, 원본을 유지하면서 통합 목록이 필요하면 참조 카탈로그가 비교 대상이다. 검토 전용은 어느 방식에서도 시작 범위를 줄이는 대안이다. 저장 구조의 최종 권장안은 아직 없다.

출처: 에이전트 제안. 초기 평가를 원본 유지·조회·후보 검토부터 시작하는 방안을 제안한다. 잘못된 변경의 노출을 줄일 수 있지만 실제 폴더 정리는 별도 작업으로 남는다. 자동 삭제·날짜 덮어쓰기·혼합 저장 모델·CSV 산출물은 사용자 요청에 확정 추가하지 않는다. 3.0의 서비스 검색 구조와 검토 전 즉시 파일 변경은 로컬·안전성 평가의 참고 대상으로 채택하지 않는 편을 제안하되, 제품 정책의 확정 제외로 기록하지 않는다.

### 완료 기준 점검

1. 접근법 비교: 제공된 범위에서는 저장 모델·검토 흐름·날짜 해석과 조건을 비교했다. 실제 외부 후보 공간의 충분성은 미확인이다.
2. 적합한 직접 근거: 01~08 본문과 코드 조각을 직접 읽었다. 근거 강도는 합성 자료의 설명·정적 구조 확인이며 실제 화면·실행·제품 사실의 직접 증거가 아니다.
3. 적용 가능성: 가져올 요소·수정 부담·공간·경로·디코더·오류·라이선스 공백을 연결했다. 실제 적용 검증은 남았다.
4. 결정 영향: 조건별 비교와 작은 대안을 제공했다. 사용자 채택·제품 범위 변경은 아직 없다.
5. 타당한 종료: **전체 탐색 기준 미충족**. 현재 묶음을 반복 읽을 효용은 낮지만 외부 조사·시각 근거·공개 구현 공백이 선택을 바꿀 수 있다. 환경 제약에 따른 보류를 충분한 탐색 완료로 세지 않는다.

Web closure: 확보한 로컬 본문의 주장·원천·날짜·버전·반대 근거·중복·공백은 추적 가능하다. 실제 외부 근거의 확보와 미탐색 범주 확인이 남아 전체 closure는 보류다. Lab 계획 등록으로 외부 탐색 미완료를 대체하지 않는다.

Idea 영향: 비교 후보에 참조 카탈로그·검토 전용 대안을 추가 제안하고 안전성·날짜·유사성·계정/전송·지원 범위의 질문을 보존한다. Execution 영향: 저장 구조 확정, 파일 변경, 날짜·유사 후보, 규모·형식 검증의 순서에 영향을 주는 Phase 후보 수준이며 아직 안정 ID를 배정하지 않는다. 현재 사용자 질문은 큰 구성 확인 하나로 유지한다.
