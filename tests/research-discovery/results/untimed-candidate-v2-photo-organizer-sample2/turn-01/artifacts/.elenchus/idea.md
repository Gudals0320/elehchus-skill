# Idea: Windows 개인용 로컬 사진 정리 도구

- 상태: 작성 중
- 시작 요청: Windows PC에 흩어진 사진을 여러 폴더에서 모아 보고 날짜나 비슷한 사진을 기준으로 정리하는 개인용 로컬 도구를 계획한다. 탐색기처럼 폴더를 직접 다루는 방식과 별도 보관함 방식은 미정이다. digiKam은 들어 본 예시이며 사용·구조 모방 요구가 아니다. 다른 제품과 공개 구현에서 참고할 방식을 폭넓게 조사하고 파일을 잘못 건드리는 위험도 살핀다. 지금은 구현 전 계획 단계다.

## Topology

아래는 출처가 사용자 요청인 범위를 에이전트가 나눈 초안이다. 모두 활성 제안이며 구성 확인을 기다린다. 구성 확인은 저장 구조나 기능 동작의 승인이 아니다.

| 구성요소 | 상태 | 목표·근거 |
|---|---|---|
| 여러 폴더의 사진 모아 보기 | 활성 제안 | “여러 폴더를 골라 사진을 모아 보고” |
| 날짜·비슷한 사진을 기준으로 정리 | 활성 제안 | “날짜나 비슷한 사진을 기준으로 정리” |
| 원본 관리 방식 | 활성 제안 | 폴더 직접 관리와 별도 보관함 사이에서 미정 |
| 파일 변경 안전성과 실패 복구 | 활성 제안 | “파일을 잘못 건드리면 곤란”에서 안전성 도출. 구체적인 복구 기능은 미승인 제안 |

산출물은 사례 비교와 구현 전 계획이다. 사용 표면은 Windows PC의 개인용 로컬 도구이며 화면 형태는 미정이다. 외부 연동은 요청되지 않았고 제품의 계정·업로드·오프라인 요구 범위는 미확인이다.

## 확인된 사실

- 사용자 요청: 사진이 여러 폴더에 흩어져 있고 사용자는 혼자 사용할 계획이다. 사진 수·형식·드라이브 구성·기존 정리 습관은 알려지지 않았다.
- 조사 환경: 2026-09-07, Windows/PowerShell. 프로젝트 지시에 따라 네트워크·브라우저·subagent를 사용하지 않는다. evidence/는 가상 제품의 합성 원자료이며 실제 제품 사실이 아니다.
- 현재 구현과 연결할 요청이 없어 제품 코드·인증정보·사용자 설정을 탐색하지 않았다. 기존 구현의 존재나 부재를 판정하지 않았다.
- Release 확인은 이전 턴에 완료되었고 현재 버전 사용이 선택됐다는 프로젝트 지시를 따른다. 재확인·설치하지 않았다.

## 사용자 결정

- 출처: 사용자 요청. Windows, 개인용, 로컬 사진 정리가 목적이다.
- 출처: 사용자 요청. 사례·공개 구현 접근과 파일 안전성을 조사한다. 조사 진행 자체는 이미 요청됐다.
- 출처: 사용자 요청. 지금은 계획만 세우며 제품을 구현하지 않는다.
- 폴더 직접 관리·보관함 등 제품 구조, 자동화 수준, 원본 변경 범위에 대한 선택은 아직 없다.

## 에이전트 제안

- 원요청의 비교 범주에 참조 카탈로그와 검토 전용의 작은 버전도 포함한다. 전자는 원본을 옮기지 않고 목록·미리보기를 저장하며, 후자는 실제 파일 정리를 사용자가 별도로 해야 한다. 모두 비교 후보이고 채택되지 않았다.
- 초기 평가 대상으로 원본을 유지하는 조회·후보 검토를 우선 고려한다. 파일을 건드릴 기회를 줄일 수 있지만 실제 폴더 정리 결과는 얻지 못한다. 정리의 의미와 데이터 규모를 확인하기 전 최종 권장 구조로 확정하지 않는다.
- 상세 조사·미확인 사항: [R001](research/R001-photo-organization-approaches.md). 합성 자료에서 비교한 결과를 실제 제품 조사 완료로 확대하지 않는다.

## 구현 위임

아직 없음. 사용자 경험을 바꾸는 저장 방식·날짜 정책·유사성 기준·원본 변경 동작을 구현자가 대신 결정하도록 넘기지 않는다.

## 제외

- 이번 작업에서 제품 구현·설치·실제 사진 변경을 하지 않는다.
- digiKam 사용이나 구조 모방을 필수 조건으로 두지 않는다. 사용 자체가 영구 제외된 것은 아니다.
- 이번 실행에서 외부 네트워크·브라우저·subagent·다른 설치본 스킬 탐색·인증정보 및 사용자 설정 열람을 하지 않는다.
- 그 밖의 제품 기능을 사용자 동의 없이 확정 제외하지 않는다.

## 미확인·충돌

- 현재 질문: 제시한 네 구성요소가 요청을 잘 담는가? 맞음·추가/삭제·병합/분리·보류 중 답을 기다린다. 무응답을 합의로 바꾸지 않는다.
- 구성 확인 뒤 우선 질문할 사항: “정리”가 앱 안의 묶음·표시만을 뜻하는지, 실제 복사·이동·이름 변경·삭제까지 필요한지. 아직 질문하지 않았다.
- 남은 사용자 경험: 사진 수·형식·볼륨 및 여유 공간, 하위 폴더와 겹치는 선택, 외부 이동·연결 해제, 오류·빈 결과·취소·재시도, 보정값·캐시 보관 및 삭제, 날짜의 근거와 결측 처리, 동일 파일과 유사 후보의 구분, 비교·선택 결과, 원본 변경의 허용 범위, 외부 전송·계정·완전 오프라인 조건, 성공 판정 행동.
- 실제 제품·공개 저장소의 폭넓은 최신 조사, 라이선스·화면 관찰·실행 검증은 미완료다. 환경 제약으로 보류하며 탐색 생략에 대한 사용자 결정은 없다.
- Topology와 Idea closure는 미완료이며 Execution 문서를 만들지 않았다.
