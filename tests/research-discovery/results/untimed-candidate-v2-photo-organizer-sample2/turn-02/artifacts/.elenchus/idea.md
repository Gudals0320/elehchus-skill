# Idea: Windows 개인용 로컬 사진 정리 도구

- 상태: 작성 중
- 시작 요청: Windows PC에 흩어진 사진을 여러 폴더에서 모아 보고 날짜나 비슷한 사진을 기준으로 정리하는 개인용 로컬 도구를 계획한다. 탐색기처럼 폴더를 직접 다루는 방식과 별도 보관함 방식은 미정이다. digiKam은 들어 본 예시이며 사용·구조 모방 요구가 아니다. 다른 제품과 공개 구현에서 참고할 방식을 폭넓게 조사하고 파일을 잘못 건드리는 위험도 살핀다. 지금은 구현 전 계획 단계다.

## Topology

사용자는 제시한 구성 중 여러 로컬 폴더의 사진을 보고 정리하는 원래 범위에 동의했다. 아래 네 구성요소를 범위 정리로 유지하며 Topology 확인을 반영한다. 저장 구조·화면·추가 기능의 승인은 아니다.

| 구성요소 | 상태 | 목표·근거 |
|---|---|---|
| 여러 폴더의 사진 모아 보기 | 활성 | 인터넷 없이 기존 사진을 탐색하고, 외장 SSD 분리 시에도 이전에 본 사진 정보를 검색 |
| 날짜·비슷한 사진을 기준으로 정리 | 활성 | 날짜로 훑기, 크게 나란히 비교, 중복 삭제 전 직접 선택. 날짜 누락·오류 존재 |
| 원본 관리 방식 | 활성 | 명시적 적용 전 원본·메타데이터 불변. 폴더·보관함·참조 카탈로그는 열린 선택 |
| 파일 변경 안전성과 실패 복구 | 활성 | 이동 기능을 고를 경우 적용 전 목록 확인, 실패 시 원본 상태와 일어난 일 파악. 복구 방식은 미정 |

전체 산출물은 사례 비교와 구현 전 계획이다. 이번 턴은 Research 결론까지이며 전체 실행 계획 합의는 다음 대화로 남긴다. 사용 표면은 Windows PC의 개인용 로컬 도구다. 폴더 화면·타임라인·보관함 구조의 선호는 미정이며, 계정·클라우드 업로드·공유는 제외한다.

## 명료도

| 활성 구성요소 | 목표 | 제약 | 성공 기준 | 맥락 |
|---|---|---|---|---|
| 사진 모아 보기 | 확정 | 부분확정 | 부분확정 | 부분확정 |
| 날짜·유사 사진 정리 | 확정 | 부분확정 | 부분확정 | 부분확정 |
| 원본 관리 방식 | 부분확정 | 부분확정 | 부분확정 | 부분확정 |
| 파일 안전성·복구 | 확정 | 부분확정 | 부분확정 | 부분확정 |

남은 공백은 저장 공간·캐시 보관, 날짜 예외 처리, 실제 파일 작업의 포함 범위, 부분 실패·복구 기준, 성능과 형식 지원 검증이다. 우선순위가 높은 사용자 결정은 파일 변경을 도구에 어디까지 맡길지다. 내부 구조와 화면 선호는 이번 답으로 확정하지 않는다.

## 확인된 사실

- 사용자 진술: JPEG·PNG·HEIC 약 5만 장이 두 드라이브와 외장 SSD에 흩어져 있다. 촬영일이 없거나 잘못된 사진이 있다. 실제 사진을 열어 확인한 사실은 아니다. 하드웨어 세부·파일시스템·여유 공간·기존 정리 습관은 미확인이다.
- 조사 환경: 2026-09-07, Windows/PowerShell. 프로젝트 지시에 따라 네트워크·브라우저·subagent를 사용하지 않는다. evidence/는 가상 제품의 합성 원자료이며 실제 제품 사실이 아니다.
- 현재 구현과 연결할 요청이 없어 제품 코드·인증정보·사용자 설정을 탐색하지 않았다. 기존 구현의 존재나 부재를 판정하지 않았다.
- Release 확인은 이전 턴에 완료되었고 현재 버전 사용이 선택됐다는 프로젝트 지시를 따른다. 재확인·설치하지 않았다.

## 사용자 결정

- 출처: 사용자 요청. 기존 범위를 구체화한다. Windows에서 혼자 여러 로컬 폴더를 모아 보며 인터넷 없이 기존 사진을 찾아야 한다. 외장 SSD가 빠져 있어도 이전에 본 사진의 정보는 검색할 수 있어야 한다. 분리 중 원본 해상도로 열람하는 것까지 요구한 것은 아니다.
- 출처: 사용자 요청. 날짜로 훑기와 사진을 크게 비교하기가 중요하다. 삭제 전 중복 후보를 나란히 비교해 직접 고른다. 시각적 유사성만으로 자동 삭제하지 않는다. 삭제 기능 자체의 제공 시점·처리 방식까지 확정한 것은 아니다.
- 출처: 사용자 요청. 명시적으로 적용하기 전 원본 사진과 메타데이터를 바꾸지 않는다. 이동 기능을 선택한다면 적용 전 목록을 확인하고 실패 후 원본 상태와 무엇이 일어났는지 알 수 있어야 한다. 모든 파일 작업의 완전 되돌리기를 합의한 것은 아니다.
- 출처: 사용자 요청. 사례·공개 구현 접근과 파일 안전성 조사는 이미 허용됐다. 역할 분담도 허용됐지만 이번 실행의 네트워크·브라우저·subagent 미제공 조건은 유지한다. 외부 계정·유료 호출·실제 개인 사진 접근은 허용하지 않는다.
- 출처: 사용자 요청. 이번에는 Research 결론을 받고 전체 실행 계획 합의는 다음에 이어간다. 제품을 구현하지 않는다. 새로운 기능이나 비용을 확정하지 않는다.
- 출처: 사용자 요청. 폴더 화면·타임라인·보관함 구조의 선호는 미정이다. 특정 제품·엔진·DB는 필수가 아니며 내부 구조는 조사 근거를 바탕으로 제안받는다. 원자료에 없는 취향을 추정하지 않는다.

## 에이전트 제안

- 출처: 에이전트 제안, 미승인. 원요청 대비 저장 방식의 비교 대안으로 참조 카탈로그를 조건부 우선 제안한다. 분리된 SSD 정보 검색과 적용 전 원본 보존에 맞는다. 원본을 옮기지 않고 앱 전용 로컬 영역에 정보를 저장하는 방식이며, 목록 갱신·재연결·보관 공간 관리 부담이 생긴다. 미리보기 보관 범위와 SQLite 등 구체적인 DB는 미정이다. 폴더 화면이나 타임라인 채택을 뜻하지 않는다.
- 출처: 에이전트 제안, 미승인. 검토 전용의 작은 버전은 조회·날짜 탐색·후보 비교·선택까지 맡기고 파일 변경은 연기한다. 범위와 파일 손실 위험을 줄이지만 실제 폴더 정리·삭제는 별도로 해야 한다. 현재 조건을 모두 충족하는 완성안으로 판정하지 않는다.
- 출처: 에이전트 제안, 미승인. 날짜 원문·출처·시간대 유무를 보존하고, 원본과 앱 내 해석을 구분하는 설계를 참고한다. 동기 확대·경로/해상도 표시·변경 기록도 비교 참고 요소다. 날짜 보정 기능·CSV·휴지통 보관 기간·추가 비용은 채택하지 않았다.
- 상세 조사·미확인 사항: [R001](research/R001-photo-organization-approaches.md). 합성 자료에서 비교한 결과를 실제 제품 조사 완료로 확대하지 않는다.

## 구현 위임

특정 기술 채택이나 구현 실행은 아직 위임하지 않았다. 제품·엔진·DB는 필수가 아니며 근거를 보고 내부 책임 구성을 제안할 수 있다. 사용자 경험을 바꾸는 저장 방식·날짜 정책·유사성 기준·원본 변경 동작은 구현자가 대신 결정하도록 넘기지 않는다.

## 제외

- 이번 작업에서 제품 구현·설치·실제 사진 변경을 하지 않는다.
- 출처: 사용자 요청. 제품 범위에서 계정·클라우드 업로드·공유·얼굴 인식·사진 편집을 제외한다. 시각적으로 비슷하다는 이유만으로 자동 삭제하지 않는다.
- 출처: 사용자 요청. 이번 조사에서 외부 계정·유료 호출·실제 개인 사진 접근을 제외한다.
- digiKam 사용이나 구조 모방을 필수 조건으로 두지 않는다. 사용 자체가 영구 제외된 것은 아니다.
- 이번 실행에서 외부 네트워크·브라우저·subagent·다른 설치본 스킬 탐색·인증정보 및 사용자 설정 열람을 하지 않는다.
- 이동·삭제 기능 전체를 확정 제외한 것은 아니다. 포함 범위는 미정이며, 더 작은 버전이나 만들지 않기는 비교 대안이다.

## 미확인·충돌

- 현재 답으로 범위 확인을 반영했으며 다시 묻지 않는다. 명시된 요구 사이에 확인된 충돌은 없다. 자료의 제약과 요구의 충돌은 R001의 후보 적합성에 반영한다.
- 다음 계획 대화의 첫 질문: “실제 파일 변경을 이 도구에 어디까지 맡길까요?” 이동·삭제 등의 포함 여부가 안전성 검증 범위와 저장 구조의 선택을 바꾸므로 먼저 다룬다. 이번 Research 전달을 이 답이나 구조 승인으로 막지 않는다.
- 남은 사용자 경험: 하위 폴더·겹치는 선택의 처리, 날짜 없음/잘못된 날짜의 표시·정렬·보정 여부, 비교·선택 결과 보관, 오프라인 정보의 구체적인 항목, 캐시의 위치·용량·보관/삭제, 여유 공간, 외부 이동·내용 변경·재연결, 빈 결과·오류·취소·재시도, 실제 파일 작업 범위와 복구 한계. 수량·형식·단독 사용·계정/전송 제외·오프라인 요구는 다시 미정으로 돌리지 않는다.
- 성공 기준 중 확정된 관찰: 인터넷 없이 탐색, SSD 분리 후 이전 정보 검색, 적용 전 원본·메타데이터 불변, 삭제 전 나란히 비교·직접 선택, 이동 채택 시 계획 목록과 실패 후 원본 상태 확인. 검색/초기 스캔 대기 시간·유사 후보 오탐/누락 허용치·HEIC 실패 처리·복구의 구체적 판정은 미합의다.
- 실제 제품·공개 저장소의 폭넓은 최신 조사, 라이선스·화면 관찰·실행 검증은 미완료다. 환경 제약으로 보류하며 탐색 생략에 대한 사용자 결정은 없다.
- 이전의 “구성 확인 대기”는 이번 사용자 답으로 대체됐다. R001의 “구조 권장안 없음”은 새 조건에 따른 참조 카탈로그 조건부 제안으로 갱신됐지만 사용자 채택은 아니다.
- Topology 확인은 반영했다. Idea closure·Research 결론 합의·전체 탐색 closure는 미완료다. 실행 계획 합의는 사용자 요청대로 다음에 이어가며 Execution 문서를 만들지 않았다.
