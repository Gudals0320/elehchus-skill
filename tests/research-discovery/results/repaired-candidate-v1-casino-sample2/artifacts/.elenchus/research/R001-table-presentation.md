직접 확인: `app.txt:1`은 `UNIMPLEMENTED PRODUCT STUB`다. 현재 제품 동작·선택된 엔진·사용 성능의 근거로 삼을 내용은 없다. 전체 저장소가 비어 있다고 추정하지 않는다. 현재 질문에 필요한 Idea·원자료·프로젝트 스킬만 읽었으며 설정·인증정보는 조회하지 않았다.

`evidence/README.md:3,18`은 모든 제품·조직·수치·코드가 합성이며 이미지·영상·데모가 없다고 명시한다. 아래 제품명은 모두 가상 사례다. 원문 파일의 텍스트는 직접 읽었지만 화면·사용성은 직접 관찰하지 않았다. `.example` 주소는 출처 식별자이며 접속 대상이 아니다.

## 사용자 기술 언급 분류

Windows PC는 현재 환경, 데스크톱 Chrome 우선은 지원 제약, 터미널→웹은 진행 제약이다. 애니메이션에 가까운 3D 느낌은 사용자 표현 목표이며 엔진 지정이 아니다. 특정 엔진·라이브러리 필수 선택은 없다. HTML·CSS 등 아래 구현 방식은 자료에서 발견한 후보이며 neutral brief의 강제 조건이 아니다.

## 조사 목적·범위와 증거 계획

목적은 탐색·벤치마킹이다. 직접 유사 사례의 화면·조작과 인접 보드게임의 가독성 해결을 비교한다. 제품 구현이나 사용성 실험을 수행하지 않는다.

## 탐색·벤치마킹

모든 화면·움직임 사실의 관찰 수준은 **자료의 설명**이다. 적용·비용 평가는 **추론**이며 직접 관찰·측정이 아니다.

| 접근법·가상 사례 | 원문 위치·화면과 조작 설명 | 가져올 요소·우리 조건의 수정 | 부담·한계·판정 |
|---|---|---|---|
| 3D 테이블+HTML — Tablehaven 0.8 | T-P:6–10. 고정 사선, 캐릭터 없음, 3D 목재 테이블·카드·칩과 HTML 점수·잔액·버튼. 휠은 오른쪽 2D 베팅 패널 | 공간 표현과 읽기·입력의 분리를 비교할 수 있음. 우리 블랙잭 스플릿 패, 바카라 세 영역, 싱글 제로 베팅과 공통 자금을 위한 실제 배치는 별도 확인 | 3D와 HTML 간 크기·위치·상태 조정 필요. 문서만으로 가독성이나 애니메이션풍 적합성은 알 수 없음. **우선 비교 후보, 미승인** |
| HTML 이미지+CSS 원근감 — Flatfelt 2.1 | F:6–10. 카드·버튼이 같은 레이아웃, 원형 휠 이미지와 별도 공 레이어. 종료 시 한 줄 결과 후 다음 베팅 입력 | 세 게임 숫자·조작을 같은 화면 흐름에 넣는 단순화 비교. 주변 공간은 배경 이미지 정도로 표현 가능하다는 추론 | 실제 3D 모델·조명 없음; 입체 재질·둘러보기 미지원. 제작 부담 감소는 저자 설명으로 같은 조건 측정 없음. **더 작은 대안**, 사용자 3D 목표의 충족 여부 미확인 |
| 공간 이동·캐릭터 중심 — Orbitroom | O:6–10. 아바타로 홀 이동→착석 카메라, 멀티·딜러. 캐릭터가 칩을 가려 외곽선·상단 패널 추가 | 장식·인물이 입력을 가리는 실패 조건 참고 | 이동·캐릭터·멀티와 로컬 모드 부재는 현재 요구와 부합하지 않음. 복도·조명·좌석 제작 부담. **이 경험은 사용자 범위에 따라 제외**; 일반적인 3D 실패로 확대하지 않음 |
| 공간을 보이되 화면 밖 조작 — Pileplay | P:6–10. 테이블·주변 선반 일부, 하단 행동 띠. 실제 크기 토큰이 안 보여 색·높이를 과장; 바뀐 토큰만 이동 | 주변 공간과 별도 텍스트의 공존, 작은 소품을 화면에서 구별시키는 원칙을 비교 | 보드게임의 인접 사례로 다중 베팅·작은 숫자 화면 기록 없음. 색·높이 과장과 이동 감소의 효과는 저자 설명. **부분 참고**, 특정 색·선반·확대 기능을 요구로 추가하지 않음 |

확인한 범주는 전체 3D 공간, 한 테이블 3D+화면 UI, CSS 원근감의 간소화, 인접 테이블 상호작용이다. 직접 3D 영역을 누르는 방식은 Orbitroom의 가림 사례가 일부 근거이며, 캐릭터 없는 단일 테이블 전체를 3D 조작으로 처리한 비교 자료는 없다. 탑뷰 등 다른 카메라, 애니메이션풍 색·재질, 서로 다른 입력 장치의 실제 사용성 역시 미탐색 공백이다. 이를 불필요하거나 열등한 접근으로 제외하지 않는다.

라운드 설정 비교: Tablehaven의 약 9초는 베팅 클릭부터 다음 베팅 가능 상태까지의 기본 카드 라운드 설명(T-P:8)이다. Flatfelt의 180ms는 카드 한 장 공개 설정 예시(F:10)다. 서로 같은 구간의 측정이 아니므로 빠르기 비율이나 선호를 계산하지 않는다. Tablehaven의 공개 건너뛰기·결과 유지, Flatfelt의 즉시 다음 입력은 비교 후보이며 우리 기능으로 합의된 내용이 아니다. Tablehaven의 모바일·키보드 단독 미지원도 우리 지원 정책이 아니다.

## Web closure와 Discovery 완료 판정

본문·출처·날짜·버전·반대 근거·중복 통합은 확인했다. 로그인 Browser Evidence는 해당 없음이다. C4에 필요한 공개 시각 관찰은 미수행이며 후속 자료 확보에 연결한다. 따라서 **전체 시각 선택에 대한 Web closure는 통과하지 않는다**. 제공 문서 설명의 제한된 사실 확인만 가능하다.

## Verdict와 현재 선택

- 판정: **결론 보류** — 최종 화면·조작 선택. **결론 가능** — 위 합성 문서 안에서의 방식 차이와 범위 적합성 비교.
- 근거: T-P의 단일 테이블+화면 UI는 사용자 공간·가독성 요구를 함께 검토할 근접 후보다. P는 주변 공간과 화면 밖 텍스트를 함께 다루는 인접 설계를 제공한다.
- 반대 근거: F는 제작을 더 줄이는 선택이다. O는 3D 공간·인물이 가독성을 해칠 수 있음을 설명한다. T-P에도 키보드 단독 지원 한계가 있고, P는 다중 베팅·작은 숫자를 검증하지 않았다.
- 추천: **출처: 에이전트 제안·미승인.** 3D 테이블+HTML 조작을 먼저 비교할 후보로 두고 CSS 원근감 대안과 나란히 판단한다. 표현 목표와 제작 부담을 비교하려는 제안이며 카메라·색·재질·조작 위치의 확정이 아니다. 특정 시각 취향에는 권장안 없음.
- 채택·제외: 채택한 엔진·카메라·재질·UX 기능 없음. 공간 이동·캐릭터·현재 멀티는 사용자 제외 범위에 따라 후보 경험에서 제외한다. 자료의 공개 건너뛰기·확대·결과 유지·색 과장을 새 기능이나 취향으로 편입하지 않는다.
- 한계·신뢰도: 제공 원문이 무엇을 설명하는지는 높음. 우리 요구에 대한 설계 적합성 추론은 중간. 시각적 완성도·반복 사용·제작 기간·성능·실제 제품 일반화는 근거 부족이며 낮음.
- Idea 변경: 승인된 범위·제외를 보존하고 비교 후보와 미결정을 연결한다. 사용자 결정을 대체하지 않는다.
- Execution 영향: 향후 웹 표현 Phase 후보에 영향을 준다. 실제 장면 비교가 디자인 확정과 에셋 제작보다 선행해야 한다는 조건만 남긴다. Phase·Build 번호·전체 실행 계획은 이번에 작성하지 않는다.

## 보류와 다음 행동

1. **자료 확보 후 비교 필요, 미수행:** 테이블 전체와 주변 공간, 바카라 베팅/정산, 블랙잭 스플릿 시 숫자·버튼, 룰렛 베팅/공 착지 장면을 실제 화면·영상 또는 공개 데모로 비교한다. 접근 가능한 자료가 제공되는 후속 조사에서 수행하며 현재 만들어 낸 이미지로 사례 관찰을 대체하지 않는다.
2. **그 다음 사용자 선택:** 카메라·구도·색·재질, HTML/3D 역할, 연출 속도·건너뛰기·결과 유지, 필요한 입력 지원. 자료 속 값을 우리 기본값으로 넣지 않는다.
