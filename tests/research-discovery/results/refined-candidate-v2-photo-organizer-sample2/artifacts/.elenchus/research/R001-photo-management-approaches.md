# Research R001: 사진 관리·검토 방식 비교

- 상태: 작성 중
- 기준: [idea.md](../idea.md)의 시작 요청, 사용자 결정, 제외, T1~T4와 열린 선택
- 확인 날짜: 2026-09-07
- 영향: Phase 후보. Execution은 아직 작성할 단계가 아니다.
- 목적: 접근법 탐색·벤치마킹 및 자료 속 주요 주장 검증. 실제 제품 동작·성능 검증은 수행하지 않는다.

## 질문·목적·범위

### Repository 기준선과 neutral brief

기존 제품 코드 수정 요청이 아니며 현재 판단 대상은 관리 방식의 선택이다. 제품 Repository 동작 조사는 생략한다. 프로젝트의 AGENTS.md, 지정 skill/SKILL.md와 필요한 단계 지침, evidence/README.md를 읽었다. .elenchus/의 기존 문서는 없었다. 원본 사진·인증정보·사용자 설정은 조사하지 않았다.

| 항목 | 현재 기준 |
|---|---|
| 중립 질문 | 여러 폴더에 흩어진 사진을 날짜·유사성으로 모아 보고 정리할 때, 어떤 관리·검토 방식이 사용자 통제와 파일 안전성에 맞는가? |
| 입력 | 사용자가 선택할 Windows PC의 여러 사진 폴더. 형식·규모·드라이브 조건 미확인 |
| 출력 | 방식별 비교, 적용 조건·비용·실패·복구 근거, 미승인 제안과 후속 사용자 결정. 실제 제품 파일 출력의 형태는 미정 |
| 사용자 경험 | 혼자 로컬에서 사진을 모아 보고 정리를 판단. 기존 폴더 직접 관리와 별도 보관함 중 선택은 열려 있음 |
| 성공 조건 | 주요 접근법의 차이와 파일 변경 위험을 근거로 비교할 수 있음. 제품의 정량 성공 기준은 아직 미정 |
| 실패 조건 | 예시 제품을 정답으로 고정, 합성 설명을 실제 관찰로 승격, 파일 변경·복구를 근거 없이 보장, 사용자 미응답을 제품 선택 승인으로 해석 |
| 확정 제약 | idea.md의 사용자 결정·제외 참조. Windows·개인용·로컬·계획만 수행 |
| 객관적 환경 사실 | 제공된 원자료는 합성 문서다. 네트워크·브라우저·subagent 경로는 이번 실행에 없다는 사용자 지시. 화면·영상·실행 가능한 데모도 없음 |
| 미해결 질문 | 관리 구조, 정리 결과와 변경 권한, 촬영 날짜 해석, 유사 사진의 의미, 실제 Windows에서의 복구·성능·사용성 |

사용자의 기술 언급 분류: Windows는 현재 환경이자 대상 제약, digiKam은 예시. 예시 제품 이름은 후보 탐색 조건에서 제외한다.

### 증거 계획과 접근 범위

| 증거원 | 상태 | 이유 | 바뀔 수 있는 결정 |
|---|---|---|---|
| Repository | 생략 | 기존 제품 동작이 이번 방식 비교의 입력이 아님. 합성 공개 코드 조각은 아래 External evidence에서 검토 | 실제 코드 재사용·연동 가능성은 미확인 |
| Independent exploration | 생략 | 사용자 지시상 subagent 경로 없음. 메인이 사례·구현·반례를 나누어 검토하나 독립 조사로 부르지 않음 | 해법 누락과 결론 편향의 한계 |
| External evidence | 필요 | evidence/의 원문으로 접근 범주·구현 전략·버전 차이·실패 사례 비교. 실제 웹 조사 수행과 구별 | 관리 구조·정리 흐름·변경 책임 |
| Browser Evidence | 생략 | 개인화·로그인 상태 확인은 필요하지 않고 브라우저도 없음 | 실제 화면·조작감은 미확인 |
| Lab | 생략 | 지금은 자료 비교. 실행 가능한 제품·데모나 사용자 데이터가 없고 모의 성공으로 실제 파일 안전성을 판정할 수 없음 | Windows 동작·성능·정확성은 후속 검증 필요 |

전체 기록 깊이를 적용한다. 관리 방식 비교와 파일 변경 위험이 복합적이므로 단일 저위험 Claim의 간소화 기준에 해당하지 않는다.

읽기 계획: 먼저 원본 폴더·보관함·참조 카탈로그 설명으로 접근 범주를 찾는다. 이어 개발 문서·변경 기록·재게시·인접 비교 도구·메타데이터 문서에서 중요한 주장의 구현 조건과 반례를 추적한다. 검색 축은 폴더/보관함/카탈로그/비교, 반대 근거 축은 이동·중단·실패·복구·누락·버전·라이선스다. 후보 발견 후 주장별 반증 조건을 구체화한다.

접근 방법은 제공된 파일 본문 읽기다. 외부 URL은 출처 식별자로만 다루며 접속하지 않는다. 네트워크·공개 API/feed/archive·공개 브라우저 경로는 이번 실행에서 사용할 수 없으므로 시도하지 않는다. 이는 URL의 404·차단을 관찰했다는 뜻이 아니다. 원자료가 대신 답할 수 있는 주장만 범위를 제한하며 실제 제품 조사 공백은 유지한다.

### 발견 후 집중 검증할 주장

첫 원문 묶음에서 원본 폴더 직접 관리, 복사 보관함, 원본을 참조하는 카탈로그라는 서로 다른 세 범주를 발견했다. 다음 검토에서는 버전 변경, 파일 변경 실패, 유사성 비교와 날짜 근거를 우선한다. 아래 주장은 제품 선택이 아니라 검증 대상이다.

| ID | 주장·선택 영향 | 필요한 출처 역할·최신성·적용 범위 | 반증 조건·다음 경로 |
|---|---|---|---|
| C1 | 원본 폴더를 직접 다루면 기존 위치를 유지하며 작업을 이해할 수 있으나 변경·복구 책임이 생긴다 | 1.7 설명과 같은 제품 개발 문서. Windows에서 원본 이동·sidecar 변경의 조건 | 미리보기·이력만으로 중단 복구까지 보장되는가. transaction 문서의 실패·복구 확인 |
| C2 | 복사 보관함은 입력 폴더가 없어져도 가져온 사진을 조회할 수 있으나 추가 공간과 원래 폴더 정리가 남는다 | 4.0 가져오기 원문. 복사·중복 판정·삭제 보관 정책의 해당 버전 범위 | 참조 모드·시각 유사 합치기 지원 여부, 제거 범위가 원래 폴더에도 적용되는지 원문 한정 검토 |
| C3 | 참조 카탈로그는 원본을 옮기지 않고 분리된 볼륨의 미리보기를 조회하는 대안이다 | 2.8 원문과 최신 변경 기록, 재게시 원천. 계정·오프라인·지원 형식 구분 | 새 버전에서 같은 조건이 유지되는가. 변경 기록과 재게시의 출처·버전 확인 |
| C4 | 바이트 중복과 시각적 유사성은 다른 정리 판단을 지원한다 | 가져오기 원문과 유사 이미지 도구 개발기·코드. 실제 데이터·버전·라이선스 범위 | 크롭·압축·메타데이터 차이와 오탐, 자동 삭제까지 정당화하는지 확인 |
| C5 | 날짜 타임라인에는 날짜 출처와 불확실성을 드러내는 처리 방식이 필요할 수 있다 | 사진 날짜 설명과 메타데이터 개발 문서. 시간대·누락·형식의 조건 | 파일 날짜·EXIF가 항상 촬영 시점을 뜻하는가. 충돌·예외·지원 형식 확인 |
| C6 | 작은 SSD 데모의 성능은 사용자 규모와 복수 볼륨에 그대로 적용할 수 없다 | 원 측정 주체·데이터·디스크 조건, 재게시와 추가 기록 | 더 큰 규모·다른 매체에서의 직접 측정 또는 독립 재현이 있는가 |

## 비교와 근거

### 접근법 비교

세 가지 원본 관리 방식과 정리 일부만 맡는 인접 도구를 비교한다. 날짜 정보 처리와 파일 작업 기록은 이 방식들에 조합할 수 있는 구현 전략이며 별도 완성 제품 구조로 강제하지 않는다.

| 접근법·대표 합성 사례 | 근거·관찰 수준 | 해결 방식과 차이 | 우리 조건에서 가져올 요소·수정·비용 | 현재 판단 |
|---|---|---|---|---|
| 원본 폴더 직접 관리 — Pathframe 1.7 | S01 6~10행, S02 6~10행; 자료 설명 | 실제 폴더 트리와 파일에 대응. 날짜·즐겨찾기는 폴더별 sidecar. 분리된 볼륨의 검색·스냅샷 없음 | 폴더 통제와 작업 전 경로 목록을 참고. sidecar도 사용자 폴더 쓰기이므로 별도 결정 필요. 파일 변경·중단·충돌 처리 부담이 남음 | 기존 폴더를 직접 정리하고 연결된 파일 조회로 충분할 때 유력. 무조건 가장 안전하거나 항상 단순하다고 확정하지 않음 |

### 탐색 갱신과 남은 범위

1. 첫 묶음 S01·S03·S04에서 직접 폴더·복사 보관함·참조 카탈로그로 범주를 넓혔다. 유력 공백은 참조 방식의 현행 로컬 조건과 실제 변경 안전성이었다.
2. 후속 S02·S05·S06에서 중단 복구의 한계, 같은 원문의 재게시, 버전 변경을 확인했다. 구버전 설명의 재인용을 최신성이나 독립 출처로 세지 않았다. 로컬 원본이라는 문구와 오프라인 처리·업로드 없음의 차이를 반영했다.
3. S07·S08로 인접 분야의 검토 전용 흐름, 유사성·동일성 분리, 날짜 출처 보존을 추가했다. 공개 코드 조각의 범위는 직접 읽되 실행했다고 하지 않았다.
4. 반대·실패 검토 범위는 제공된 8개 본문 전체의 중단·연결 해제·공간·충돌·외부 변경·오탐·누락·지원 형식·버전·측정 조건이다. 인터넷·이슈 저장소의 별도 검색을 수행했다는 뜻이 아니다.

현재 자료에는 실제 현행 제품의 폭넓은 비교, 전체 공개 구현·라이선스, 실제 화면·동작, 보관함의 내보내기·재해 복구 구현이 없다. 다른 유사성 접근법(예: 학습 모델을 이용한 후보 생성)이 선택을 바꿀 가능성도 미탐색이며, 지원·성능을 가정해 후보로 채택하지 않는다. 클라우드 의존 방식은 로컬 요구의 적합성을 점검하는 반대 사례로 다뤘고 제품 범위에 추가하지 않았다. 다중 사용자·공유·얼굴 인식 등은 요청되지 않아 탐색 범위를 임의로 확대하지 않았다.

## 결론과 다음 행동

### Verdict

- **판정: 결론 보류.** 제공된 합성 문서 안의 접근 방식·버전 차이·실패 조건 비교는 결론 가능하다. 사용자가 요청한 실제 제품과 공개 구현의 폭넓은 조사, 특정 제품·라이브러리 채택, 실제 Windows 파일 안전성·속도·유사성 정확성·사용성 판단은 결론 보류다. 자료 검토를 수행했다는 사실과 원래 조사 요청의 완결을 구분한다.
- **근거:** 원본 직접 관리, 복사 보관함, 참조 목록, 후보 검토 전용이라는 다른 접근법을 원문과 조건에 연결했다. 로컬 참조 방식도 비교할 선택지라는 근거가 생겼으며 폴더/보관함 이분법으로 고정할 필요는 없다.
- **반대 근거:** 폴더 방식도 sidecar 쓰기·이동 실패가 있고, 보관함은 복사 공간·원래 폴더 정리가 남으며, 카탈로그는 외부 변경·오래된 정보·재연결 문제가 있다. 같은 제품의 새 버전은 온라인 서비스 의존으로 달라질 수 있다. 검토 전용은 변경 위험을 줄여도 실제 파일 정리까지 끝내지 않는다.
- **후보·채택·제외:** 구체적 제품은 채택하지 않는다. S06의 서비스 의존 구조는 로컬 방식의 근거로 제외하고 S04의 참조 설계 아이디어는 비교 대상으로 유지한다. 2.x 설치로 돌아가자는 추천은 하지 않는다. 이동·삭제 자동화와 완전 복구 보장은 근거가 부족해 확정하지 않는다. 이는 사용자가 해당 기능을 영구 제외했다는 뜻이 아니다.
- **신뢰도:** 높음—제공된 본문·버전·재게시 관계의 판독. 중간—그 설명에서 도출한 조건별 설계 비교. 낮음—우리 환경에서의 실제 적합성·정확성·성능·복구와 현실 제품 추천.
- **한계:** 전부 합성 자료이며 실제 외부 원문 방문·화면·영상·제품 실행·Lab·독립 에이전트 조사를 수행하지 않았다. 원문 계열이 같은 문서의 수를 독립 검증 횟수로 계산하지 않았다. 실제 제품 비교는 현재 환경의 접근 제한 때문에 열린 상태다.

|---|---|---|---|
| P1. 원본을 유지하는 참조 카탈로그를 관리 방식 비교에 추가 | 두 방식 사이의 대안 추가. 특정 제품·DB 채택은 아님 | 복사하지 않고 모아 볼 여지; 캐시·목록 갱신과 경로 재연결 책임 | 미승인 |
| P2. 초기 범위를 원본·sidecar를 변경하지 않는 조회·후보 검토로 줄이는 대안 | 원본 변경 기능의 도입을 연기하는 축소안. 임시·로컬 정리 정보 저장 방식은 별도 결정 | 사진 손상 위험을 줄여 판단 흐름부터 검토; 실제 폴더 정리와 공간 회수는 별도 작업 | 미승인 |
| P3. 파일 변경을 선택하면 계획 검토·충돌 확인·실행 시 원본 재확인·중단 기록을 요구 | “잘못 건드리면 곤란”을 구체화하는 안전 제안 | 변경 결과와 부분 실패를 이해할 수 있음; 단계·구현·검증 부담 증가, 완전 복구 보장은 별개 | 미승인 |

권장 범위는 **P1을 비교에 포함하고 P2를 작은 시작안으로 검토하는 것**까지다. 사진을 유지할 기준 위치와 “정리”의 결과가 미정이므로 최종 관리 방식의 단일 권장안은 아직 없다. 날짜 우선순위·후보 점수·자동 삭제 정책도 사용자에게 대신 확정하지 않는다.

### 남은 공백과 검증 순서

아래는 Execution에서 고려할 검증 후보이며 아직 Phase·Build나 제외·연기 합의가 아니다. 등록만으로 미완료 탐색을 완료 처리하지 않는다.

| 공백 | 다음 행동·관찰과 통과/실패 판단 | 선행해야 하는 결정·작업 |
|---|---|---|
| 실제 제품·공개 구현의 미탐색 범위 | 접근 가능한 후속 환경에서 유지되는 실제 원문·저장소·라이선스·변경 기록·실패 이슈를 비교. 세 관리 방식과 검토 전용 흐름의 유력 대안 누락을 재점검 | 구체적 제품·의존성·코드 재사용 채택 전. 현재 조사 요청은 미완료로 보존 |
| 파일 변경 안전성 | 합의된 작업 유형마다 충돌·부족한 공간·외부 수정·잠금·드라이브 분리·복사 중단·재개를 통제된 fixture로 관찰. 검증 안 된 복사 뒤 원본 제거, 재개 중 중복 제거, 설명할 수 없는 부분 완료는 실패 후보 | 허용할 쓰기·복구 계약 합의 후, 원본 이동·삭제 기능보다 먼저. 실제 실험은 미실행 |
| 참조 목록의 신선도 | 폴더 외부 이동·수정·연결 해제 후 표시·원본 접근·재연결 확인. 잘못된 파일을 원본으로 여는 경우 실패 후보 | 참조 방식 선택 시, 정리 결과 적용 전에 |
| 가져오기·보관함 책임 | 원본과 복사본 관계·재가져오기·공간 부족·휴지통 만료·내보내기·복구 범위를 합의하고 검증 | 보관함 선택 시, 실제 사진 이관 전에 |
| 날짜 해석 | EXIF 결측·시간대 없음·기기 차이·수정일 변화·손상 데이터·필요 형식에서 근거와 미확인 상태 표시 확인. 근거 없는 촬영 시점 확정은 실패 후보 | 날짜 정책·보정 저장 선택 전후, 날짜를 이용한 파일 변경 전 |
| 유사 후보의 의미·정확성 | byte 동일·크롭·압축·축소본·연사·비슷한 배경 등 합의한 예시로 오탐·누락과 보존 판단을 확인. 허용 수준은 사용자 성공 기준과 연결 | 자동화 수준·유사성 방법 확정 및 원본 변경 연결 전에 |
| 입력 규모·지원 형식·사용성 | 규모·드라이브·JPEG/PNG/HEIC 등 실제 필요를 먼저 확인. 초기/증분 스캔·후보 생성 시간과 정보 식별·확대 검토 행동을 관찰 | 속도·지원·레이아웃 확정 전에. 현재 허용 시간이나 사진 수 목표를 임의 생성하지 않음 |

### 완료 조건 점검

| 기준 | 현재 근거와 판정 |
|---|---|
| Discovery 1. 접근법 비교 | 자료 범위에서 충족: 세 관리 방식·검토 전용·유지 대안의 차이와 선택 조건을 제시. 실제 시장의 충분한 탐색은 미완료 |
| Discovery 2. 적합한 직접 근거 | 부분 충족: 원문 본문·짧은 코드 구조는 직접 확인. 시각·상호작용·동작·전체 구현·실제 제품 사실은 미확인 |
| Discovery 3. 적용 가능성 | 부분 충족: 가져올 요소·수정·비용·실패 조건을 연결. 코드 라이선스·Windows 적용·정확성은 미확인 |
| Discovery 4. 결정 영향 | 충족한 범위: P1~P3과 후보 유지·제외 이유를 제시할 수 있음. 사용자 합의는 대기이며 제품 선택으로 승격하지 않음 |
| Discovery 5. 타당한 종료 | 충분한 탐색 종료는 불충족. 제공된 모든 관련 본문을 검토해 같은 파일을 다시 읽을 효용은 낮지만 실제 사례·공개 구현·화면의 미탐색 공백은 선택을 바꿀 수 있음. 환경 제한에 따른 현재 자료 검토 종료와 Research 완료를 구분 |
| Web Evidence closure | 출처·버전·원문 위치·반대 자료·공백·중복 원천을 추적 가능하게 기록. 실제 웹 접근은 미수행이며 미확인 고영향 주장은 위 후속 행동에 연결. 원래 외부 탐색 전체의 closure로 처리하지 않음 |
| Research closure | 미통과. 전체 Verdict 보류, 사용자 합의 대기, 실제 탐색·검증 공백 존재. 상태와 index는 작성 중 유지 |

Idea에서 바꿀 내용은 위 미승인 제안과 관련 Research 참조뿐이다. 확정된 사용자 요구·제약·제외는 유지한다. Execution은 아직 만들지 않으며 Phase·Build 승인을 받았다고 기록하지 않는다. 다음 질문은 현재 대기 중인 T1~T4 Topology 확인 하나다. 확인 이후에는 파일 변경 권한과 원하는 정리 결과처럼 되돌리기 어려운 결정을 우선한다.
