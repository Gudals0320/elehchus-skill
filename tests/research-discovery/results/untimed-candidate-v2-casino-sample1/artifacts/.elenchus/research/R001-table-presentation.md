# Research R001: 테이블 화면과 조작 방식

- 상태: 작성 중
- 기준: [Idea](../idea.md)의 사용자 결정·제외·미확인
- 확인 날짜: 2026-09-07
- 영향: Phase 후보

## 질문·목적·범위

탐색·벤치마킹 질문: 테이블 주변 공간, 카드·숫자 가독성, 애니메이션에 가까운 3D 느낌을 어떤 화면·조작 방식으로 함께 다룰 수 있는가?

- 입력: 합의된 싱글 카지노 범위와 제공된 합성 문서. 후보를 읽기 전에 사용자 조건을 기준으로 삼았다.
- 출력: 직접 유사·인접·반대 사례 비교, 가져올 요소·제약·비용, 사용자에게 남길 선택과 근거의 한계.
- 사용자 경험: Windows PC의 데스크톱 Chrome에서 테이블 게임을 혼자 조작한다. 자세한 제약·제외는 Idea를 따른다.
- 성공 조건: 화면과 조작의 차이 및 우리 조건의 교환 관계를 출처로 추적할 수 있다. 실제 읽기 쉬움·취향 적합성·애니메이션 체감은 시각 관찰이 필요하며 현재 수치 기준은 미정이다.
- 실패 조건: 문서 설명을 직접 관찰로 바꾸거나 취향·새 기능·기술을 대신 확정하는 것.
- 저장소 기준선: Idea의 확인된 사실 참조. 기존 구현에 의한 카메라·UI·엔진 제약을 확인하지 못했다.
- 기술 분류: Windows와 데스크톱 Chrome은 사용자 환경, 6덱·싱글 제로 등은 게임 제약이다. 지정 엔진·라이브러리 후보는 없다.
- 미해결: 카메라·구도·색·재질, 텍스트/버튼과 3D의 역할, 직접 클릭·드래그 등 조작 방식과 진행 연출.

| 증거원 | 상태 | 이유 | 바뀔 수 있는 결정 |
|---|---|---|---|
| Repository | 필요·확인 | 현재 의도와 미구현 기준선 | 기존 구조 제약 여부 |
| Independent exploration | 생략 | 이번 실행에서는 subagent를 사용하지 않는다는 프로젝트 조건. 메인이 사례와 구현 질문을 분리해 조사하며 독립 탐색으로 계산하지 않음 | 독립 검토 공백 |
| External evidence | 필요·로컬 대체 | 제공된 `evidence/` 본문으로 범주·사례·반대 근거를 탐색. 실제 외부 웹 조사와 구분 | 화면·조작 후보의 차이 |
| Browser Evidence | 생략 | 로그인·개인화 관찰이 필요한 질문이 아니며 연결도 제공되지 않음 | 없음 |
| Lab | 생략 | 이번 비교에 쓸 화면·실행 자료가 없고 취향을 검증할 실험을 아직 구성하지 않음 | 실제 가독성·체감은 미확인 |

공개 시각 관찰은 필요하지만 자료 묶음에 없고 네트워크·브라우저 경로는 이번 실행에서 제공되지 않는다. `.example` 접근·설치·권한 확대는 시도하지 않는다. 이는 HTTP 실패를 직접 확인한 기록이 아니다. 먼저 관련 문서 본문을 읽고, 발견한 유력 후보와 반대·실패 근거를 같은 묶음에서 다시 확인한다. 화면·움직임 판단에 필요한 공백이 남으면 결론 보류로 유지한다.

## 발견 후 검증할 주장과 자료 경로

복수 후보·실패 경험·출처 중복이 있으므로 전체 Evidence 의미를 사용한다. 외부 검색 대신 01~06 본문에서 카메라·HTML·perspective·가림·시간·사용성 관련 문구를 탐색하고, 관련 개발기와 인접 사례를 따라간다. 07~08은 별개의 구현 질문인 R002에서 검증한다.

| 주장 | 결정 영향·필요한 근거 | 적용·최신성 기준 | 반증·남은 공백 |
|---|---|---|---|
| C1. 3D 테이블과 별도 텍스트/버튼의 역할 분담이 문서상 사례로 존재한다 | UI 역할 선택. 제품 안내와 제작기·인접 원문 | Tablehaven 0.8과 Pileplay 해당 제작기 범위 | 글과 물체가 가리거나 숫자가 작으면 우리 가독성 결론은 성립하지 않음. 실제 화면 필요 |
| C2. 평면 표현은 제작을 줄일 수 있지만 원하는 입체 표현을 제한한다 | 축소 대안 선택. 사용자 설명과 제작 부담의 비교 근거 | Flatfelt 2.1의 설명만 사용 | 동일 조건 비교가 없으면 절감량·우열을 확정하지 않음 |
| C3. 공간 이동형의 추가 제작·가림 문제가 현재 범위에 불필요한 부담이다 | 제외 유지. 원 제작자의 실패 경험과 사용자 제외 조건 | Orbitroom 해당 제작기의 경험 | 단일 테이블에도 같은 비용이 든다는 일반화는 금지 |
| C4. 문서의 시간 수치·재게시·제작자 평가는 우리 UX 우수성을 검증하지 않는다 | 연출 속도·취향 확정 방지. 수치 정의와 원천 고지 | 각 명시 버전·작성일에 한정 | 실제 독립 사용성 관찰이나 우리 화면 측정이 있어야 판단을 강화할 수 있음 |

다음 확인은 같은 원문 재인용, 제작 시간·사용성 비교의 유무, 없어진 시각 자료의 대체본 존재 여부다. 묶음 밖은 현재 접근 경로가 아니므로 추가 공개 자료를 실제 조회했다고 기록하지 않는다.

## 비교와 근거

아래 이름은 모두 **가상 제품**이다. 2026-09-07 메인이 로컬 본문을 직접 읽었다. 관찰 수준은 전부 **자료의 설명**이며, 화면·영상·실제 조작을 직접 관찰한 사례는 없다. 적용·추천 문장은 **추론/에이전트 제안**이다.

위 주소는 원천 식별자이며 방문한 URL이 아니다. 원자료의 문구가 직접 통제하는 버전별 설정은 해당 본문으로 확인했고, 이를 일반적인 최적 UX로 확장하지 않았다. 서로 다른 가상 작성자의 공통 설명도 실제 제품의 독립 실증 자료로 바꾸지 않는다.

접근 결과: 관련 01~06과 README의 로컬 본문을 확보했다. S1의 `/media/table-wide.png`, `/media/round.webm`은 문서가 미제공으로 명시하고, S5 영상·S6 이미지도 묶음에 없다. 로컬 파일 목록과 README에서 다른 이미지·영상·실행 데모가 없음을 확인했다. 같은 주장에 대한 로컬 대체로 S4·S6 설명을 비교했지만 시각 증거를 대신하지 못한다. 외부 API·feed·archive·브라우저·로그인 경로는 네트워크/브라우저 미제공 및 예약 도메인이라는 terminal reason으로 시도하지 않았다. HTTP 404나 접속 실패를 측정한 것은 아니다. 추가 자료가 제공되면 재개할 수 있다.

| C3 | S5의 이동·멀티·가림·추가 작업과 사용자 제외 조건 | 현재 범위 부적합 확인 | 이동·캐릭터·서버 기능 제외 유지. 자료의 기간을 우리 견적으로 사용하지 않음 |
| C4 | S1의 약 9초, S4의 180ms, S3의 원천 고지, S6의 사용성 실험 부재 | 우리 제품의 최적 속도·사용성이라는 해석은 근거 부족 | 약 9초는 베팅부터 다음 베팅까지, 180ms는 카드 한 장으로 분모도 다름. 속도 우열 비교·기본값 채택 금지 |

아직 비교하지 못한 관련 범주는 **숫자·버튼까지 3D 장면 안에서 조작하는 테이블 방식**과 **실제 애니메이션풍 미술/카메라 대안**이다. 대응 사례가 없어 제외나 열등 판정을 하지 않는다. 모바일 최적화·공유·통계·로그인 사례는 이번 결정에 필요하지 않아 탐색을 늘리지 않았다.

## 결론과 다음 행동

- **판정: 결론 보류.** 문서에 설명된 접근법의 비교 결과는 제시할 수 있으나, 요청된 화면·조작 사례의 직접 관찰과 디자인 선택은 완료하지 못했다. 제공 자료를 모두 읽었다는 사실로 전체 디자인 탐색을 완료 처리하지 않는다.
- **근거:** S1의 직접 유사 조건과 S4의 축소 대안, S6의 주변 공간·행동 띠, S5의 불필요한 공간 제작/가림이라는 차이가 확인된다.
- **반대 근거:** 숫자·작은 물체가 실제로 읽히는 화면이 없고, S6는 다중 베팅 사례가 아니다. 비용·시간·생동감은 비교 실측·선호도 결과가 아니다.
- **미승인 제안 P1 — 비교 우선 후보:** 별도 텍스트/버튼과 3D 테이블을 결합하는 구성을 다음 화면 비교에 포함한다. 출처: 에이전트 제안, 근거 S1·S2·S6. 원계획 대비 새 기능 추가 없이 표현 역할을 구체화하는 선택이다. 공간과 정보 배치를 따로 조정할 수 있지만 두 표현 영역의 배치·상태 연동 부담이 있다. 최종 채택·고정 사선·2D 베팅 패널 확정이 아니다.
- **동등한 축소 대안 P2:** S4처럼 이미지와 약한 원근을 사용하는 구성을 남긴다. 출처: 에이전트 제안. 원계획 대비 입체 재질·카메라 표현을 줄일 수 있으며 모델/조명 작업이 줄 가능성이 있지만 원하는 3D 느낌도 줄 수 있다. 사용자 승인 전 범위를 축소하지 않는다. 단순화와 3D 요구의 교환 관계를 고려하면 무조건 권장할 근거는 없다.
- **제외 유지:** 이동형 카지노는 사용자 결정에 따라 현재 범위에서 제외한다. 새로 제외 승인을 받을 필요는 없다.
- **취향 추천:** 카메라 각도·구도·색·재질의 권장안 없음. 판단 가능한 시각 근거가 없다. 주변 공간을 얼마나 보여 줄지, 텍스트/버튼과 3D의 역할, 클릭/드래그, 결과 표시·연출 길이·건너뛰기도 미정이며 사례에 있다는 이유로 기능을 추가하지 않는다.
- **한계·신뢰도:** 문서 내용과 버전·원천 구분은 높음. 우리 조건의 구조적 적합성 추론은 중간. 실제 시각 품질·취향·사용성은 낮음/미확인. 실제 제품 사실에 대한 결론은 내리지 않았다.
- **Idea 영향:** 사용자 확정 제약은 유지한다. P1·P2를 미승인 대안으로 연결하고 웹 표현의 명료도·성공 기준을 올리지 않는다.
- **Execution 영향:** Phase 후보에만 연결한다. 이번에는 Execution 문서·Phase/Build 번호를 만들지 않는다. 다음에는 화면·동작 근거를 확보해 비교하고 사용자가 표현 역할을 정한 뒤 관련 제작 범위를 구체화해야 한다.

### 완료 기준 점검

| Discovery 기준 | 결과·근거 |
|---|---|
| 접근법 비교 | 문서 범위에서 충족: 3D+HTML, 이미지/CSS 축소, 인접 보드게임, 이동형 반대 사례의 차이 제시 |
| 적합한 직접 근거 | 미충족: 본문은 직접 확인했지만 화면·움직임 판단에 필요한 직접 시각 근거 없음 |
| 적용 가능성 | 부분 충족: 가져올 요소·별도 작업·제한을 구분했으나 세 게임 화면의 실제 검증 없음 |
| 결정 영향 | 결과와 미승인 제안·제외 유지·미정 선택을 제시. 사용자 결론 확인은 대기 |
| 타당한 종료 | 전체 탐색은 미충족: 3D 안의 조작 및 애니메이션풍 화면 등 선택을 바꿀 공백이 남음. 같은 문서 반복 읽기의 효용만 낮으며 추가 시각 자료의 효용은 높음 |

Web Evidence 추적은 주장·버전·원문·독립성·실패/미시도 경로·반대 근거까지 기록했으나, 시각 근거 공백 때문에 전체 closure는 통과하지 않았다. 후속 공개 시각 탐색 또는 사용자와의 연기 범위 확인이 필요하다. 이는 아직 실행하지 않은 검증을 Build에 등록해 완료로 바꾸는 처리가 아니다.

현재 문서 상태는 작성 중이다. 사용자가 문서 비교 결과와 보류 범위를 확인하기 전에는 확정으로 바꾸지 않는다.
