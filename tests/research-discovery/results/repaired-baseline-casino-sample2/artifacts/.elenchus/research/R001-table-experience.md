## Repository 기준선

관찰: `AGENTS.md`, `skill/SKILL.md`, Idea·Research·Web Evidence 단계 지침, 기존 `idea.md`, `evidence/README.md` 및 01~08 본문을 읽었다. 기존 계획은 Topology 확인 전 초안이었으며 최신 사용자 응답으로 범위 확인을 반영했다. 기존 Research index·R 파일은 파일 목록에서 발견되지 않아 R001·R002를 부여했다. 상세 화면 주장은 아래 S01·S03~S06을 사용하고 제작 구조는 R002에 둔다.

해석: 현재 질문은 기존 제품 코드의 수정이나 성능 감사가 아니다. 관련 제품 코드·설정·테스트 탐색을 생략했으며, 코드가 없거나 특정 스택이 설치됐다고 결론 내리지 않는다. 인증정보·사용자 설정은 읽지 않았다. 사용자가 Research를 명시적으로 요청했으므로 Idea의 미정 취향을 확정하는 절차로 조사 진입을 막지 않았다. Idea closure는 미완료다.

## 사용자 기술 언급 분류

Windows PC는 현재 사용 환경, 데스크톱 Chrome은 우선 지원 환경이다. 터미널 → 애니메이션 웹앱 순서는 필수 제약이다. 3D 느낌은 경험 요구이며 특정 엔진 선택이 아니다. 필수 라이브러리·엔진 언급은 없다. 자료에 등장하는 제품·기술은 모두 사례/후보로만 다룬다.

## 사례 비교: 화면·입력·피드백과 전이 한계

아래는 모두 **문서 묘사**다. 실제 화면을 보거나 플레이하지 않았다.

| 사례·역할 | 화면·시각 설명 | 입력·라운드 피드백 | 우리 조건에 참고할 부분 | 전이할 수 없는 점·부담 |
|---|---|---|---|---|

## Verdict와 Web closure

- 판정: **결론 가능 — 문서에 근거한 사례 차이와 현재 범위 적합성 비교에 한정.** 실제 외관·조작감의 채택 판단은 결론 보류다.
- 근거: S01은 현재 사용 맥락에 가까운 분리형 화면, S04는 작은 표현 대안, S06은 주변 공간·식별성의 인접 사례를 설명한다.
- 반대 근거: S05의 가림·작업 범위, S04의 입체 표현 한계, S06의 입력 밀도 차이, S01·S03의 원천 중복.
- 채택·제외: 비교 출발점 권고는 위 표와 같다. 실제 카메라·재질·버튼 역할을 채택한 것이 아니다. 자료가 기술한 건너뛰기·확대·접근성 기능은 새 요구로 추가하지 않는다.
- 한계: 전부 합성 문서. 스크린샷·영상·데모·직접 사용·사용성 시험 없음. 실제 제품의 우열, 구체적 제작비·기간, 사용자 PC 성능을 입증하지 못한다.
- 신뢰도: **중간** — 문서상 차이·범위 부적합 판단에 한정. 실제 시각 취향·가독성·조작감 적합성은 **낮음**.
- Web closure: 전체 Claim map·계획·접근 기록·본문/버전 대조·반대 자료·중복·공백 처리를 기록했다. 네트워크/Browser 조사를 완료했다고 주장하지 않는다. C4를 남겨 둔 시각 채택의 closure는 보류하며, 현재 묶음에서 문서 비교는 종료 가능하다. 사용자에게 제시할 결론·보류 범위의 확인은 아직 대기 중이다.

## Idea와 Execution에 미치는 영향

Idea에는 사용자가 확정한 경험·제약을 보존하고 이 연구 링크만 연결한다. 문서상의 권고는 사용자 결정으로 옮기지 않는다. 최종 카메라·구도·색·재질·3D/UI 역할·속도·건너뛰기·결과 유지 방식은 미정이다.

Execution은 작성하지 않는다. 다음 대화에서 웹 표현 Phase 후보를 논의할 때, 실제 화면 자료가 있으면 사용자와 주변 공간/카드·숫자 가독성을 비교할 필요가 있다. 룰렛 베팅 영역과 블랙잭 스플릿처럼 밀도가 높은 상태도 비교 대상이라는 **검토 제안**을 남긴다. Build 번호·상세 구현 순서·수치 합격선은 합의하지 않았다.
