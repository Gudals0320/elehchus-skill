# Idea: 개인용 Windows 로컬 사진 정리 도구

- 상태: 작성 중
- 시작 요청: Windows PC에 흩어진 사진을 여러 폴더에서 모아 보고 날짜나 비슷한 사진을 기준으로 정리하는 개인용 로컬 도구의 구현 전 계획을 세운다. 폴더 직접 관리와 별도 사진 보관함 중 어느 방식이 나을지 비교하고, 기존 제품과 공개 구현에서 폭넓게 참고할 방식 및 파일 안전성을 조사한다. digiKam 언급은 채택이나 구조 모방 요구가 아니다.

## Topology

사용자는 제시한 내용 중 여러 로컬 폴더의 사진을 보고 정리한다는 원래 범위에 동의했다. 아래 네 영역을 그 범위를 다루는 조사 구분으로 유지한다. 활성은 검토 대상이라는 뜻이며 제품 행동·화면·구조의 확정을 뜻하지 않는다.

| ID | 상위 구성요소 | 상태 | 초기 의도와 근거 |
|---|---|---|---|
| T1 | 사진 위치 선택과 모아 보기 | 활성 | 두 드라이브와 외장 SSD에 있는 JPEG·PNG·HEIC 약 5만 장을 여러 폴더에서 모아 본다. 인터넷 없이 검색하고 SSD 분리 시 이전에 본 정보도 찾는다. 출처: 사용자 요청. |
| T2 | 날짜·유사 사진 기준 정리 | 활성 | 날짜로 훑고 사진을 크게 비교한다. 촬영일 누락·오류가 있다. 중복은 삭제 전 나란히 비교해 직접 선택하며 시각적 유사성으로 자동 삭제하지 않는다. 날짜 정책과 정리 행동의 상세 범위는 미정. 출처: 사용자 요청. |
| T3 | 저장·관리 방식 | 활성 | 폴더 직접 관리·보관함 및 조사에서 찾은 대안을 비교한다. 폴더 화면·타임라인·보관함 구조의 선호와 제품·엔진·DB는 미정. 출처: 사용자 요청. |

산출물은 구현 전 계획이며, 사용 표면은 혼자 쓰는 Windows 로컬 도구다. 외부 서비스 연동은 요청에 없으며 채택하지 않았다. 기존 제품·공개 구현 조사는 위 구성요소의 판단 근거를 확보하는 활동이다.

## 미확인·충돌

- 사진 정리에 필요한 실제 파일 변경 범위: 이동 채택 여부, 삭제 적용·휴지통·복구 기간, 취소·재시도·부분 성공의 경험. 조사 결론은 사용자 선택을 대체하지 않는다.
- 분리 SSD에서 조회할 정보 범위와 미리보기 보관량·품질·용량 부담, 화면 선호와 관리 방식. 원본 없는 큰 비교는 별도 보관 정책 없이 보장하지 않는다.
- 날짜의 우선순위·누락·오류·시간대·사용자 보정 처리, 시각적 유사 후보의 허용 누락과 검토량.
- 지원하지 못한 HEIC·깨진 파일·스캔 중단·빈 결과의 표시, 5만 장에서 수용할 지연·메모리·캐시 규모. 사용자는 사진 수·형식·장치 조건을 답했으므로 다시 질문하지 않는다.
- 실제 제품·공개 구현의 폭넓은 비교는 현재 자료와 연결 환경만으로 충족할 수 없다. 합성 문서로 비교 가능한 설계 관점과 외부 검증이 필요한 주장을 구분해야 한다.
- 서로 모순되는 확정 결정은 아직 없다.
- 다음 대화에서 우선할 사용자 결정 질문: “외장 SSD가 빠져 있을 때 이전에 본 사진은 날짜·경로 같은 정보만 확인하면 충분한가요, 저장된 미리보기로 크게 비교할 수 있어야 하나요?” 보관량과 관리 방식 선택에 영향을 준다. 이번 응답에서는 Research 결과를 제시하고 답을 추정하지 않는다.
