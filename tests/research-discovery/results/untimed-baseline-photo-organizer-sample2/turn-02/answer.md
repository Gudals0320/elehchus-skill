Research 결론은 **원본을 제자리에 두고 사진 정보와 필요한 미리보기를 별도로 저장하는 로컬 참조 카탈로그를 우선 검토하자**는 제안입니다. 외장 SSD가 빠져도 이전 정보를 찾으려는 요구와 잘 맞습니다. 특정 제품·DB·화면 구성의 확정은 아닙니다.

검토 근거는 모두 **제공된 가상 제품의 합성 문서**입니다.

| 관리 방식 | 얻는 것 | 주요 부담·한계 |
|---|---|---|
| 폴더 직접 탐색 — Pathframe 사례 | 실제 폴더와 대응하는 탐색, 이동 전 경로 목록 | 설명된 방식에서는 분리된 SSD 사진이 검색에서도 빠짐 |
| 복사 보관함 — Albumvault 사례 | 가져온 복사본을 원장치 없이 열람 | 원본 복사본과 미리보기만큼 공간 추가, 기존 폴더 정리는 별도 |
| 참조 카탈로그 — Indexlens 2.8 패턴 | 원본 이동 없이 분리 장치의 저장 정보 검색 | 정보 갱신·경로 재연결·미리보기 보관 필요 |

버전 차이는 결정적입니다. **Indexlens 3.0은 계정·온라인 검색과 썸네일·메타데이터 동기화를 요구**하고, 2.x는 보안 패치가 종료됐다는 기록이 있습니다. 따라서 참조 방식의 아이디어를 참고하되 해당 제품 채택은 추천하지 않습니다. Photo Digest 소개도 구판 문서의 재게시여서 독립 검증으로 세지 않았습니다. [관리 방식 비교 근거](<fixture>/.elenchus/research/R001-collection-access.md)

제작 방법에서는 다음을 참고할 만합니다.

- **날짜:** 원문 값·출처·시간대 유무를 보존하고 불확실성을 표시합니다. 촬영일 우선순위와 보정 정책은 미정으로 유지합니다. [날짜 조사](<fixture>/.elenchus/research/R002-date-interpretation.md)
- **비교:** 바이트가 같은 파일과 시각적으로 닮은 후보를 구분합니다. Pairboard의 나란히 비교·동기 확대·해상도·용량·경로 표시는 참고 후보입니다. 유사 점수는 삭제 판단을 대신하지 않습니다. [후보 비교 조사](<fixture>/.elenchus/research/R003-candidate-review.md)
- **파일 변경:** 이동을 채택한다면 목록 검토 → 적용 시 재검증 → 복사·확인·원본 제거의 단계 기록을 검토합니다. 작업 기록이나 같은 드라이브의 빠른 이름 변경만으로 완전 복구를 보장할 수는 없습니다. [파일 안전성 조사](<fixture>/.elenchus/research/R004-file-change-safety.md)

탐색·비교부터 만들고 파일 적용은 연기하는 작은 대안도 남겼습니다. 그 경우 앱 안에서 실제 폴더 정리는 끝나지 않습니다.

**5만 장 성능, HEIC 지원, 유사 후보의 누락률, 중단 후 복구는 미검증**입니다. 실제 제품·공개 저장소·화면을 관찰한 조사로 보고하지 않았으며, 신규 기능·비용·엔진은 확정하지 않았습니다. 사용자 조건과 제외를 문서에 반영했고 전체 실행 계획 합의는 다음으로 남겼습니다.
