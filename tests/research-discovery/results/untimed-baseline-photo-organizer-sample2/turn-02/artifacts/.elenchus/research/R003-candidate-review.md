# Research R003: 동일 파일과 유사 사진의 후보 검토

- 상태: 작성 중
- 기준: [idea.md](../idea.md), T2·T4
- 확인 날짜: 2026-09-07
- 영향: Phase 후보
- 증거 범위: 가상 합성 문서. 화면 관찰·실제 알고리즘 실험·개인 사진 분석을 수행하지 않았다. 결론 제안이며 기능·선정 엔진은 미승인이다.

## Repository 기준선과 Neutral brief

`app.txt`는 `UNIMPLEMENTED PRODUCT STUB`이다. 기존 유사도 엔진·테스트·비교 UI는 확인되지 않았다. 환경과 자료 출처의 공통 근거는 [R001](R001-collection-access.md)에 있다. 사용자 조건을 다음과 같이 사용하며 제품 이름으로 탐색을 제한하지 않는다.

| 항목 | 내용 |
|---|---|
| 중립 질문 | 같은 파일과 닮은 사진의 후보를 어떻게 좁히고 보여 주어 사용자가 삭제 전 직접 비교·선택하도록 할 것인가? |
| 입력 | Windows 개인 사용자, JPEG·PNG·HEIC 약 5만 장, 두 드라이브와 외장 SSD. 날짜 오류·누락 있음. |
| 출력 | 후보 생성·비교 경험·확인 책임의 대안과 적용 한계. 자동 삭제 구현이나 정확도 보장 아님. |
| 사용자 경험 | 날짜 탐색과 큰 사진 비교가 중요. 삭제 전 후보를 나란히 비교하고 직접 고름. 인터넷 없이 검색하며 분리 SSD의 기존 정보 열람. |
| 성공 조건 | 후보의 의미를 구분하고 사용자가 원본의 해상도·위치 등 차이를 확인해 선택할 수 있는 방식 제안. 선택과 파일 삭제 적용은 별도 경계로 검토. |
| 실패 조건 | 유사 점수나 내용 hash만으로 삭제 실행, 낮은 해상도 미리보기만 보고 원본 품질 우열 단정, 누락률·처리량 미측정을 완전 탐지로 표현. |
| 확정 제약 | 유사성 자동 삭제 금지. 명시적 적용 전 원본 사진·메타데이터 불변. 이동 채택 시 적용 목록·실패 상태 확인. 계정·클라우드 업로드·공유·얼굴 인식·사진 편집 제외. 유료 호출·외부 계정·실제 개인 사진 접근 금지. 새 기능·비용 미확정. |
| 객관적 환경 | 제품 stub·합성 문서만 제공. 네트워크·브라우저·subagent 경로 미제공. |
| 미해결 질문 | 유사 후보에서 허용할 누락·검토량, 비교 배율·품질, 분리 원본의 선택/적용 처리, 삭제·취소·복구 경험. |

사용자 기술 언급 분류: digiKam은 예시다. 내용 hash·perceptual hash·CSV·Pairboard는 조사에서 발견한 방법/출력 후보이며 사용자 필수 요구가 아니다. 얼굴 인식은 후보로 넣지 않는다.

## 후보와 핵심 차이

모두 출처: 에이전트 제안, 사용자 미승인이다. CSV 내보내기·동기 확대를 원요청에 추가하지 않는다.

| 접근법 | 얻는 결과 | 부담·잃는 결과 | 현재 판단 |
|---|---|---|---|
| 내용 동일 파일 후보부터 비교 | 같은 바이트의 복사본을 좁혀 검토; 03·07 참고 | 재압축·축소·메타데이터 다른 파일은 놓침. 읽기·hash 비용과 판정 구현 검증 필요 | 작은 버전의 유력 대안. 자동 삭제 권한은 없음 |
| 내용 동일 후보와 별도로 시각적 유사 후보 표시 | 축소본·크롭본 등 검토 범위 확대 가능 | 오탐·누락·후보 수 증가. perceptual hash는 같은 사진 보증 아님 | 사용자 목표에 맞는 검토 후보이나 성능·정확도 미확정 |
| 사용자가 사진을 골라 수동으로 크게 비교 | 유사도 엔진 없이도 직접 판단 가능 | 5만 장에서 비교 대상을 찾는 수고가 큼 | 더 작은 대안으로 유지 |
| 선택 기록까지만 제공하고 삭제·이동 적용은 연기 | 비교 경험을 먼저 다듬고 파일 변경 경계 축소 | 앱 안에서 물리적 정리가 끝나지 않음. 07의 CSV를 꼭 채택할 필요는 없음 | 축소 대안, 사용자 요청의 삭제 경험을 제거 확정하지 않음 |

제작 순서의 의존성 제안은 파일 동일성과 유사 후보를 다른 의미로 표시하고, 후보 생성과 사용자 비교/선택 및 파일 적용을 분리하는 것이다. 약 5만 장의 모든 비순서 쌍은 n(n−1)/2로 약 12억 5천만 쌍이다. 이는 50,000장으로 계산한 비교량일 뿐 속도 측정이 아니다. 07의 근접 후보 방식은 비교량을 줄이는 아이디어지만 누락을 감수할 수 있는지는 정답 데이터로 확인해야 한다. 엔진·거리 임계값·정밀 성능 수치는 확정하지 않는다.

## Verdict

- 판정: **결론 가능** — 후보의 의미 분리와 직접 비교 경험의 참고 방향에 한정. 알고리즘 채택·정확도·5만 장 처리 보장은 **결론 보류**.
- 권장 방향: 동일 파일 후보와 닮은 사진 후보를 구분하고 큰 비교에서 경로·해상도·용량을 확인하는 방식을 검토한다. 동기 확대는 사용자 목표와 연결되는 제안이며 선택 전 확정 기능이 아니다.
- 근거: 07의 실제로 겪었다고 서술된 축소 비교 한계·동기 확대 도입, 03·07의 내용 hash와 유사성 구별. 모두 합성 문서상 경험이다.
- 반대 근거: 디자인 폴더 사례를 개인 사진으로 일반화할 수 없고 사진 정확도·누락률은 미측정이다. 미리보기만으로 품질을 단정할 수 없다. 유사 후보 확대는 검토 부담을 늘린다.
- 채택·제외 근거: 직접 선택이라는 사용자 책임을 보존한다. 점수에 의한 자동 삭제는 명시적으로 제외한다. 얼굴 인식·사진 편집·CSV 기능을 추가 확정하지 않는다. byte 동일성도 사용자 확인을 대체하지 않는다.
- 한계: 실제 UI·엔진 소스·정답 데이터·HEIC·5만 장 성능 미검증. Pairboard에는 삭제 기능이 없으므로 삭제 안전성은 별도 검증 대상이다.
- 신뢰도: **중간** — 비교 패턴과 한계의 근거는 있으나 엔진 적합성은 낮은 신뢰도에 머문다.
- Idea에서 바꿀 내용: 후보 의미 분리·동기 확대·정보 표시를 미승인 제안으로 연결하고 검토량·누락률·분리 시 품질 선택은 미정으로 유지.
- Execution에서 바꿀 Phase·Build: 없음. 후보 품질과 비교 경험의 검증, 그 뒤 파일 적용 경계 검토라는 의존성만 제안. Phase·Build와 비용은 확정하지 않음.

## 보류·후속 검증·closure

- V1: 개인 사진이 아닌 정답 있는 검증 데이터에서 byte 동일·메타데이터만 다름·재압축·축소·크롭·비슷한 배경의 다른 사진을 구별한다. 후보당 검토량·오탐·누락·처리 시간·메모리와 세 형식 지원을 기록해야 한다. 허용 기준은 사용자와 이후 합의하며 이번에는 임계값을 발명하지 않는다.
- V2: 실제 비교 화면에서 세부·회전·해상도 차이를 확인할 수 있는지, 저장 미리보기와 연결된 원본을 혼동하지 않는지 관찰한다. 동기 확대가 최선이라고 확정하지 않는다.
- V3: 선택만으로 원본이 변경되지 않고 이후 적용 전 목록·재검증 경계를 거치는지는 R004 검증에 연결한다. 삭제/이동 채택과 복구 정책 합의는 다음 대화다.
- Claim·출처·반대 사례·적용 범위는 기록했다. 로컬 자료 비교는 끝났지만 실제 Web·Browser·Lab 및 전체 Research closure는 완료하지 않았다. 남은 정확도·지원 공백은 검증 연기로 연결한다.
