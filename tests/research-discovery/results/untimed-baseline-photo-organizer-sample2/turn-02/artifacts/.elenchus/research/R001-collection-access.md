## Repository 기준선

관련 파일 목록과 `app.txt`를 읽었다. 본문은 `UNIMPLEMENTED PRODUCT STUB`이며 기존 사진 앱 코드·테스트·선택된 DB의 근거는 확인되지 않았다. `.elenchus/idea.md`는 작성 중이다. 사용자가 이번에 Research 결론까지 요청했으므로 확인된 조건만 intake로 쓰고 남은 UX 선택을 닫지 않는다. 제품·설정·인증정보는 조사하거나 변경하지 않았다.

`evidence/README.md`에 따르면 모든 제품·조직·측정값·코드는 가상 합성 자료다. 아래의 “확인”은 해당 문서 내용의 확인이다. 실제 제품·실제 공개 저장소의 검증을 뜻하지 않는다.

## 사용자 기술 언급 분류

Windows와 사진 형식·규모·장치는 현재 환경 및 지원 목표다. digiKam은 **예시**이며 neutral brief의 후보 비교 조건에서 제외했다. 폴더 직접 관리와 별도 보관함은 **비교 후보**다. 특정 제품·엔진·DB는 필수 제약이 아니다. 아래 SQLite·디코더 언급은 합성 문서의 구현 사례이며 사용자 요구가 아니다.

## 독립 solution explorer

사용자는 조사와 역할 분담을 허용했지만 지원되지 않는 subagent 경로를 호출하지 않았다. 별도의 승인된 전달 brief나 독립 조사 결과는 없다. 위 neutral brief를 기준으로 메인 세션이 근거·반례·더 작은 대안·경계와 의존성을 검토했다. 이를 독립 출처나 독립 에이전트 결과로 계산하지 않는다.

1. 01·03·04에서 직접 탐색·복사·참조 방식의 차이를 확보했다. 분리 SSD 정보 열람 때문에 참조 방식을 유력하게 보되 제품 자체의 현재 적합성은 남겼다.
2. 05는 04 재게시이므로 지지 출처 수를 늘리지 않는다. 판정 영향이 큰 버전 공백에 대해 06을 확인했고 Indexlens 제품 채택 후보를 제외하는 방향으로 수정했다. 참조 방식의 설계 가치는 별개다.
3. 02·07·08로 파일 안전·큰 비교·형식 한계를 보완했다. 텍스트가 실제 관찰·성능 검증이 되는 것은 아니다.
4. 자료 묶음의 관련 원문을 모두 확인했다. 같은 원문 재독으로 C3·C4는 해결되지 않는다. 추가 실제 문서·코드·검증 자료는 결론을 바꿀 수 있으나 제공되지 않아 후속 검증으로 남긴다. “더 찾아도 바뀌지 않음”으로 닫지 않는다.

## 후보와 핵심 차이

모두 출처: 에이전트 제안인 비교이며 기능·구조의 사용자 승인이 아니다.

| 접근법·참고 사례 | 사용자가 얻는 것 | 부담·실패·조건 | 현재 판단 |
|---|---|---|---|
| 폴더 직접 탐색: Pathframe 1.7 | 실제 폴더와 화면이 대응, 이동 전 경로 목록 | 분리 장치는 검색에서도 사라짐. 폴더 sidecar 기록은 적용 전 불변 요구와 저장 시점 조정 필요 | 폴더 탐색·목록 검토는 참고. 설명된 구조 그대로는 SSD 요구 미충족 |
| 복사 보관함: Albumvault 4.0 | 가져온 복사본으로 원장치 없이 열람, 로컬 무계정 설명 | 원본 복사본+미리보기 공간, 기존 폴더 정리는 별개. 참조 모드 없음 | 대안 유지. 파일 크기 합계가 없어 비용·용량 산출이나 채택 불가 |
| 원본 위치를 유지하는 참조 카탈로그: Indexlens 2.8의 패턴 | 별도 로컬 기록으로 분리 장치 정보 검색, 원본 이동 불필요 | 캐시 저장·갱신·재연결 필요, 저장 미리보기 품질 밖의 원본 열람은 불가 | 우선 검토 방향. 특정 제품·SQLite 채택과 분리 |
| 작은 버전: 참조 탐색·비교만, 파일 적용 기능 연기 | 날짜 탐색·큰 비교와 분리 정보 열람에 집중, 파일 변경 실패 범위 감소 | 앱 안에서 물리적 정리는 완료되지 않음. 보관 정책·HEIC 검증은 여전히 필요 | 같은 지위의 축소 대안, 사용자 미승인 |
| 새로 만들지 않고 기존 도구 조합 사용 | 자체 개발·유지 부담 감소 가능 | 실제 도구의 오프라인·데이터 처리·형식·안전 검증과 작업 전환 부담 | 현재는 실제 제품 근거 없어 채택 결론 보류 |

폴더 화면·날짜 타임라인·큰 비교 화면은 원본을 복사하는지 참조하는지와 별개로 설계할 수 있다는 것은 에이전트의 구조적 해석이다. 사용자에게 세 가지를 반드시 하나만 고르게 하지 않는다. 초기 화면·결합 방식은 취향을 추정하지 않고 남긴다.

제작 패턴 제안은 선택 폴더를 읽고 별도 로컬 기록에 위치·추출 정보·필요한 미리보기를 저장하는 것이다. 04의 볼륨 식별자+상대 경로·갱신 시각·원본 연결 전 버튼 제한을 참고하되 장치 식별의 신뢰성과 재연결 충돌 처리는 미검증이다. 영속 기록이 필요하다는 판단과 특정 DB 선정은 다른 결정이다.

## Verdict

- 판정: **결론 가능** — 제공 합성 자료에서 참고할 관리 패턴과 부적합 조건을 구분하는 범위에 한정한다. 실제 제품·엔진 채택, 지원·성능 보장은 **결론 보류**다.
- 권장 방향: 원본 위치를 유지하는 로컬 참조 카탈로그를 우선 검토한다. SSD가 없어도 이전 정보를 찾으면서 원본 복사를 필수로 하지 않는 점이 사용자 조건과 맞는다. 구조 제안이며 미승인이다.
- 근거: 04의 참조 기록·분리 시 검색, 01의 직접 탐색 한계, 03의 복사·공간 교환 관계.
- 반대 근거: 참조 기록은 오래되거나 경로가 끊길 수 있다. 원본 없이 큰 비교를 원하면 고품질 미리보기나 복사본의 공간 부담이 커져 보관함의 가치가 높아질 수 있다.
- 채택·제외 근거: 세 방식의 유용한 패턴을 비교 대상으로 유지한다. 가상 Indexlens 3.0은 계정·온라인·업로드 조건 때문에 부적합하고, 2.x도 보안 패치 종료 기록 때문에 설치 대안으로 추천하지 않는다. 05는 독립 지지 근거에서 제외한다. 실제 digiKam의 사실이나 추천으로 옮기지 않는다.
- 한계: 합성 문서만 검토. 실제품·공개 저장소·화면·실측 미확인. HEIC 디코딩과 메타데이터 읽기는 별도 검증 대상이고 5만 장 지원은 입증되지 않았다.
- 신뢰도: **중간** — 문서 안의 관리 방식 차이와 버전 충돌은 직접 확인했으나 사용자 환경 적합성과 취향은 미정이다. 실제 제품 추천의 신뢰도는 낮다.
- Idea에서 바꿀 내용: 참조 방식이라는 미승인 대안을 추가. 기존 사용자 조건·제외는 유지. 사용자에게 보이는 관리·보관 선택은 확정하지 않는다.
- Execution에서 바꿀 Phase·Build: 아직 없음. 후보 영역은 형식·분리 장치 탐색 검증 후 관리 구조 선택이다. Phase/Build ID나 일정·비용을 이번에 만들지 않는다.

## 보류·후속 검증·closure

- V1: 실제 Windows 구성에서 JPEG·PNG·HEIC 정상·지원 불가·손상 입력을 합성/공개 검증 데이터로 확인한다. 계정·업로드 없이 표시·읽기 가능해야 한다. 디코더 설치·배포 조건·라이선스·비용은 미확인으로 남기며 설치나 지출을 승인하지 않았다.
- V2: 5만 장·복수 볼륨에서 초기/재탐색, 날짜 탐색, 캐시 사용량과 재시작, 분리·재연결·외부 경로 변경을 검증한다. 원본 분리를 삭제로 오인하지 않고 저장 정보의 시점·접근 불가 상태를 설명하는지가 관찰 기준 제안이다. 수용 지연·용량은 사용자와 이후 합의한다.
- V3: 개인 사진 없는 화면·검증 자료로 큰 비교와 분리 시 미리보기 품질을 확인한다. 실제 화면을 보지 않았으므로 현재 UX 우열은 확정하지 않는다.
- 원자료의 Claim·날짜·버전·재게시 관계·반대 근거와 접근 경계는 기록했다. 그러나 실제 외부 근거의 공백이 있으므로 원래 요청의 폭넓은 Web 조사 완료 및 전체 Research closure를 선언하지 않는다.
- 사용자 지시대로 이번에는 결론 제안까지 제공한다. 다음 합의의 우선 질문: **외장 SSD가 빠져 있을 때 날짜·경로 같은 정보만 필요할지, 저장된 미리보기로 크게 비교할 수 있어야 할지?** 이 답에 따라 참조 캐시와 복사 보관함의 교환 관계를 다시 판단한다.
