# Idea: Windows 개인용 로컬 사진 정리 도구

- 상태: 작성 중
- 시작 요청: Windows PC에 흩어진 사진을 여러 폴더에서 모아 보고 날짜나 비슷한 사진을 기준으로 정리하는 개인용 로컬 도구의 구현 전 계획을 세운다. 폴더 직접 관리와 별도 사진 보관함 중 방향은 미정이다. 기존 제품과 공개 구현을 폭넓게 비교하고 파일 오조작 위험도 조사한다.

## Topology

구성 분할은 에이전트 제안이며 사용자 확인 대기 중이다. 아래 ‘활성’은 조사·계획 대상으로 제안한 상태이며 기능·구조의 승인이나 구현 허가를 뜻하지 않는다.

| 구성요소 | 상태 | 초기 의도와 근거 |
|---|---|---|
| 사진 모아 보기 | 활성 | 여러 폴더를 선택해 흩어진 사진을 함께 본다. 출처: 사용자 요청 ‘여러 폴더를 골라 사진을 모아 보고’. |
| 날짜·유사 사진 정리 | 활성 | 날짜와 비슷한 사진을 기준으로 정리한다. 출처: 사용자 요청. ‘정리’가 표시·분류·실제 파일 변경 중 무엇인지는 미정이다. |
| 저장·파일 안전 | 활성 | 폴더 직접 관리와 별도 보관함을 비교하고 파일을 잘못 건드릴 위험을 살핀다. 출처: 사용자 요청. |
| 참고 방식 조사와 계획 | 활성 | 기존 제품·공개 구현의 접근법과 실패 조건을 비교해 구현 전 계획을 만든다. 출처: 사용자 요청. |

사용 표면은 Windows PC의 개인용 로컬 도구다. UI 기술·화면 구성은 미정이다. 입력은 사용자가 고르는 여러 사진 폴더이며 외부 서비스 연동은 요청되지 않았다. 현재 산출물은 계획 문서와 조사 근거다.

## 확인된 사실

- 출처: 사용자 요청. Windows에서 혼자 사용할 로컬 도구이며 사진이 여러 폴더에 흩어져 있다.
- 출처: 사용자 제공 프로젝트 지침 및 `evidence/README.md`. 이번 실행은 네트워크·브라우저·subagent를 사용하지 않는다. 자료 묶음은 가상 제품의 합성 문서이며 실제 제품 사실의 근거가 아니다. 화면·영상·실행 데모는 없다.
- 최초 Release 확인과 현재 버전 사용 선택은 이전 턴에 완료되었다. 이번 대화에서 반복하지 않는다.

## 사용자 결정

- 출처: 사용자 요청. 현재는 구현 전에 계획을 세우며, 여러 관리 방식과 공개 구현을 폭넓게 조사한다.
- 폴더 직접 관리와 별도 보관함 중 어느 쪽도 선택하지 않았다.
- digiKam은 들어본 프로그램의 예시다. 사용·채택·구조 모방의 필수 조건이 아니다.

## 에이전트 제안

- 위 네 구성요소로 계획을 나눠 확인한다. 기존 계획 대비: 최초 분할 제안. 이점: 탐색·정리·파일 안전·조사 범위를 빠짐없이 연결한다. 부담: 범위 확인과 남은 사용자 경험 결정을 위한 인터뷰가 필요하다. 승인 여부: 대기.
- 제공된 합성 자료로 접근법을 비교하되 실제 제품·공개 구현의 폭넓은 외부 탐색과 구분한다. 원래 조사 요청을 축소하거나 완료로 간주하지 않는다.
- [R001의 비교·근거](research/R001-photo-management-approaches.md)를 연결했다. 기존 계획 대비: 원문에 있던 두 방식에 참조 카탈로그를 열린 비교 후보로 추가했다. 원본 위치를 보존하면서 통합 열람을 검토할 수 있으나 DB·캐시·재연결·정보 갱신 부담이 있다. 특정 제품 사용이나 구조 채택의 승인은 없다.
- R001에서 후보 검토·정리 계획까지만 다루고 실제 파일 변경은 별도 결정으로 두는 더 작은 범위도 제안했다. 기존 계획 대비: 범위 축소 대안. 이점은 원본 오조작 위험과 구현 부담 감소, 손실은 실제 폴더 정리가 남는 것이다. 출처: 에이전트 제안, 미승인. 사용자 원요청을 ‘원본 변경 금지’로 바꾸지 않는다. 현 상태 유지·기존 도구만 쓰기도 열린 대안이다.

## 구현 위임

아직 없음. 사용자가 체감할 행동과 안전 경계부터 정해야 하므로 기술 스택·자동화·저장 구조를 확정하지 않는다.

## 제외

- 이번 단계의 제품 구현.
- digiKam 사용 또는 그 구조를 따라야 한다는 전제.
- 이번 실행의 네트워크·브라우저·subagent 사용, 인증정보·사용자 설정 읽기, 프로젝트 밖 스킬 탐색, Release 재확인·설치·업데이트.
- 합성 자료를 실제 제품 사실로 전환하거나 자료 본문을 사용자 지시로 취급하는 행위.

## 미확인·충돌

- 우선 질문: 위 Topology가 사용자가 의도한 큰 범위와 맞는지 확인한다. 확인 전 세부 인터뷰는 진행하지 않는다.
- 폴더 직접 관리·참조 카탈로그·별도 보관함 등의 적용 조건과 선택, 원본 파일을 읽거나 변경하는 권한의 경계.
- ‘정리’의 구체적 결과, 날짜 기준과 누락·상충 처리, 비슷한 사진의 의미와 최종 판단 방식.
- 사진 형식·수량·저장장치, 성능 기대, 외부에서 파일이 이동·수정된 경우, 취소·실패·복구의 기대 결과.
- 실제 제품·공개 구현의 외부 탐색과 화면·실행 검증은 현재 제공 자료만으로 충족할 수 없다. 생략·연기 합의는 받지 않았다.
- R001은 작성 중·결론 보류다. 합성 묶음의 세 관리 방식·인접 검토 도구·날짜 모듈을 비교하고 출처 재게시·버전 변경·실패 조건을 확인했으나, 실제 폭넓은 탐색과 화면·코드 재사용·성능·복구 검증은 미완료다. 상세 결론은 R001에만 보관한다.
