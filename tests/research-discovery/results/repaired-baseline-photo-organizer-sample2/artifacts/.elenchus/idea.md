# Idea: Windows 개인용 로컬 사진 정리 도구

- 상태: 작성 중
- 시작 요청: Windows PC에 흩어진 사진을 혼자 정리하는 로컬 도구를 계획한다. 여러 폴더를 선택해 사진을 모아 보고, 날짜나 비슷한 사진을 기준으로 정리하고 싶다. 탐색기처럼 폴더를 직접 다루는 방식과 별도 사진 보관함 방식은 아직 선택하지 않았다. digiKam을 사용하거나 그 구조를 따르라는 요청은 아니다. 기존 제품과 공개 구현에서 참고할 방식을 폭넓게 비교하고 파일을 잘못 건드릴 위험도 함께 검토한다. 지금은 구현 전 계획만 수립한다.

## Topology

사용자가 이전에 제시된 범위 중 여러 로컬 폴더의 사진을 보고 정리하는 원래 범위에 동의했다. 아래 항목은 그 범위의 조사 구성이며 제품 기능·저장 방식의 추가 승인이 아니다.

| 구성요소 | 상태 | 사용자 근거 |
|---|---|---|
| 여러 폴더의 사진 모아 보기 | 활성 | Windows에서 혼자 사용, 인터넷 없이 기존 사진 탐색, 연결 해제된 외장 SSD의 이전 사진 정보 조회 |
| 날짜·중복·유사 사진 정리 | 활성 | 날짜로 훑기와 큰 비교 화면, 중복 후보를 나란히 비교해 직접 선택 |
| 저장·관리 방식 비교 | 활성 | 폴더 화면·타임라인·보관함 선호 미정, 내부 구조는 조사 근거로 제안 |
| 원본 보호·실패 확인 | 활성 | 명시적 적용 전 원본·메타데이터 불변, 이동을 고르면 적용 목록과 실패 결과 확인 |

## 확인된 사실

- 출처: 사용자 요청. JPEG·PNG·HEIC 약 5만 장이 두 드라이브와 외장 SSD에 흩어져 있다. 촬영일이 없거나 잘못된 사진이 있다. 실제 개인 사진·하드웨어는 열람하거나 측정하지 않았다.
- 출처: 사용자 제공 환경과 읽기 전용 문서 확인(2026-09-07). Windows PowerShell 작업 환경이며 `.elenchus/idea.md`는 기존 작성 중 문서다. `evidence/README.md`는 모든 제품·조직·수치·코드가 합성 자료이며 화면·실행 데모가 없다고 명시한다.
- 기존 제품 코드와 현재 프로그램 동작은 이번 요청의 근거가 아니므로 조사하지 않는다. 인증정보·사용자 설정도 읽지 않는다.

## 사용자 결정

- Windows PC에서 혼자, 인터넷 없이 기존 사진을 찾아본다. 여러 로컬 폴더를 선택해 모아 보고 정리한다.
- 외장 SSD가 빠져 있어도 이전에 본 사진의 정보를 찾아본다. 오프라인 큰 이미지 표시나 축소판의 보존 범위까지 확정한 것은 아니다.
- 날짜로 훑어보기와 사진을 크게 비교하기가 중요하다. 폴더 화면·타임라인·보관함의 선호는 미정이다.
- 명시적으로 적용하기 전에는 원본 사진과 메타데이터를 바꾸지 않는다. 이동 기능을 선택하는 경우 적용 전 대상 목록을 확인하고, 실패 후 원본 상태와 발생한 일을 알 수 있어야 한다.
- 중복은 삭제 전 후보를 나란히 비교해 사용자가 직접 고른다. 시각적 유사성만으로 자동 삭제하지 않는다.
- 조사와 역할 분담을 허용했다. 이번에는 Research 결론까지 받고, 전체 실행 계획 합의는 다음에 진행한다. 새로운 기능·비용을 확정하지 않는다.

## 에이전트 제안

- 출처: 에이전트 제안. 조사를 R001 모아 보기·저장, R002 파일 변경·복구, R003 날짜 근거, R004 중복·유사 비교로 분리한다. 원래 범위의 조사 구성 변경이며 기능 추가가 아니다.
- 조사 결론에서 제시할 구조·사용자 흐름은 미승인 제안으로 관리한다. 특정 제품·엔진·DB 채택은 확정하지 않는다.

## 구현 위임

사용자가 내부 구조의 근거 있는 제안을 요청했다. 엔진·DB·코덱·UI 도구 선택은 필수 조건이 아니며 아직 선정·구현을 위임한 상태가 아니다. 되돌리기 어려운 파일 동작, 비용, 지원 범위를 기술 세부로 숨겨 확정하지 않는다.

## 제외

- 계정, 클라우드 업로드, 공유, 얼굴 인식, 사진 편집.
- 외부 계정 생성·사용, 유료 호출, 실제 개인 사진 접근.
- 이번 턴의 제품 구현, 전체 Phase·Build 실행 계획 합의, Release 재확인·설치·별도 업데이트.
- 환경상 네트워크·브라우저 연결·subagent 사용. 역할 분담 허용을 환경 제약 해제로 해석하지 않는다.
- digiKam 채택·구조 모방의 전제. 사용자 언급 분류는 예시이며 필수 제약이 아니다.

| 영역 | 분류·남은 결정 | 현재 처리 |

| 정상 흐름·출력 | 여러 폴더 탐색→날짜 훑기/비교→사용자 선택은 요구, 화면 구성·목록 정보는 미정 | Research에서 경험 대안 비교 |

사용자 요구 사이의 직접 충돌은 발견하지 않았다. Idea의 네 차원과 공격 표면을 확정한 것은 아니며 한 문장 목표의 최종 확인·Execution 합의는 후속 대화에 남긴다.
