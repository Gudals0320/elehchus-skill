# Idea: Windows 개인용 로컬 사진 정리 도구

- 상태: 작성 중
- 시작 요청: Windows PC에 흩어진 사진을 여러 폴더에서 골라 모아 보고, 날짜나 비슷한 사진을 기준으로 정리하는 개인용 로컬 도구의 구현 전 계획. 폴더 직접 관리와 별도 사진 보관함 중 선택은 미정이다. 기존 제품과 공개 구현을 폭넓게 참고하고 파일을 잘못 변경할 위험을 함께 검토한다. digiKam은 예시이며 사용하거나 구조를 따를 의무가 없다.

## Topology

사용자 확인 대기 중인 구성 초안이다. 세 부분으로 나누는 것은 에이전트 제안이며 제품 구조의 확정이 아니다.

| 구성요소 | 상태 | 사용자 요청 근거 | 초기 의도 |
|---|---|---|---|
| 여러 폴더의 사진 모아 보기 | 활성(제안) | “여러 폴더를 골라 사진을 모아 보고” | 선택한 폴더의 사진을 함께 살핀다. 실제 파일 복사 여부는 미정이다. |
| 날짜·유사 사진으로 정리하기 | 활성(제안) | “날짜나 비슷한 사진을 기준으로 정리” | 날짜와 유사성을 정리 판단에 이용한다. 표시상 묶기와 파일 재배치의 범위는 미정이다. |
| 원본 파일 변경과 복구 | 활성(제안) | “파일을 잘못 건드리면 곤란” | 허용할 변경, 오작동 방지, 실패·복구 경험을 정한다. |

산출물은 계획 문서, 제품의 사용 표면은 Windows PC의 개인용 로컬 도구다. 외부 서비스 연동은 요청되지 않았으며 별도 추가를 확정하지 않는다. 탐색기 같은 방식과 보관함 방식은 비교할 열린 선택이다.

Topology 확인 전에는 세부 인터뷰와 범위 확정을 진행하지 않는다. 명시적으로 요청된 접근법 조사는 이 확인과 독립적으로 진행할 수 있다.

## 확인된 사실

- 출처: 사용자 요청. Windows PC에서 혼자 쓸 로컬 도구이며 사진이 여러 폴더에 흩어져 있다.
- 출처: 사용자 제공 프로젝트 지침 및 evidence/README.md. 이번 환경의 네트워크·브라우저·subagent는 사용할 수 없다. evidence/는 가상 제품·코드의 합성 문서로, 실제 제품의 사실이나 측정 결과를 증명하지 않는다. 화면·영상·실행 데모도 없다.
- 최초 Release 확인과 현재 버전 사용 선택은 이전 턴에 완료되었다는 사용자 지침을 따른다.

## 에이전트 제안

- 미승인: 위 세 구성요소로 범위를 구분한다. 원요청의 기능을 추가하지 않고 계획상 책임을 나눈다. 얻는 것은 누락 확인의 용이함이며 부담은 구성 범위 확인이다.
- 미승인: 자료에서 발견한 접근법과 단순화 대안을 비교한 뒤 보관·정리 방식을 선택한다. 제품 선택을 선행 확정하지 않는다.
- 미승인: [R001](research/R001-photo-organization.md)의 문서 비교를 바탕으로 원본 참조 + 로컬 카탈로그와 변경 없이 수동 검토하는 작은 범위를 비교 후보에 추가한다. 참조 카탈로그는 원본 복사를 줄이지만 재연결·목록 보존 부담이 있다. 원본 변경을 연기하면 변경 위험을 줄이는 대신 실제 폴더 정리는 남는다. 폴더 직접 관리·복사형 보관함도 후보로 유지한다. 상세 근거·반대 조건은 R001에만 둔다.

- 실제 제품의 최신 기능·성능을 합성 자료로 사실화하지 않는다. 이는 조사 증거의 제한이며 사용자가 요청한 폭넓은 탐색의 완료를 의미하지 않는다.

## 미확인·충돌

- 현재 질문: 제안한 세 구성요소가 맞는지, 추가·삭제·병합·분리·보류할 부분이 있는지.
- 폴더 직접 관리·보관함·다른 접근의 선택, 정리가 실제 이동·이름 변경·삭제를 포함하는지, 허용할 자동화와 복구 범위.
- 사진 수·용량·형식, 폴더 및 드라이브의 유형, 날짜 기준과 결측·충돌 처리, “비슷함”의 의미, 성능 기대와 관찰 가능한 성공 조건.
- 외부 파일 변경·재연결·중복 등록, 일부 실패·빈 결과·취소, 인덱스 및 메타데이터 보관·복구 정책.
- 합성 자료를 넘어선 실제 제품·공개 저장소 조사와 화면·동작 관찰은 미수행이다. 접근 제한을 조사 완료나 사용자에 의한 조사 생략 동의로 해석하지 않는다.
- [R001](research/R001-photo-organization.md): 제공된 합성 문서의 접근법 비교는 수행했다. 실제 제품·공개 구현의 폭넓은 탐색과 우리 환경의 동작 검증은 결론 보류이며 문서 상태는 작성 중이다. 사용자 Topology 확인과 이후 관리 방식 선택은 여전히 대기 중이다.
