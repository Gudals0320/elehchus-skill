# Research R001: 로컬 사진 관리·정리 방식

- 상태: 작성 중
- 기준: [idea.md](../idea.md)의 사용자 결정·제외·미확인 사항. Topology 확인 대기 중이며 명시적으로 요청된 조사만 선행한다.
- 확인 날짜: 2026-09-07 (Asia/Seoul)
- 영향: Phase 후보

## 질문·목적·범위

목적은 접근법 탐색·벤치마킹과 유력 방식의 안전성 주장 검토다. 자료는 모두 가상 제품·코드의 합성 문서이며 실제 제품 사실을 입증하지 않는다. 사용자의 폭넓은 실제 제품·공개 구현 조사 요청은 유지하며, 이번에 가능한 문서 비교를 그 요청의 수행 완료로 대체하지 않는다.

Repository 기준선: 현재 질문은 신규 도구의 관리 방식 탐색으로 기존 제품 코드와의 연결 확인은 생략한다. 제품 코드의 존재·부재나 현재 동작을 조사했다고 주장하지 않는다. 직접 확인한 범위는 이 프로젝트의 지정 스킬·단계 지침 및 evidence/README.md와 자료 파일 목록이다. 기존 .elenchus 문서는 없었으며 초기 의도 문서를 작성했다. 사용자 지침상 네트워크·브라우저·subagent는 사용할 수 없다. 인증정보와 사용자 설정은 읽지 않는다.

조사 깊이는 전체 기록이다. 여러 후보와 파일 손상 위험, 버전 충돌 가능성이 있으므로 단일 저위험 사실 확인으로 축소하지 않는다.

초기 검색·읽기 계획: 안내문의 접근 범주에 따라 01·03·04의 제품 원문을 먼저 읽는다. 발견한 구현·제약·버전 단서를 따라 02·05·06·07·08에서 필요한 부분을 확인한다. 로컬 검색어는 폴더·보관함·참조·날짜·유사·이동·복구·중단·외부 변경·버전·라이선스다. 반대·실패 조건은 덮어쓰기·충돌·삭제·오탐·시간대·공간 부족·다른 볼륨·재연결로 추적한다. 출처 역할은 제품 작성자의 설명, 구현 작성자의 개발 문서, 재게시 자료를 구분한다. 최신성은 제공 문서의 날짜·버전 내에서 판단하며 실제 현재 릴리스로 확대하지 않는다.

공개 접근은 시도하지 않는다. terminal reason은 이번 실행의 네트워크·브라우저 미제공이라는 경로 제한이며 개별 URL의 404나 원문 부재를 확인한 것이 아니다. 대체 경로는 제공된 로컬 본문이다. 실제 공식 문서·공개 저장소·이슈·API·아카이브·화면 경로는 남아 있으나 이번 환경에서는 사용할 수 없다. 추가 실제 조사의 효용이 낮다는 결론을 내리지 않는다.

## 비교와 근거

아래의 제품명·버전·작성 주체는 **제공된 합성 세계 안의 사례 식별자**다. 모든 원문 본문을 메인이 로컬에서 직접 읽었다. 관찰 수준은 **자료의 설명**이며, Chronofile의 짧은 코드 구조만 **직접 코드 열람**이다. 화면 관찰·설치 테스트·코드 실행은 전혀 수행하지 않았다. 실제 제품의 독립 출처나 공개 저장소를 확보했다는 뜻이 아니다.

### 중요한 주장·반대 근거·공백

### 탐색 갱신과 우선 공백

첫 묶음(S01·S03·S04)에서 폴더 직접 관리·복사형 보관함·참조 카탈로그의 세 범주를 발견했다. 중요한 공백은 이동 실패와 참조형 설계의 버전 범위였다. 다음 묶음(S02·S05·S06)에서 원자성의 한계, 재게시 중복, 3.0의 온라인 의존을 확인해 판정을 바꿨다. 인접 구현 탐색(S07·S08)에서 원본 변경 없는 수동 검토와 날짜 출처 보존을 더 작은 대안·공통 원리로 추가했다.

반대 근거 점검 범위는 S01–S08 전체 본문이다. 특히 이동 중 연결 끊김·외부 변경·볼륨 차이(S02), 추가 공간·원래 폴더 정리 잔존(S03), 분리·재연결·정보 노후(S01·S04), 버전별 온라인 전환(S06), 유사 오탐·후보 누락 미측정(S07), 시간대·수정일·형식 제한(S08)을 확인했다. 반대 근거를 수집했지만 독립 현장 재현으로 확대하지 않는다.

남은 최상위 공백은 사용자가 원하는 정리가 원본 폴더 구조 변경까지 포함하는지와 실제 제품·공개 구현의 직접 근거다. 전자는 Topology 확인 다음의 안전·사용자 결과 질문으로 돌아간다. 후자는 환경 접근 제한으로 유지한다. 얼굴·의미 기반 묶기 같은 추가 접근 범주는 이번 원자료로 비교할 수 없고 사용자 요구에도 확정돼 있지 않다. 실제 탐색 범주의 충분성을 선언하지 않으며 자료가 생기면 현재 목적에 맞는 범주를 다시 점검한다.

## 결론과 다음 행동

- **탐색 판정: 제한된 합성 문서 안의 접근법·선택 조건 비교는 결론 가능. 사용자가 요청한 실제 제품·공개 구현의 폭넓은 탐색 전체는 결론 보류.** 실제 제품의 채택 추천, 현재 시장 범위의 충분성, 시각·상호작용 품질은 판정할 근거가 없다.
- **검증 판정: 자료 안의 버전 차이·원자성 일반화·유사성 동일시·날짜 확정 주장은 검토 가능. 우리 Windows 도구의 복구·정확도·성능·형식 지원·코드 재사용은 결론 보류.** Lab은 실행하지 않았다.
- 신뢰도: 문서의 명시적 내용·출처 중복·버전 차이 판독은 높음. 원리를 사용자에게 적용할 수 있다는 판단은 중간이며 사용 상황 미확인에 제한된다. 실제 제품 추천과 구현 성공 예측은 낮음.
- 근거와 반대 근거: 위 비교·C1–C7 참조. 카탈로그는 복사 부담을 줄이지만 재연결·목록 복구 책임이 생기고, 보관함은 원본 위치에서 독립되지만 추가 공간·가져오기 부담이 있으며, 폴더 방식은 실제 정리와 연결되지만 파일 변경 실패를 다뤄야 한다. 하나를 보편적 정답으로 정하지 않는다.

**미승인 에이전트 제안:** 우선 원본을 참조하는 로컬 목록과 사람이 검토하는 정리안을 유력 후보로 비교한다. 원본에 쓰지 않는 초기 범위라면 변경 위험을 줄이고 보관 방식의 선택을 나중에 되돌리기 쉽다는 추론이다. 원요청 대비 단순화는 실제 이동·이름 변경·삭제를 뒤로 두는 것이고, 사용자가 얻는 것은 통합 보기·검토이며 잃는 것은 원래 폴더가 즉시 정돈되는 결과다. 사용자에게 실제 폴더 재배치가 핵심이면 이 추천은 달라진다. 카탈로그 선택, 원본 변경 연기, CSV 출력 어느 것도 사용자 합의로 기록하지 않는다.
