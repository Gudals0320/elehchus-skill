- 확인 날짜: 2026-09-07
- 영향: Phase 후보

## 질문·범위·증거 계획

중립 질문은 촬영일이 없거나 잘못된 사진을 날짜 탐색에서 어떻게 설명할지다. 입력은 원문 날짜·EXIF/파일 날짜·시간대 정보가 있을 수도 없는 JPEG·PNG·HEIC, 출력은 근거를 구분할 수 있는 날짜 표시와 탐색이다. 성공은 추정 날짜를 실제 촬영일로 오인시키지 않고 원본 메타데이터를 명시적 적용 전 보존하는 것, 실패는 복사된 파일 날짜나 알 수 없는 시간대를 확정 촬영 시각으로 취급하거나 자동 수정하는 것이다. 기본 정렬 정책과 날짜 보정 기능의 포함 여부는 미정이다.

Idea 외 제품 기준선은 조사하지 않았다. 출처 식별·접근 제한은 [R001](R001-photo-access.md#증거-계획과-접근-범위)을 따른다. Chronofile 0.6은 발견한 모듈 사례이며 엔진 채택이 아니다.

| 증거원 | 상태 | 이유 | 바뀔 수 있는 결정 |
|---|---|---|---|
| Repository | 필요 | Idea의 날짜·메타데이터 제약 확인 | 보정 기능을 이미 요구된 기능으로 오인하지 않음 |
| Independent exploration | 생략 | subagent 미제공, 메인이 정책과 데이터 보존을 검토 | 독립 탐색 한계 |
| External evidence | 필요 | E01·E04·E08 합성 원문·코드 텍스트 확인 | 날짜 선택 방식·출처 표시·보정 저장 위치 |
| Browser Evidence | 생략 | 계정별 관찰 질문 없음, 연결 미제공 | 영향 없음 |
| Lab | 생략 | 완전한 파서·HEIC/손상 fixture가 없음. 예제 딕셔너리 실행은 지원 검증이 아님 | 포맷 지원·오류 처리 미검증 |

## 비교·Claim 검증

`촬영일·파일 날짜·시간대·수정일·출처·fixture`로 관련 본문을 재확인했다. 후보 비교·지원 경계가 있으므로 전체 기록을 적용한다. E01은 1.7, E04는 2.8, E08은 0.6 설명에 한정한다. 화면은 관찰하지 않았다.

| 접근·주장과 영향 | 근거·관찰 수준·반증 조건 | 적용·반대 근거·부담 | 판정·공백 |
|---|---|---|---|
| 촬영일/파일 날짜를 사용자가 선택 · 탐색 방식 | [E01 첫 문단](../../evidence/01-pathframe-guide.md), 자료의 설명 | 선택 근거가 명료하지만 촬영일 결측 처리·기본값은 문서에서 미확인 | 범위 제한. 사용자가 어떤 기본값을 원하는지 아직 모름 |

## 결론과 다음 행동

**판정: 결론 가능 — 날짜 출처와 불확실성을 분리하는 설계 원칙의 문서 비교. 결론 보류 — 기본 날짜 정책·시각 UX·모듈 채택과 실제 형식 지원.** 문서 해석 신뢰도는 높음, 적용 추론은 중간, 실제 지원 판정은 낮음이다.

권장 제안은 원문/파싱 값/출처/시간대 유무를 보존하고 화면에 표시하는 날짜의 근거를 설명하는 것이다. 사용자가 보정을 원한다면 읽어 온 값과 사용자 보정값을 별개로 저장하는 접근을 검토할 수 있으나, 보정 기능과 저장 위치는 추가 제안일 뿐이다. 원본 쓰기나 sidecar 생성은 자동 확정하지 않는다. 읽기 전용 카탈로그에 저장하는 제안도 실제 원본의 메타데이터 수정과 구분한다.

기본 정책에는 다음 교환 관계가 있다. EXIF가 없을 때 파일 날짜를 임시로 쓰면 연속 탐색이 쉽지만 잘못된 시대에 놓일 수 있다(E04·E08). 촬영일 미확인을 별도로 모으면 잘못된 단정을 줄이지만 타임라인 밖에서 확인할 사진이 늘어난다(**에이전트 제안**, 문서 속 실제 화면 아님). 날짜 원천을 사용자가 전환하면 해석은 명확하지만 선택 부담이 생긴다(E01). 어느 정책도 사용자 취향으로 확정하지 않는다. 더 작은 버전은 출처 표시와 읽기만 제공하고 보정 기능을 연기하는 안이며, 잘못된 날짜를 앱 안에서 바로잡는 결과가 사라진다.

Discovery 점검: 정책 접근·적합한 설명/코드 근거·변경 비용·미승인 선택을 비교했다. 제공 문서를 더 읽어도 실제 파서 지원이나 화면 편의는 판정할 수 없다. 실재 모듈·시각 사례 탐색은 R001의 미완료 범위이며 검증 Build로 대체해 완료 처리하지 않는다. Web 근거는 합성 원문 범위만 추적했다.

다음 공개 근거에서는 실제 날짜 모듈의 읽기 전용 경계·지원 형식·사용 조건을 확인해야 한다. 우리 환경 검증 후보는 비개인 JPEG·PNG·HEIC의 날짜 결측/손상/상충, 시간대 없음, 다른 기기 시각, 파일 날짜 변경이다. 채택 기준 제안은 출처·불확실성을 유지하고 한 파일 실패를 설명하며 원본을 바꾸지 않는 것이다. 날짜 숫자가 나오는 것만으로 성공으로 보지 않는다. 이를 의존하는 지원·정렬 구현보다 먼저 검증하되 지금은 미실행이고 Execution 합의도 없다.

Idea에는 출처 표시 제안과 기본 정렬·보정 기능 미정을 연결한다. 기존 제약을 바꾸지 않고 상태를 작성 중으로 유지한다.
