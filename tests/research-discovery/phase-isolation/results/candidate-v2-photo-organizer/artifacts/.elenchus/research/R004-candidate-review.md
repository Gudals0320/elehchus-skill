# Research R004: 동일·유사 사진 후보와 사람의 비교

- 상태: 작성 중
- 기준: [Idea의 큰 비교·삭제 전 직접 선택 요구](../idea.md)
- 확인 날짜: 2026-09-07
- 영향: Phase 후보

## 질문·범위·증거 계획

중립 질문은 동일 파일과 닮은 사진을 어떻게 후보로 제시해 사람이 판단하도록 할지다. 입력은 약 5만 장의 JPEG·PNG·HEIC와 저장된 정보, 출력은 후보와 비교에 필요한 사진·정보다. 성공은 후보의 의미를 구분하고 사람이 나란히 비교해 직접 선택하는 것, 실패는 유사도만으로 동일 사진이라 단정하거나 자동 삭제하는 것이다. 계정·업로드·얼굴 인식·편집은 제외한다. 실제 삭제 기능, 오프라인 큰 비교의 해상도, 유사 후보 기준·누락 허용치는 미정이다.

기준선·원문 출처·로컬 접근 기록은 [R001](R001-photo-access.md#증거-계획과-접근-범위)을 따른다. Pairboard는 디자인 이미지의 인접 사례, Albumvault는 가져오기 중복 처리 사례다. 둘 모두 필수 엔진이 아니다.

| 증거원 | 상태 | 이유 | 바뀔 수 있는 결정 |
|---|---|---|---|
| Repository | 필요 | 사용자 비교·자동 삭제 제외 조건 확인 | 후보 추천과 삭제 권한 구분 |
| Independent exploration | 생략 | subagent 미제공, 메인이 후보 의미·반례·작은 대안을 검토 | 독립성 한계 |
| External evidence | 필요 | E03·E07 및 오프라인 경계 E04의 합성 문서 확인 | 해시 방식·검토 경험·성능 전제 |
| Browser Evidence | 생략 | 개인화 화면 질문 없음, 연결 미제공 | 영향 없음 |
| Lab | 생략 | 실행 파일·이미지·정답 집합이 없음. 의미 없는 샘플로 정확도·누락률을 보장할 수 없음 | 실제 후보 품질은 보류 |

공개 시각 자료는 큰 비교의 UX 판단에 필요하지만 README·E07에 포함되지 않았고 브라우저도 미제공이다. 직접 시각 관찰 대신 문구만 확보한 상태로 남긴다.

## 비교·Claim 검증

후보 범주를 byte 동일, 시각적 유사, 자동 후보 생성 없이 사람이 비교하는 축소안으로 나누었다. `hash·크롭·압축·배경·동기 확대·누락·5만`을 재확인했다. 모든 제품 동작·실패 경험은 **자료의 설명**이며 동작하는 도구나 화면은 보지 않았다. 최신성은 Albumvault 4.0 및 버전 미기재 Pairboard 제작기 날짜 한정이다.

| 접근·주장과 영향 | 직접 확인한 근거·반증 조건 | 반대 근거·적용·부담 | 판정·공백 |
|---|---|---|---|
| byte hash로 동일 파일 후보 구분 | [E03 둘째 문단](../../evidence/03-albumvault-guide.md), [E07 첫 문단](../../evidence/07-pairboard-devlog.md) | 파일 내용 동일성과 사진 장면 동일성은 다름. 메타데이터·압축·크롭만 달라도 별도 파일일 수 있음 | 문서 설명 확인. 자동 가져오기 생략 동작을 자동 삭제 권한으로 가져오지 않음 |
| perceptual hash의 가까운 점수를 동일 사진으로 단정 가능 | E07 첫 문단: 원본·축소·크롭 후보 및 같은 색 배경의 다른 이미지 사례. 오탐이 반증 조건 | 사람 검토가 필요한 유사 후보의 근거일 뿐. 사진 분야 정확도는 미측정 | 반박. byte 동일 후보와 별도 표시하는 구조를 권장 제안 |
| hash 근처 후보만 모으면 5만 장에 충분히 빠르고 정확 | E07 마지막 문단: 전체 쌍 폭증을 줄이려 근처만 수집 | 누락률·사진 정확도·실제 실행 시간 미측정. 가지치기는 계산량을 줄이는 방향이지만 누락 위험 | 범위 제한/근거 부족. 후보 수·지연·누락 검증 전 성능 보장 불가 |
| 두 장과 해상도·용량·경로, 동기 확대가 검토에 도움 | E07 둘째 문단: 축소 화면에서 원본 세부를 놓쳐 동기 확대 추가 | 큰 비교 요구와 관련 있는 실패 경험. 실제 가독성·확대 동작은 미관찰 | 자료 설명 확인, 시각 UX는 근거 부족. 동기 확대는 미승인 기능 제안 |
| 분리 SSD의 저장 미리보기만으로 원본 세부를 충분히 비교 | [E04 첫 문단](../../evidence/04-indexlens-guide.md): 저장 미리보기 검색, 원본 접근 비활성. E07은 축소 비교의 한계 | 미리보기의 크기·압축은 미기재. 전체 원본의 선명도와 같다고 볼 수 없음 | 근거 부족. 저장 정보 조회와 원본 크기 비교를 구분하고 후자는 연결 필요 여부를 설계해야 함 |
| 비교 결과 선택만 제공하고 삭제 기능은 연기 | E07 둘째 문단: CSV 산출, 원본 수정 없음 | 오류가 직접 원본 삭제로 이어지지 않고 개발 범위 감소. 실제 삭제/정리는 수동으로 남음 | 문서 기반 단순화 제안. CSV·삭제 연기는 사용자 결정 아님 |

## 결론과 다음 행동

**판정: 결론 가능 — 후보 의미 분리와 사람이 검토하는 흐름의 합성 문서 비교. 결론 보류 — 시각 UX·5만 장 성능·후보 품질·실제 구현 채택.** 설명 해석 신뢰도는 높음, 사진 도구 적용 추론은 중간, 실측 성능과 정확도는 낮음이다. E03·E07은 서로 다른 가상 작성 주체지만 독립적인 실제 검증을 제공하지 않는다.

byte 동일 후보와 시각적 유사 후보를 구분하고, 두 장의 큰 비교와 해상도·용량·경로를 참고하는 접근을 제안한다. 동기 확대는 원본 세부를 놓친 사례에 대응하는 후보 기능이며 사용자의 취향·확정 기능으로 바꾸지 않는다. 선택을 직접 한다는 사용자 요구는 그대로 유지한다. byte 동일이든 유사 후보든 자동 삭제는 채택하지 않는다. 삭제를 제품 안에 넣는 결정과 복구 정책은 [R002](R002-file-operations.md)에 남겨 둔다.

다른 대안은 자동 유사 후보 생성을 연기하고 사용자가 고른 사진의 큰 비교부터 제공하는 것이다. 후보 오탐·누락 알고리즘의 제작 부담은 줄지만 비슷한 사진을 자동으로 찾아 주는 결과가 사라진다. **출처: 에이전트 제안, 미승인 축소안**이며 원래 범위에서 해당 결과를 이미 제외했다고 기록하지 않는다. 사진용 다른 검색 기법의 실제 구현 근거는 자료 묶음에 없으므로 이 방식이 전체 해법 중 최선이라고 선언하지 않는다.

Discovery 점검: 접근 차이·설명 원문·비교 적용·선택 영향을 검토했다. 실제 장면과 사진 분야 후보 품질의 직접 근거가 없어 전체 탐색 완료는 아니다. 같은 제작기 재독으로는 공백을 메울 수 없다. 필요한 실제 소스·화면·독립 실패 자료의 탐색을 R001과 함께 이어가야 하며 그 미완료를 시험 계획 작성으로 대체하지 않는다.

실제 실행 가능한 후보를 확보한 뒤 비개인 사진으로 원본/재압축/축소/크롭/같은 배경의 다른 사진을 포함한 정답 집합을 만들고 오탐·누락·검토 후보량·시간·메모리를 측정하는 검증을 제안한다. 사용자 5만 장 접근을 허가받은 것으로 해석하지 않는다. 품질·속도의 수치 기준은 사용자 목표와 자료를 보고 정해야 하며 지금 임의 확정하지 않는다. 연결 해제 중 미리보기 품질과 원본 상세 접근 실패도 후속 관찰 대상이다. 알고리즘·캐시 설계에 의존하기 전에 검증할 조건이며 실제 Lab 실행·Execution 합의는 아직 없다.

Idea에는 후보 유형 분리 제안과 비교 화면·캐시 품질·삭제 미정을 연결한다. 추가 기능·비용은 확정하지 않고 상태를 작성 중으로 유지한다.
