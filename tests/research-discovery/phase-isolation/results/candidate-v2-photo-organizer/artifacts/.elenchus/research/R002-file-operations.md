# Research R002: 원본 보존과 파일 작업 실패

- 상태: 작성 중
- 기준: [Idea의 명시적 적용·실패 설명 요구](../idea.md)
- 확인 날짜: 2026-09-07
- 영향: Phase 후보

## 질문·범위·증거 계획

중립 질문은 파일을 옮기는 기능을 선택할 경우 원본과 실패 경위를 어떻게 보존할지다. 이동 기능 자체는 미정이다. 입력은 여러 드라이브에 있는 선택 파일과 정리안, 출력은 적용 전 원본·대상 목록과 적용 후 항목별 결과다. 성공은 사용자가 승인한 범위만 변경되고 실패 시 원본 위치와 진행 상태를 설명할 수 있는 것, 실패는 미승인 변경·덮어쓰기·중복 삭제·경위 불명이다. 사용자 데이터·권한·제외는 Idea를 그대로 따른다. 완전 복구, 일괄 원자성, 삭제 보관 정책은 확정 사실이 아니다.

기준선·가상 원천의 작성자/버전/날짜·로컬 접근 기록은 [R001의 증거 계획](R001-photo-access.md#증거-계획과-접근-범위)을 따른다. 제품 파일은 열거나 변경하지 않았다. Pathframe·Albumvault·Pairboard는 발견한 비교 사례이며 필수 기술이 아니다.

| 증거원 | 상태 | 이유 | 바뀔 수 있는 결정 |
|---|---|---|---|
| Repository | 필요 | Idea의 조건부 이동 요구와 현재 문서 확인 | 이동을 확정 기능으로 오인하지 않음 |
| Independent exploration | 생략 | 이번 실행에 subagent 미제공. 메인이 작업 책임·반례·축소 대안을 검토 | 독립 검토 한계 |
| External evidence | 필요 | E01·E02·E03·E07 합성 원문을 로컬에서 직접 읽음 | 작업 전 검토·실패 설명·기능 축소 |
| Browser Evidence | 생략 | 계정 화면 질문 없음, 연결 미제공 | 영향 없음 |
| Lab | 생략 | 실행 가능한 파일 작업 구현이 없으므로 문서로 설계 비교. 임의 mock의 성공을 복구 검증으로 대신하지 않음 | 실제 안전성은 결론 보류 |

## 비교·Claim 검증

조사 범위는 즉시 변경, 계획 후 적용, 검토만 수행하는 대안이다. `복사·삭제·원자성·journal·재개·충돌·공간·변경`을 E01~E03·E07에서 확인했다. 전체 기록을 적용하며 모든 동작은 **자료의 설명**이다. UI·파일시스템 실행을 직접 관찰하지 않았다. 최신성은 문서에 명시된 Pathframe 1.7 등 해당 버전 한정이다.

| 접근·주장과 영향 | 직접 확인한 원문·반증 조건 | 반대 근거·적용 비용 | 판정·다음 공백 |
|---|---|---|---|
| 드롭 즉시 이름 변경 · 검토 단계가 없어도 실패 설명 가능 여부 | [E02 첫 문단](../../evidence/02-pathframe-transaction.md): 초기 즉시 변경은 드라이브 간 중단 상태를 설명하지 못했음 | 명시적 적용 전 변경 금지·적용 전 목록 요구와 맞지 않음 | 반박. 이 상호작용은 제외 제안이며 새 사용자 제약을 만들지 않음 |
| 계획 목록·작업 기록 후 적용 · 요구에 맞는 절차인지 | E02 첫·둘째 문단, [E01 둘째 문단](../../evidence/01-pathframe-guide.md): 경로 목록, 충돌/여유 공간 점검, 복사→확인→원본 제거, 재개 중 이중 삭제 방지 | 계획 뒤 외부 변경은 해당 항목 보류. 기록과 실제 파일이 어긋나는 실패 경계의 추가 구현 필요 | 범위 제한. 이동을 고른 경우의 권장 구조, 안전 보장 아님 |
| journal/rename만으로 전체 이동이 원자적이고 완전 복구 가능 | E02 둘째·셋째 문단: 다른 드라이브와 전체 일괄 작업의 원자성·완전 복구를 보장하지 않음. 중간 상태 존재가 반증 | 동일 드라이브 rename 사례를 두 드라이브+외장 SSD에 일반화할 수 없음 | 반박. 복사본만 남음·일부 완료·원본 제거 실패 등을 설명할 결과 모델 필요 |
| 휴지통이면 원본 보호가 해결되는지 | [E03 마지막 문단](../../evidence/03-albumvault-guide.md): 보관함 UI 제거 후 30일 휴지통 | 이 설명은 가져온 보관함 사진에 한정. 외부 원본 이동 복구 보장 아님. 기간·보관 공간 부담 | 범위 제한. 30일 정책은 참고만, 사용자 선택으로 이식하지 않음 |
| 파일 변경을 만들지 않고 후보 검토까지만 제공 | [E07 둘째 문단](../../evidence/07-pairboard-devlog.md): 비교 후 CSV, 삭제·원본 수정 없음 | 앱 내부 파일 변경 위험과 복구 구현 부담 감소. 실제 폴더 정리는 별도 수작업으로 남음 | 문서 설명 확인. 더 작은 버전의 미승인 대안; CSV 추가는 확정하지 않음 |

## 결론과 다음 행동

**판정: 결론 가능 — 합성 문서에서 참고할 작업 절차와 축소안 비교. 결론 보류 — 실제 Windows 파일 작업의 안전성·복구 가능성.** 신뢰도는 문서의 실패 조건 확인에 높음, 설계 적용 추론에 중간, 실행 보장에 낮음이다. E01·E02는 같은 제품 계열이며 독립적인 복구 재현 증거가 아니다.

이동을 채택한다면 읽기/정리안 작성과 실제 변경을 분리하고, 경로·충돌·용량을 검토한 뒤 명시적 적용으로 진행하는 방식을 제안한다. 항목마다 복사·검증·원본 제거의 진행 기록과 마지막으로 확인한 양쪽 파일 상태를 남기고, 재개 시 이미 끝난 삭제를 반복하지 않도록 해야 한다. 현재 연결되지 않은 경로의 상태는 확인 불가로 표시한다. 구체적인 복사 검증 방법, 기록 저장의 내구성, 취소·복구 정책은 미정이다. 작업 목록 승인에 사용자가 확인하지 않은 원본 제거를 끼워 넣지 않는다.

더 작게 시작하는 대안은 사진 목록·날짜 탐색·후보 비교·정리안 검토까지 제공하고 이동·삭제를 연기하는 것이다. 제작 부담은 줄지만 실제 파일 정리 작업이 사용자에게 남는다. **출처: 에이전트 제안, 미승인 단순화**다. 이동을 고르면 필요한 절차라는 결론을 이동 기능 채택으로 바꾸지 않는다.

Discovery 점검: 접근 차이·원문 설명·적용 비용·결정 영향은 비교했다. 제공 자료 안의 절차 비교를 더 반복할 효용은 낮다. 그러나 실제 공개 소스와 복구 실패 사례의 추가 탐색은 여전히 유효하며, 실재 제품 탐색의 공백은 R001과 함께 보류한다. Web 근거는 합성 문서 범위만 추적됐고 실제 웹 조사는 미수행이다.

후속 검증 후보는 비개인 시험 파일로 드라이브 간 연결 중단, 디스크 부족, 이름 충돌, 계획 후 외부 수정, 권한 실패, 프로세스 중단·재시작을 재현하는 것이다. 채택 기준 제안은 미승인 변경·덮어쓰기·이중 삭제가 없고, 부분 완료와 남은 원본/복사본을 항목별로 설명할 수 있는 것이다. 원본 유실이나 설명할 수 없는 결과는 실패다. 어떤 시험도 지금 실행하지 않았다. 이 검증은 실제 이동 기능을 사용자 원본에 적용하기 전에 필요하다. Execution의 검증 Build 후보로 남기며 Build 생성·번호 부여·전체 합의는 다음 대화에서 다룬다.

Idea에는 조건부 작업 절차의 제안과 이동·삭제 미정을 연결한다. 요구·제외를 바꾸지 않으며 Research 결론에 대한 사용자 합의 전까지 상태는 작성 중이다.
