- 기준: [Idea의 최초 요구·선호 답변](../idea.md)
- 확인 날짜: 2026-09-07
- 영향: Phase 후보

## 질문·기준선·중립 brief

중립 질문은 여러 폴더의 사진을 어떤 저장·탐색 방식으로 모아 보고, 외장 SSD가 빠졌을 때 무엇을 제공할지다. 목적은 사례·구현 접근의 탐색과 중요한 제약의 문서 검증이다.

기준선: 현재 `.elenchus/idea.md`에 Topology 확인과 Research 진행 결정이 있다. 읽기 전용으로 확인한 `.elenchus/` 파일 목록에는 Idea만 있었으며 기존 Research·Execution은 없었다. 현재 질문에 제품 코드의 동작 확인은 필요하지 않아 제품 코드·설정은 탐색하지 않았다. 따라서 기존 제품 구현의 존재 여부나 동작을 추정하지 않는다. 프로젝트 지침과 `evidence/README.md`는 증거를 합성 문서로 제한한다.

| 항목 | 내용 |
|---|---|
| 입력 | 사용자가 선택한 여러 폴더, 두 드라이브와 외장 SSD, 약 5만 장의 JPEG·PNG·HEIC |
| 출력 | 사진을 모아 보는 로컬 목록과 날짜·비교에 필요한 정보; SSD 분리 시 이전에 본 사진의 저장된 정보 |
| 사용자 경험 | Windows에서 혼자, 인터넷과 계정 없이 검색; 날짜로 훑고 사진을 크게 비교 |
| 성공 조건 | 원본을 명시적 적용 전 바꾸지 않으며, SSD 분리 후에도 저장된 정보를 찾을 수 있음 |
| 실패 조건 | 계정·통신 없이는 검색 불가, 원치 않는 원본·메타데이터 변경, 분리된 사진 정보 소실 |
| 확정 제약 | Idea의 사용자 답변을 적용. 업로드·공유·얼굴 인식·사진 편집 제외, 유료 호출·개인 사진 접근 불허 |
| 객관적 환경 | Windows/PowerShell, 로컬 파일 읽기 가능. 네트워크·브라우저·subagent 경로는 이번 실행에서 사용하지 않는 제공 조건 |
| 미해결 | 폴더/타임라인 선호, 참조/복사 방식, 이동 기능, 오프라인 미리보기 크기·보존량, 검색 성능 목표, 엔진·DB·배포 방식 |

digiKam은 **예시**다. 후보 발견의 필수 조건에서 제외했으며 이 제품의 기능을 조사·검증한 것으로 기록하지 않는다. Windows와 기존 파일 형식·규모는 **현재 환경이자 제약**이다. 아래에서 발견한 제품·SQLite 등은 **후보 또는 구조 사례**이며 필수 기술이 아니다.

| 증거원 | 상태 | 이유 | 바뀔 수 있는 결정 |

## 접근법 비교와 적용

| 접근법·대표 사례 | 근거·관찰 수준 | 사용자에게 생기는 결과·차이 | 적용·비용·판단 |
|---|---|---|---|
| 원본 폴더 직접 탐색 · Pathframe 1.7 | E01, 자료의 설명 | 실제 폴더 트리와 격자, 날짜 선택. 분리된 폴더는 검색에서 사라짐 | 폴더 맥락과 적용 전 목록은 참고 가능. 이 설명 그대로는 SSD 분리 요구 미충족. JSON sidecar 쓰기는 원본 사진 수정과 다르지만 원본 폴더에 파일을 추가하므로 저장 위치·적용 시점을 별도로 정해야 함. 지속 목록을 추가하면 단순 직접 탐색보다 관리 부담이 늘어남 |
| 복사형 전용 보관함 · Albumvault 4.0 | E03, 자료의 설명 | 가져온 복사본으로 검색·타임라인·원본 크기 열람 가능. 참조 전용 모드 없음 | 분리 후 전체 사진이 꼭 필요할 때 유력. 원본 복사본+미리보기 공간, 가져오기 시간, 원래 폴더와 별도 관리 부담. 실제 폴더 정리는 자동으로 해결되지 않음. 예산·용량은 미확인이라 차선 대안으로 유지 |
| 원본 참조 카탈로그 · Indexlens 2.8의 구조 | E04, 자료의 설명 | 원본은 제자리에 두고 위치·메타데이터·미리보기를 지속 저장. SSD 분리 시 저장 정보 검색, 원본 작업 비활성 | 현재 요구에 대한 우선 검토 제안. 경로 재연결, 마지막 갱신 시각, 목록·캐시 보존 관리가 필요. 캐시 크기·백업·재구축 정책 미정. 해당 제품 구버전 사용 추천과 구분 |
| 계정 서비스가 검색하는 참조 방식 · Indexlens 3.0 | E06, 자료의 설명 | 원본은 로컬이어도 썸네일·검색 정보 동기화, 로그인·온라인 연결 필요 | 계정·업로드·오프라인 제약에 어긋나므로 이 시나리오의 후보에서 제외. E04·E05를 현행 동작 근거로 사용하지 않음 |
| 후보 비교에 집중하는 작은 도구 · Pairboard | E07, 자료의 설명 | 선택 후보 비교 후 CSV, 파일 변경 없음 | 전체 목록·분리 정보 요구를 해결하는 대체 구조는 아님. 이동·삭제를 처음부터 만들지 않는 축소안의 참고. CSV 기능 자체는 미승인 |

폴더 화면·타임라인은 탐색 화면의 선택이고, 참조 카탈로그·복사 보관함은 저장 책임의 선택이다. E03·E04 모두 날짜 탐색을 설명하므로 타임라인을 위해 원본 복사가 필수라고 볼 근거는 없다. 두 화면을 모두 만드는 것은 자동 확정하지 않는다. 배치·가독성·전환 체감은 관찰하지 못했으므로 시각적 권장안은 없다.

## 결론과 다음 행동

**판정: 결론 보류 — 실제 제품·공개 구현을 폭넓게 조사하고 시각 경험까지 판정하는 원래 범위 전체.** 이번에 확보 가능한 합성 문서의 방식 비교에는 **결론 가능**하다. 원본 참조 카탈로그를 우선 검토하고, 원본 전체를 연결 해제 후에도 열어야 하는 요구가 생기면 복사형 보관함을 다시 비교한다. 현재 사용자는 저장된 정보 검색을 요구했으므로 전체 복사 비용을 먼저 확정할 근거가 없다. 직접 폴더 방식만으로는 E01의 분리 동작이 요구에 맞지 않는다.

신뢰도: 문서 내용·버전 불일치 판정은 높음, 사용자 조건에 대한 구조 제안은 중간, 실제 제품 적합성·성능·시각 UX는 낮음. 모두 합성 자료 범위다. SQLite는 E04의 사례일 뿐 DB·엔진·프레임워크 선택, 코드 재사용·라이선스·설치 비용은 미확인이다. 코드 조각이나 문서 설명을 재사용 가능한 전체 공개 구현으로 부르지 않는다.

Discovery 완료 점검: (1) 주요 저장 방식과 작은 대안 비교는 수행, (2) 문서 원문은 확인했으나 필요한 실제 장면·실재 구현 근거는 미확보, (3) 적용 변경·비용을 비교, (4) 제안·제외·보류의 영향을 제시, (5) 로컬 자료 추가 재독의 효용은 낮지만 실제 제품·시각 근거는 선택을 바꿀 수 있어 전체 종료 조건 미충족. Web closure도 확보한 문서의 출처·버전·반례 추적만 충족하며 실제 외부 탐색 완료로 표시하지 않는다. 접근 한계로 멈춘 사실을 충분한 탐색 완료나 사용자 생략 합의로 바꾸지 않는다.

Idea 반영은 참조 방식의 **에이전트 제안**과 열린 선택의 근거 연결뿐이다. 요구의 추가·삭제는 없으며 폴더/타임라인 취향은 미정이다. 만들지 않기·기존 도구 사용은 제작 부담을 없애는 대안이지만 이 자료로 실재 대체 제품의 적격성을 판정할 수 없어 미선택으로 남긴다.

다음 행동은 실제 공개 제품·화면·소스 자료를 읽을 수 있는 조건에서 누락 범주의 탐색을 이어가는 것이다. 그 전까지 실재 제품·엔진 채택과 화면 선택은 보류한다. 별도로 우리 환경의 HEIC·규모·캐시 보존·볼륨 재연결은 후속 검증 후보이며, 지원·성능에 의존하는 제품 작업보다 먼저 확인해야 한다. 전체 Execution과 검증 Build의 등록·합의는 다음 대화 대상이고 지금 실행하지 않았다. 문서 상태를 확정으로 올리지 않는다.
