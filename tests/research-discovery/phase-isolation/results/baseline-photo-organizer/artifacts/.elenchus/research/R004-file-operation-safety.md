# Research R004: 파일 작업의 검토·실패·원본 추적

- 상태: 작성 중
- 기준: [idea.md](../idea.md)
- 확인 날짜: 2026-09-07
- 영향: Phase 후보. 이동 기능 채택·삭제 복구 정책·Execution 순서는 미확정이다.

## Repository 기준선과 Neutral brief

기존 `idea.md`에서 명시적 적용 전 원본·메타데이터 무변경, 이동 기능을 선택할 경우 사전 목록 검토와 실패 결과 확인, 삭제 후보의 수동 비교를 확인했다. 실제 파일 작업 구현·파일시스템·드라이브 식별 값·설정·개인 사진은 확인하지 않았다.

| 항목 | 내용 |
|---|---|
| 중립 질문 | 파일 작업을 선택할 경우 적용 전 검토와 실패 후 원본 상태 확인을 어떻게 보장할 것인가? |
| 입력 | 복수 드라이브·외장 SSD의 사진, 사용자가 검토한 변경 후보. 이동 기능 채택은 아직 미정 |
| 출력 | 계획 목록·적용·작업 기록·실패 설명의 책임 경계와 더 작은 범위의 비교 |
| 사용자 경험 | 바뀔 원본·대상을 먼저 보고 명시적으로 적용한다. 중단·실패 후 원본과 복사본에 무슨 일이 일어났는지 알 수 있다. |
| 성공 조건 | 검토되지 않은 삭제가 없고, 충돌·분리·외부 수정에 대응하며, 항목별 결과와 남은 작업을 설명한다. |
| 실패 조건 | 자동 이동·원본/sidecar 쓰기, 무검토 덮어쓰기·삭제, 중단 후 상태 불명, 재시도로 중복 삭제, 일괄 원자성·완전 복구의 근거 없는 보장 |
| 확정 제약 | Windows 개인용·로컬·오프라인, 약 5만 JPEG·PNG·HEIC. 계정·클라우드 업로드·공유·얼굴 인식·편집 제외. 개인 사진·유료 호출·외부 계정 불허. |
| 객관적 환경 사실 | Pathframe 개발 기록은 합성 문서이며 실행 가능한 작업 엔진·복구 테스트가 없다. 네트워크·Browser·subagent 미지원. |
| 미해결 질문 | 파일 이동 채택 여부, 충돌 시 사용자 선택, 삭제의 복구 방식·보존 기간, 확인 방법·재개 정책과 안전 검증 |

기술 언급 분류: Windows·사진 형식은 필수 환경/지원 조건, digiKam은 예시다. journal·복사 후 확인은 조사한 제작 패턴이며 특정 API·DB나 완성된 구현이 아니다.

| Independent exploration | 생략 | 이번 실행 미지원. 메인 세션에서 작업 엔진·복사형 보관함·검토만 제공하는 대안 검토 | 기능 규모와 실패 책임 |
