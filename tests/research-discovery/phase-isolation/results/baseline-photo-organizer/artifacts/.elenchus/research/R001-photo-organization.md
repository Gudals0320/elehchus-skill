## Repository 기준선과 Neutral brief

확인한 사실: 기존 `idea.md`에는 Topology 확인과 Research 진행 결정, 사용자 요구·선호가 기록되어 있다. 기존 Research index와 Execution 문서는 없다. 현재 질문에는 사용자 의도와 `evidence/` 문서가 관련되며, 제품 코드·설정·개인 사진은 조사하지 않았다. 특정 엔진·DB가 이미 채택됐다는 저장소 근거는 없다.

| 항목 | 내용 |
|---|---|
| 중립 질문 | 여러 볼륨의 사진을 어떤 원본 관리 구조로 모아 보고 오프라인으로 열람할 것인가? |
| 입력 | Windows, 두 드라이브와 외장 SSD의 여러 폴더, JPEG·PNG·HEIC 약 5만 장 |
| 출력 | 선택한 폴더의 사진과 정보를 모아 보는 방식, 원본 위치와 분리된 SSD의 이전 정보에 접근하는 방식의 비교 |
| 사용자 경험 | 인터넷 없이 날짜로 훑어보고 크게 비교하며, SSD가 빠져도 이전에 본 사진 정보를 찾는다. 기본 화면 취향은 미정이다. |
| 성공 조건 | 원본·메타데이터를 명시적 적용 전 변경하지 않고 여러 위치를 통합 탐색한다. 연결되지 않은 원본과 저장된 정보의 차이를 설명한다. |
| 실패 조건 | 계정·온라인 연결·업로드가 필수이거나, SSD 분리로 기존 정보가 사라지거나, 가져오기·원본 이동을 사용자 선택 없이 강제한다. |
| 확정 제약 | 개인용 로컬 도구. 계정·클라우드 업로드·공유·얼굴 인식·사진 편집 제외. 외부 계정·유료 호출·실제 개인 사진 접근 불허. 기능·비용을 새로 확정하지 않는다. |
| 환경 사실 | 이번 실행의 네트워크·Browser·subagent 경로는 제공되지 않는다는 프로젝트 지침이 있다. 증거 묶음은 가상 제품의 합성 문서이며 화면·실행 데모가 없다. |
| 미해결 질문 | 폴더 직접 관리·복사형 보관함·참조 카탈로그 중 제품 방향, 기본 화면, 미리보기 보존 범위, HEIC 제작 방법, 성능·저장 공간 기준 |

사용자 기술 언급 분류: Windows는 **현재 환경이자 필수 제약**, JPEG·PNG·HEIC와 오프라인 정보 열람은 **필수 제약**, digiKam은 **예시**다. digiKam을 비교의 전제나 우선 후보로 사용하지 않았다. 특정 엔진·DB는 필수 조건이 아니며, 자료에 등장한 SQLite는 기술 사례일 뿐이다.

폴더 화면·타임라인은 탐색 표면이고, 복사형 보관함·참조 카탈로그는 원본 관리 방식이다. 서로 완전히 배타적인 한 축의 선택으로 묶지 않는 것이 합리적이라는 **설계 해석**이며 사용자 선호를 확인한 사실은 아니다.

## Verdict

- 판정: **결론 가능**
- 범위: 합성 문서에서 참고할 설계 패턴과 현재 요구와의 충돌에 대한 조건부 결론. 실제 제품 선정·지원 보장·성능 판정은 포함하지 않는다.
- 근거: S4의 원본 비이동·오프라인 정보 저장은 사용자의 분리된 SSD와 원본 보존 요구에 가장 직접적으로 대응한다. S1과 S3의 상반된 원본 관리 방식이 대안과 비용을 드러낸다.
- 반대 근거: 참조 구조는 정보가 오래되거나 외부 이동 후 연결이 끊길 수 있다. 복사형 보관함은 이미 가져온 사진을 원래 위치 없이 열 수 있다는 이점이 있다. S6은 과거 구조와 현행 제품 추천의 연결을 반박한다.
- 채택·제외 근거: **원본은 제자리에 두고 정보·미리보기를 별도 로컬 저장하는 구조를 우선 검토하도록 제안**한다. 특정 제품·DB 채택은 하지 않는다. 계정/온라인 검색/동기화 의존 구조와 분리된 SSD 정보 미보존은 현재 조건에 맞지 않는다.
- 한계: 화면 관찰·실행·실제 공개 생태계 조사가 없다. 캐시 해상도를 원본 크기 비교 가능성으로 해석하지 않는다. 저장 공간·성능·HEIC와 재연결 품질은 미확인이다.
- 신뢰도: **중간**. 문서 내 구조 비교와 버전 충돌 판단은 명확하지만 사용자 PC 적용 근거는 부족하다.

## Idea·Execution 영향과 보류

- 출처: 사용자 요청 — 기존 목표·Topology·제약·제외를 유지한다. Research 진행·현재 버전 선택을 다시 묻지 않는다.
- 출처: 에이전트 제안 — 참조 카탈로그 우선 검토는 원래 미정 구조를 좁히는 제안이다. 정보·미리보기 지속 저장의 공간과 관리 부담이 추가되며 **사용자 미승인**이다. 폴더·타임라인 기본 화면에 우선순위를 강제하지 않는다.
- Idea에는 제안 상태와 연결만 기록한다. 보관함 채택·미리보기 크기·새 기능·비용을 확정하지 않는다.
- Execution에서는 원본 관리·오프라인 정보·형식/규모 검증에 영향이 있다. 아직 Phase·Build를 만들거나 번호·순서를 합의하지 않는다.
- 후속 검증 과제(미합의): 개인 사진 대신 허용된 비개인 fixture를 확보한 뒤 JPEG/PNG/HEIC 디코딩과 날짜 추출, 5만 장·복수 볼륨의 최초 스캔/재검색/저장량, SSD 분리·재연결·외부 경로 변경을 확인해야 한다. 통과 기준은 형식별 실패가 설명되고 저장 정보와 원본의 상태가 구별되는 것, 시간·용량 수용치는 사용자와 정하는 것이다. 근거가 확보되기 전 해당 지원·성능 보장을 포함한 Execution closure는 보류한다.

## Web closure와 이번 조사 경계

핵심 Claim에 본문·작성 시점·버전·반례·근거 부족을 연결했고, 접근 기록과 원문 중복을 정리했다. 허용된 로컬 대체 경로에서의 문서 비교는 종료 가능하다. 실세계 제품 조사·Browser 관찰·Lab 검증의 완료를 뜻하지 않는다. 남은 C4와 실제 UX·재연결 공백은 후속 검증으로 연기했으며 필수 요구에서 삭제하지 않았다. 조사 결과는 작성했지만 사용자 제품 선택과 Research 결론 확인 전이므로 문서 상태는 `작성 중`이다.
