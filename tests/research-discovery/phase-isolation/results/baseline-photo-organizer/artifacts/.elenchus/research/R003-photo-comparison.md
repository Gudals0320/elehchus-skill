# Research R003: 동일·유사 후보와 비교 경험

- 상태: 작성 중
- 기준: [idea.md](../idea.md)
- 확인 날짜: 2026-09-07
- 영향: Phase 후보. 유사도 엔진·화면·성능 목표와 Execution 계획은 미확정이다.

## Repository 기준선과 Neutral brief

`idea.md`에서 중복 후보를 나란히 비교해 직접 선택하고, 외형 유사성만으로 자동 삭제하지 않는다는 요구를 확인했다. 기존 구현이나 정확도 측정은 현재 자료에서 확인하지 않았다. 실제 개인 사진에 접근하지 않았다.

| 항목 | 내용 |
|---|---|
| 중립 질문 | 동일·유사 사진 후보를 어떻게 찾고 사용자가 비교·선택하게 할 것인가? |
| 입력 | 두 드라이브와 외장 SSD의 JPEG·PNG·HEIC 약 5만 장, 복사본·축소본 등 여부는 미확인 |
| 출력 | byte 동일 후보와 외형 유사 후보의 구별, 큰 사진 비교 경험과 탐색 방법의 비교 |
| 사용자 경험 | 삭제 전 후보를 나란히 크게 보고 직접 고른다. 원본과 메타데이터는 명시적 적용 전 바꾸지 않는다. |
| 성공 조건 | 후보가 제안인 이유와 한계를 알 수 있고, 해상도·용량·위치 등 선택 근거와 원본 접근 가능 여부를 구별한다. |
| 실패 조건 | 유사 점수를 동일 사진 보증으로 제시하거나 자동 삭제한다. 연결되지 않은 원본의 세부를 캐시만으로 확인했다고 한다. |
| 확정 제약 | Windows, 로컬·오프라인·개인용, 날짜 탐색도 필요. 계정·업로드·공유·얼굴 인식·편집 제외. 개인 사진·유료 호출·외부 계정 불허. |
| 객관적 환경 사실 | Pairboard 제작기는 합성 서술이고 화면·실행 파일이 없다. 네트워크·Browser·subagent 미지원. |
| 미해결 질문 | 유사 후보의 누락·오탐 허용 범위, 비교 화면 동작, SSD 분리 시 비교 한계, 알고리즘·임계값과 삭제 적용 방식 |

기술 언급 분류: Windows·형식은 필수 환경/조건, digiKam은 예시다. byte hash·perceptual hash는 문서에서 발견한 접근법 후보이며 특정 엔진 채택이 아니다.
