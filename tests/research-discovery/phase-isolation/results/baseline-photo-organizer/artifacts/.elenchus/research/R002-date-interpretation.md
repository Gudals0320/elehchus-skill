- 상태: 작성 중
- 기준: [idea.md](../idea.md)

## Repository 기준선과 Neutral brief

기존 `idea.md`의 확정 입력을 확인했다. 현재 질문에 필요한 제품 구현·날짜 정책·테스트의 기존 사실은 확인되지 않았으며 설정이나 실제 사진은 읽지 않았다.

| 항목 | 내용 |
|---|---|
| 중립 질문 | 없거나 잘못된 촬영일을 어떻게 설명하고 날짜별 탐색에 사용할 것인가? |
| 입력 | Windows의 여러 볼륨에 있는 JPEG·PNG·HEIC 약 5만 장. 촬영일이 없거나 잘못된 사진 포함 |
| 출력 | 원본 메타데이터와 표시용 날짜를 구별하는 방법, 출처·불확실성·보정 저장 위치의 비교 |
| 사용자 경험 | 날짜로 사진을 훑고 크게 비교한다. 잘못된 날짜를 자동으로 사실처럼 표시하지 않는다. |
| 성공 조건 | 촬영일·파일 날짜의 한계를 설명하고 원본을 명시적 적용 전 변경하지 않는다. SSD 분리 시에도 이전에 저장한 날짜 정보를 볼 수 있다. |
| 실패 조건 | 파일 수정일을 실제 촬영일로 확정하거나, 시간대 없는 값을 임의 정규화하거나, 날짜를 읽는 과정에서 원본·sidecar에 보정값을 쓴다. |
| 확정 제약 | 로컬·오프라인·개인용. 계정·클라우드 업로드·공유·얼굴 인식·편집 제외. 실제 개인 사진·유료 호출·외부 계정 사용 불허. |
| 객관적 환경 사실 | 자료는 합성이며 Chronofile 코드 조각은 실행 결과가 아니다. 네트워크·Browser·subagent 경로가 없고 실행 fixture도 제공되지 않는다. |
| 미해결 질문 | 촬영일 누락·오류의 표시·정렬 정책, 사용자 보정 기능과 저장 위치, 시간대 표현, HEIC·깨진 메타데이터 지원 |

기술 언급 분류: Windows와 사진 형식은 필수 환경·지원 조건, digiKam은 예시다. Chronofile은 이번 자료의 구현 사례이며 필수 의존성이 아니다. 특정 DB는 선택되지 않았다.

## 후보와 핵심 차이

| 접근법 | 사용자 결과 | 얻는 것 | 부담·사라지는 결과 | 판정 |
|---|---|---|---|---|
| EXIF 우선, 없으면 파일 날짜를 임시 표시 | 날짜 탐색에 더 많은 사진 포함 | 빠르게 날짜 범위를 훑음 | 복사일이 촬영일처럼 보일 위험. 출처를 붙여도 잘못된 EXIF 자체는 해결되지 않음 | S4의 사례. 사용자 정책으로 미확정 |
| 촬영일 불명·의심 항목을 별도로 표시 | 확실하지 않은 날짜를 드러냄 | 허위 정확성 감소 | 의심 판단 규칙·누락 사진 위치가 필요하고 연속 타임라인이 덜 채워짐 | 에이전트 대안. 시간순 배치보다 불확실성 표현을 우선할 때 적합 |
| 사용자가 표시용 날짜를 별도로 보정 | 원본을 바꾸지 않고 자신의 정리 날짜 사용 | 잘못된 날짜에 대응 | 보정 입력·저장·충돌 관리가 추가됨 | 에이전트 제안, 기능 채택과 저장 위치 미승인 |
| 원본·sidecar에 날짜 적용 | 다른 도구에 변경값 전달 가능성 | 도구 간 값 사용의 가능성 | 파일 변경 책임·지원 검증 필요. 이점의 실제 호환성도 자료에서 미확인 | 기본 동작으로 채택하지 않음. 명시적 적용 전 쓰기 금지는 확정 요구 |
| 더 작게: 출처를 표시하고 보정은 연기 | 읽기 중심 날짜 탐색 | 보정·쓰기 기능 부담 감소 | 잘못된 날짜를 앱에서 고치지 못함 | 범위 축소 대안으로 미승인 |

제작 방법으로는 원문 값, 파싱 결과, 출처, 시간대 유무를 구별해 보관하는 S8의 레코드 구조가 유용하다. **제안**으로 표시용 보정값도 읽은 값과 분리하면 원래 정보를 잃지 않고 설명할 수 있다. 제공된 코드는 네 필드를 반환하는 예시뿐이며 읽기 parser·전체 날짜 정책·HEIC 지원 구현으로 채택할 수 없다.

## Verdict

- 판정: **결론 가능**
- 범위: 날짜의 출처·불확실성과 원본 쓰기의 분리 원칙. 특정 정렬 정책·parser 지원 보장은 보류한다.
- 근거: S8은 날짜의 원문·출처·시간대를 구별하고, S4는 임시 파일 날짜와 출처 배지라는 경험을 설명한다.
- 반대 근거: 촬영일 우선만으로 시계 오류를 해결할 수 없고 파일 날짜 fallback은 잘못된 시간순 배치를 만들 수 있다. S1의 sidecar 보정은 원본 폴더에 쓰기를 발생시킨다.
- 채택·제외 근거: **날짜 값에 출처·시간대 유무를 함께 유지하고, 표시용 해석/보정을 원본 메타데이터와 분리하는 방식을 제안**한다. 출처 없이 파일 날짜를 촬영일로 확정하거나 사용자 선택 없이 시간대를 가정하는 방식은 피한다. 특정 fallback·의심 판단·사용자 보정 기능은 확정하지 않는다.
- 한계: 실제 날짜 정확도·HEIC·깨진 메타데이터 처리·화면 사용성을 측정하지 않았다.
- 신뢰도: **중간**. 정보 구분의 근거는 있으나 사용자에게 맞는 날짜 정책과 모듈의 실제 지원은 미확인이다.

## Idea·Execution 영향과 보류

- 출처: 사용자 요청 — 날짜로 훑기와 원본 무변경을 유지한다. 원자료의 특정 정렬 취향을 사용자에게 귀속하지 않는다.
- 출처: 에이전트 제안 — 출처/시간대 정보의 구분은 원래 요구를 구체화한다. 표시용 보정 기능은 추가 선택으로, 입력·저장 관리 부담이 있으며 미승인이다. 보정 연기는 부담을 줄이지만 잘못된 날짜 수정 결과를 없앤다.
- Idea에는 제안과 미결정만 연결한다. Execution의 날짜 읽기·오류 표시·선택적 보정에 영향이 있으나 Phase·Build와 순서를 작성하지 않는다.
- 후속 검증 과제(미합의): 비개인 fixture 확보 후 누락·잘못된 문자열·시간대 유무·기기 오차·복사 후 수정일·JPEG/PNG/HEIC의 추출을 확인한다. 파싱 실패는 실패로 표시하고 원문/출처를 잃지 않으며 원본·sidecar가 변경되지 않아야 한다. 문서의 함수만 실행하는 테스트로 이를 대체하지 않는다.
- 미결정은 다음 대화로 유지한다. 특히 날짜 누락 시 임시 파일 날짜와 미상 묶음 중 무엇을 보여 줄지에 따라 사용자 경험이 달라진다. 근거가 없으면 자동 보정 보장은 하지 않고 관련 기능의 확정·검증을 연기한다.

## Web closure와 이번 조사 경계

모든 Claim에 본문·날짜·버전·반례와 공백을 연결했다. 접근 가능한 관련 로컬 문서 대조는 끝났으며 원격 경로는 미지원·미시도로 기록했다. Browser·Lab 없이 형식 지원이나 실제 촬영 시각을 검증한 것으로 보지 않는다. C3은 후속 검증으로 연결했다. Research 결론은 작성했지만 사용자 결론 확인·제품 정책 선택 전이므로 상태는 `작성 중`이다.
