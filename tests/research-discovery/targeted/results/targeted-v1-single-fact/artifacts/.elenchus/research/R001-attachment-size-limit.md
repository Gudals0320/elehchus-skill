# Research R001: 첨부파일 크기 상한

- 상태: 확정
- 기준: ../idea.md
- 확인 날짜: 2026-09-07
- 영향: Phase 후보
- 출처: 사용자 요청. 기존 미확인 사실을 확인하며 기능·조사 범위 추가는 없음.

## 기준선과 중립 질문

현재 Idea는 사내 메모 도구의 파일 첨부를 다루며 Topology는 사용자 확인 완료다. Paperpost API 2.3은 현재 환경이자 이번 확인의 필수 대상이다. 입력은 사용자가 지정한 `evidence/current-manual.md`, 출력은 첨부파일 하나당 최대 크기와 단위다. 사용자에게 해당 값만 전달한다. 성공 조건은 원문에서 대상 버전과 파일 하나의 상한을 직접 확인하는 것이며, 값·단위·대상이 불명확하거나 충돌하면 결론을 보류한다. 다른 제품 비교·사례 탐색은 제외한다. 제품 코드와 설정은 이 문서상 제한 확인에 무관하므로 읽지 않았다.

## 간소화 Evidence

| Claim | 근거·관찰 | 본문·화면 확인 | 적용 범위·확인 날짜 | 반대·실패 점검 | 상태 |
|---|---|---|---|---|---|
| 첨부파일 하나의 최대 크기는 25 MiB(26,214,400 bytes)다 | [제공 원문](../../evidence/current-manual.md), 5행. Paperpost 유지보수자, 2026-08-01. 원천: https://paperpost.example/docs/2.3/attachments | 메인 세션이 파일 본문을 직접 읽음 | API 2.3, 파일 하나당 제한. 2026-09-07 확인 | 다른 값·버전·요청 전체 제한이면 반증됨. 본문은 요청 body 제한과 별개임을 명시하며 초과 시 ATTACHMENT_TOO_LARGE로 거절한다고 설명 | 확인 |

- 간소화 이유: 비교 없는 저위험 단일 사실이며 해당 정책을 직접 명시하는 유지보수자 원문 보관본 하나가 판정한다. 본문 내 충돌·접근 실패·남은 공백이 없다.
- 두 번째 출처와 별도 반대 검색은 생략: 제공된 가상 제품의 원문이 제한을 직접 규정하고 사용자가 확인 범위를 이 문서로 한정했다. 요청 전체 제한과의 혼동 및 초과 실패 조건은 같은 본문에서 점검했다.
- 추가 조사가 Verdict를 바꿀 가능성이 낮은 이유: 지정 버전의 크기와 단위가 명시되어 있고 확인 범위는 제공 문서의 기재값이다.

## Verdict와 Web closure

판정: 결론 가능. 신뢰도: 높음(제공 원문 기재값 기준). 근거는 위 본문이며 반대 근거는 해당 본문에서 발견되지 않았다. 실제 서비스 호출이나 실시간 웹 확인은 수행하지 않았고 다른 버전·요청 body 전체 제한으로 일반화하지 않는다. 후보 비교·채택·제외는 이번 단일 사실 확인에 해당하지 않는다.

본문·출처·날짜·대상 버전·적용 범위를 대조했고 간소화 및 추가 조사 생략 사유를 기록했다. 이 질문의 남은 공백은 없다. Idea의 크기 상한 미확인을 확인된 사실로 갱신한다. Execution 문서는 없으며 Phase·Build를 새로 만들지 않는다. Research의 사실 확인만 끝났으며 전체 계획 세션은 진행 중이다.
