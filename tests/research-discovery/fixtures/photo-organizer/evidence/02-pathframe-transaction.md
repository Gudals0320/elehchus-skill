# Pathframe 1.7 파일 작업 개발 기록

원천: https://pathframe.example/dev/1.7/file-journal
작성: Pathframe 유지보수자, 2026-01-12

초기 구현은 사용자가 드롭한 즉시 파일 이름을 바꿨다. 다른 드라이브 이동 중 연결이 끊어지면 복사와 삭제의 중간 상태를 설명할 수 없었다. 지금은 계획 목록과 작업 journal을 만들고 적용 전에 대상 충돌·남은 공간을 확인한다. 드라이브 간 이동은 복사, 확인, 원본 제거의 세 단계다. 중단된 기록을 재개할 때 이미 완료한 항목을 다시 삭제하지 않는다.

동일 드라이브 rename이 빠르다는 사실은 드라이브 간 작업의 원자성이나 전체 일괄 적용의 원자성을 뜻하지 않는다. 사용자가 검토하지 않은 원본 삭제는 UI에서 노출하지 않는다. 프로그램 밖에서 원본이 변경되면 실행 당시 파일 정보가 계획 당시와 달라졌음을 보여 주고 해당 항목을 보류한다.

문서에 있는 API는 작업 기록·재개 구조의 설명이며 파일시스템마다의 완전한 복구 보장을 선언하지 않는다. 소스나 실제 데이터로 별도 확인해야 하는 경계가 남아 있다.
