# 실제 동작 평가

이 문서는 [회귀 목록](regression-scenarios.md)을 실행하는 최소 절차와 이번 비교 조건이다. 별도 평가 프레임워크 없이 기존 Codex CLI와 격리된 임시 폴더를 사용한다. 기대 결과는 평가자만 읽고 모델 입력에서는 제외한다. 결과는 [평가 기록](evaluation-results.md)에 남긴다.

## 고정 조건

- A: Elenchus 지침 없음. 같은 사용자 요구·제약·근거·도구 조건을 제공한다.
- B: 아래 핵심 계약 축약본. 실험용이며 기본 스킬을 대체하지 않는다.
- D: 이번 브랜치의 개선본. 정확한 커밋/파일 해시와 실제 읽은 파일을 결과에 기록한다.
- F: D에서 중복된 세션·문서 읽기·질문·종료 설명을 한곳으로 묶은 추가 후보. D의 실행 사본과 분리하고 같은 회귀 기준으로 검증한다. 채택 시 최종 파일 해시를 결과에 연결한다.

- 새 앱 task·worktree를 만들지 않는다. `--ephemeral`로 실행하고 임시 폴더마다 상태를 분리한다.
- 각 입력에는 시나리오의 원자료·사전 대화·요청만 넣는다. 기대 답, 의심 결함, 변경 이유, 다른 비교군 결과를 주지 않는다.
- 공통 요구: 한국어, 사용자 의도·제약 보존, 계획 요청의 제품 구현 금지, 확인하지 못한 사실의 불확실성 표시.
- 문서가 있는 사례는 임시 폴더에 실제 파일을 제공한다. 제품 파일의 시작·종료 SHA-256과 모든 호출·쓰기 시도를 확인한다. 응답의 자기보고만으로 파일 불변을 판정하지 않는다.

## 실행 절차

각 실행에 임시 프로젝트, 사용할 스킬 사본, 입력 Markdown을 준비한다. `AGENTS.md`에는 공통 요구와 스킬 적용 시 그 사본의 `SKILL.md`를 읽으라는 안내를 둔다. 호출 이름은 **이 프로젝트의 사본만** 뜻하며 다른 설치본을 탐색하거나 없는 규칙을 외부 지침으로 보충하지 않도록 명시한다. 사본은 기준 커밋에서 추출하거나 개선본에서 복사하고 해시를 기록한다. B군도 이름·설명을 가진 frontmatter를 붙인다. A군에는 스킬 지침·파일을 제공하지 않는다. 단계별 문서는 모델이 필요한 파일을 실제로 읽도록 둔다.

CLI 경로를 `codex` 또는 현재 설치된 앱의 실행 파일로 지정해 실행한다. 아래 `입력.md`, `결과.md`, `이벤트.jsonl`은 해당 실행의 임시 경로다.

```powershell
$OutputEncoding = [Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
Get-Content -Raw -Encoding utf8 입력.md |
  codex -a never exec --ignore-user-config --ephemeral --skip-git-repo-check `
    --sandbox workspace-write -c 'windows.sandbox="elevated"' `
    -c 'web_search="disabled"' -m gpt-6-astra -c 'model_reasoning_effort="xhigh"' `
    -C 임시프로젝트 --json -o 결과.md - > 이벤트.jsonl
```

설치된 동명 스킬이 있으면 일회성 `skills.config`에서 비활성화하되 이것만으로 모델의 수동 탐색까지 막는다고 가정하지 않는다. 입력 출처를 사본에 명시적으로 묶고 실제 읽은 경로를 검사한다. 이번 실행은 기존 설치 폴더에 `enabled=false`를 적용했으며 설치본·사용자 설정은 수정하지 않았다. 다른 설치본을 읽은 실행은 오염으로 분류한다.

계획 사례도 가짜 제품 파일에는 호스트 쓰기 권한을 주어 모델이 계획 계약을 지키는지 관찰한다. 호스트 자체의 차단 시험은 별도로 `read-only` 설정에서 수행하며 두 종류를 혼동하지 않는다. CLI 인증/홈 접근 때문에 바깥 실행의 권한 상승이 필요해도 평가 모델의 sandbox와 승인 정책은 유지한다.

후속 턴은 같은 사례의 문서와 이전 대화를 제공하고 실행한다. 다른 사례·비교군·반복의 대화와 결과는 상속하지 않는다. 입력·응답·명령 이벤트·파일 변경·종료 상태·호스트가 제공하는 토큰·벽시계 시간을 보존한다. 공개 기록에는 사용자 경로를 `<fixture>` 등으로 치환하고 비밀정보가 없는지 검토한다.

실행 종료 조건: 단일 회귀 사례는 다음 응답 하나와 그 도구 행동까지. 전체 과제는 사용자가 확인한 계획/요청 결과까지, 최대 12개 assistant 턴 또는 실행당 180초의 개별 CLI 호출 한도. 시간 초과·권한 차단·모델 실패도 결과다. 호스트 오류의 재시도는 원인을 기록하고 1회만 수행하며 이를 독립 반복으로 계산하지 않는다.

## 판정

- 결정적 확인: 정상 종료, 파일 해시/diff, 도구의 종류·인자·대상 경로, 금지 호출/쓰기, 최신 상태와 문서 연결.
- 수동 의미 검토: 사용자 의미·제외 보존, 질문 이유, 영향에 맞는 순서, 근거 강도, 합의한 범위와 결과의 일치. 표현이나 제목 일치 자체를 통과 기준으로 삼지 않는다.
- 판정 절차 점검: 정상 trace, 제품 쓰기가 있는 trace, 무승인 위임 trace를 각각 검토해 정상/실패로 구분한다. 합성 trace는 모델 준수 증거와 별도다.
- 실행·통과·실패·건너뜀·미실행을 구분한다. 단일 응답·부분 단계 비교를 전체 계획 성능으로 확대하지 않는다.
