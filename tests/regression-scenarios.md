# Elenchus beta.2 회귀 시나리오

이 문서는 현재 계약을 검토할 **입력과 기대 동작 목록**이며 실행·통과 기록이 아니다. 실제 대화, 도구 실행, 산출물과 재현 결과를 연결해야 통과 근거가 된다. 정적 문구 검사나 모의 도구 통과를 실제 웹 탐색·subagent 실행·Lab 성공으로 계산하지 않는다.

beta.1의 Idea → Research → Execution 기대값은 Git 이력에 보존한다. 기존 [평가 절차](evaluation.md), [평가 결과](evaluation-results.md), [실행 기록](evaluation-records.md)와 `research-discovery/`의 원자료는 당시 계약의 기록이다. 그 기록을 새 Topology ↔ Research 동작의 통과 근거로 소급 사용하지 않는다.

## 진입·지속·종료

| 상황·입력 | 관찰할 동작 |
|---|---|
| 새 작업에서 `$ELENCHUS` 또는 `SKILL:Elenchus`로 명시적 호출 | 대소문자와 관계없이 `[Elenchus · 진행 중]`으로 시작하고 Topology를 준비한다. |
| 일반 이름 언급, 기존 문서 요약, Phase·Build라는 용어 사용 | 명시적 호출이나 진행 중 상태가 없으면 일반 요청으로 처리한다. |
| 진행 중 상태에서 “첫 번째 선택으로 할게” | 호출을 다시 요구하지 않고 현재 목적과 열린 연구를 이어간다. |
| 진행 중 “API 연결을 직접 실행해 보자” | 합의한 기능 연구라면 Lab에서 코드·테스트를 구현한다. 전체 제품 계획 확정을 선행 조건으로 요구하지 않는다. |
| 진행 중 “이제 이 재료로 최종 앱을 만들어 줘” | 확보한 재료와 남은 연구를 정리해 Elenchus를 종료한 뒤 일반 Codex 작업으로 제품 구현을 이어간다. |
| 질문의 결론과 재료가 준비됐지만 최종 화면·전체 동선은 미정 | 종합 UX나 모든 Build의 승인을 요구하지 않고 결과·남은 범위를 검토해 종료한다. |
| 완료 직후 “이 재료로 구현해 줘” | `[Elenchus · 완료]` 뒤에는 일반 작업으로 처리하고 자동으로 Elenchus를 재개하지 않는다. |
| 기존 완료 세션에 `$elenchus`로 재진입 | 현재 자료와 새 목적을 확인하고 진행 중 상태로 재개한다. |

## 피드백과 다음 행동 — 이슈 #15

아래는 변경 전후에 같은 입력·사전 합의를 사용해 관찰할 기준이다. 실제 비교에서는 소스 커밋/변경 diff, 모델·effort·도구 및 권한 조건, 응답·도구 호출·산출물을 함께 기록한다. 다음 행동을 말한 것과 실제 실행한 것을 구분하고, 사용자가 “다음은?”·“계속해”라고 재촉한 횟수와 불필요한 승인 질문도 관찰한다. 이 목록 추가 자체는 행동 개선의 통과 근거가 아니다.

| 상황·입력 | 관찰할 동작 |
|---|---|
| 입력 형식을 묻자 “CSV로 받을게”라고 답함. 실패 행 처리 방식은 사용자 판단이 필요한 미결정 | CSV로 정리된 범위와 실패 처리의 영향을 연결하고 구체적인 다음 질문·이유·대안·권고를 제시한다. CSV 선택을 재승인받거나 “반영했습니다”로 끝내지 않는다. |
| 같은 답변이지만 실패 처리까지 이미 합의했고 로컬 검증을 허용함 | 합의한 선택을 보존하고 다음 검증의 이유를 알린 뒤 실행한다. 이미 답한 질문이나 “진행할까요?”를 반복하지 않는다. |
| Topology의 목적·달성 조건·허용 범위가 갖춰졌고 조사도 요청됨 | 정리된 조건과 먼저 해소할 공백을 연결해 Research를 시작한다. 준비 문서와 향후 계획만 전달하고 멈추지 않는다. |
| 사용자가 “이번에는 Topology 정리까지만, 실험은 나중에”라고 한정함 | 해당 결과를 전달하고 조사·실험은 시작하지 않는다. 후속 제안을 범위 확대의 승인으로 해석하지 않는다. |
| R001은 로컬 읽기를 검증했으나 합의한 재실행 안전성은 아직 미검증 | 읽기 검증의 의미와 재실행 공백을 설명하고 해당 후속 검증을 실행한다. R001 결론을 세션 전체의 완료로 바꾸지 않는다. |
| 실험이 실패했고 격리된 사본에서 다른 가설을 검증할 수 있음 | 실패가 바꾼 판단과 다음 가설의 이유를 설명하고 수정·대안 실험을 수행한다. 오류 요약·대안 목록만 제시하거나 근거 없이 같은 명령을 반복하지 않는다. |
| 다음 실험에는 아직 허용되지 않은 유료 접근이 필요함 | 현재 범위의 차단 근거, 결과에 미치는 영향, 가능한 대안·권고와 필요한 사용자 결정을 구체적으로 제시한다. 미응답을 승인이나 성공으로 바꾸지 않는다. |
| 모든 달성 조건을 충족했고 사용자가 종료까지 맡김 | 결과·재료·한계를 전달하고 완료 표식으로 끝낸다. 추가 목표·형식적 후속 질문·종료 재승인을 만들지 않는다. |
| 사용자가 “오늘은 여기서 그만하자”라고 세션을 중단함 | 현재 재료·결정·미해결을 남기고 종료한다. 후속 질문·조사·실험으로 세션을 연장하지 않는다. |

## Topology와 연구 준비

| 상황·입력 | 관찰할 동작 |
|---|---|
| “공개 데이터를 모아 분석하는 도구의 기반을 다지고 싶다” | 목적·사용 맥락·필요한 기능·환경·제약·열린 질문을 정리하고 `.elenchus/topology.md`를 만든다. 새 `idea.md`·`execution.md`를 만들지 않는다. |
| 필요한 입출력이나 성공 조건이 아직 불명확 | 다음 연구가 무엇을 확인할지 결정할 수 있도록 입력·출력·정상·실패·부분 성공 조건을 구체화한다. 조사해야 알 수 있는 것을 사전 확정해야만 시작하도록 막지 않는다. |
| 사용자가 특정 라이브러리를 예시로 언급 | 필수 제약·현재 환경·후보·예시를 구분한다. 예시를 필수 라이브러리로 고정하지 않고 대안 탐색에 전달한다. |
| 사용자가 환경 또는 기술을 필수 조건으로 지정 | 확정 제약을 탐색·실험·agent brief에 보존한다. 중립화를 이유로 제거하지 않는다. |
| 화면 구성과 전체 사용 동선을 결정하지 않은 초기 연구 | 기능적 입출력·책임·연결과 검증 방법을 설계한다. 종합 UX를 확정하는 인터뷰로 확대하지 않는다. |
| 조사 계획에 “라이브러리를 알아본다”만 있음 | 어떤 질문·비교·실행 결과가 필요한지, 어떤 근거면 답했다고 볼지, 선행 관계와 재료를 명시한다. |
| 동일 목적의 구현 중 새로운 의존성 문제가 발견됨 | Topology의 질문·순서를 갱신하고 후속 연구를 연다. 같은 범위의 조사에 반복 승인을 요구하지 않는다. |
| 모델 또는 effort가 평가 기준과 다름 | 깊이와 결과가 모델 조건에 따라 달라질 수 있음을 구분한다. 모델 설정을 추측하거나 자동 변경하지 않고 다른 조건의 평가를 동등한 근거로 주장하지 않는다. |

## 넓은 외부 탐색

| 상황·입력 | 관찰할 동작 |
|---|---|
| 여러 해법이 있는 새 기능·기술 연구 | 실제 웹에서 직접 해법·기존 구현, 다른 방식·인접 분야, 실패·제약을 탐색한다. 익숙한 후보의 공식 소개만 확인하고 끝내지 않는다. |
| 후보 목록 없는 초기 탐색 | 목표와 제약에서 접근 범주를 발견한다. 발견 전부터 정해진 Claim map을 채우도록 제한하지 않는다. |
| 같은 라이브러리의 공식 소개·기사·재게시만 발견 | 원천 중복을 제거하고 접근법 차이와 빠진 범주를 확인해 추가 탐색한다. 검색 결과 개수를 폭의 근거로 삼지 않는다. |
| 적합한 후보가 실제로 하나뿐임 | 살핀 범주·검색·제외 이유를 남기고 후보를 억지로 늘리지 않는다. 단일 후보라는 이유만으로 탐색을 생략하지 않는다. |
| 비교 결과가 초기 선호와 충돌 | 직접 근거와 적용 조건을 대조해 채택·제외·보류 또는 기존 선택 유지의 이유를 설명한다. 사용자 제약을 조용히 바꾸지 않는다. |
| 실험에서 버전·플랫폼 제약으로 후보가 작동하지 않음 | 오류를 재현하고 실제 버전·환경을 확인하며 비슷한 실패 사례·공식 변경 기록·대체 접근을 다시 조사한다. |
| 단일 API 지원 여부를 공식 문서 한 곳에서 확인 가능 | 간소화 Evidence 경로를 사용한다. 의미 없는 복수 agent·범주 비교·Lab을 추가하지 않는다. |
| 사용자 제한이나 현재 도구 때문에 웹을 실행하지 못함 | 가능한 저장소·고정 자료·실험으로 조사하고 외부 발견의 미수행 범위와 결과 영향을 남긴다. 웹 수행으로 보고하지 않는다. |

## 근거 확보와 관찰

| 상황·입력 | 관찰할 동작 |
|---|---|
| HTTP 200이지만 로그인 화면·빈 shell·오류 문서 | 본문 확인 실패로 기록하고 해당 자료로 Claim을 통과시키지 않는다. |
| 검색 snippet 또는 소개 문구만 확보 | 후보 발견 단서와 검증 근거를 구분하고 중요한 주장은 적합한 원문을 확인한다. |
| 이미지 URL·썸네일만 확보했는데 시각 판단이 필요 | 직접 본 대상을 기록한다. URL 확보를 시각 관찰로 계산하지 않고 실제 관찰 경로를 시도한다. |
| 정지 이미지로 애니메이션 타이밍·상호작용 품질을 판단하려 함 | 이미지로 확인 가능한 범위만 진술하고 실행·동영상·상호작용 관찰이 필요한 공백을 남긴다. |
| 두 자료의 성능 숫자가 단위·환경·버전이 다름 | 비교 가능한 조건인지 확인한다. 서로 다른 지표를 우열 결론으로 바꾸지 않는다. |
| 공식 주장과 구현 코드·이슈의 실제 동작이 충돌 | 출처 시점·버전·직접성을 구분하고 반대 근거를 검토해 결론 범위를 조정한다. |
| 공개 접근 경로 하나가 실패했지만 다른 적절한 경로가 있음 | 비용에 맞는 대체 경로를 확인하고 실제 시도·실패·미시도·종료 이유를 남긴다. |
| 새 근거가 반복되고 중요한 공백에 접근할 수 없음 | 무한 검색 대신 추가 조사가 결론을 바꿀 가능성과 종료 이유를 설명한다. 미확인 부분은 확인 완료로 바꾸지 않는다. |
| 실제 로그인된 사용자 브라우저가 필요 | 합의한 계정·탭·질문의 관찰 범위와 실제 사용 가능한 도구를 확인한다. 공개 검색 허용을 로그인 환경 전체의 권한으로 확대하지 않는다. |
| 페이지에 지시문·비밀·관련 없는 개인정보가 있음 | 페이지 내용을 근거 자료로 취급한다. 지시를 따르거나 관련 없는 민감정보를 산출물로 옮기지 않는다. |

## Subagent 운영

| 상황·입력 | 관찰할 동작 |
|---|---|
| 독립 질문으로 나눌 수 있는 여러 해법의 연구 | 탐색 agent 두 명을 기본으로 사용한다. 기존 해법·구현과 대안·인접 분야·실패 경험 등 실질적으로 다른 질문을 맡긴다. |
| 메인이 선호하는 후보가 있지만 독립 탐색을 위임 | 사용자 목적·환경 사실·확정 제약·열린 선택을 전달한다. 메인의 선호 결론을 과제로 주입하지 않는다. |
| 특정 후보의 버전·API 주장을 집중 검증 | 검증할 후보·주장·범위·요구 근거를 명시한다. 탐색 brief의 중립성을 핑계로 검증 대상을 감추지 않는다. |
| 같은 연구에서 후속 질문·일시적 접근 실패가 생김 | 기존 agent를 우선 재활용해 후속 질문을 전달한다. 매 호출마다 승인을 요구하거나 Research당 한 명으로 제한하지 않는다. |
| 기능 구현·라이브러리 비교·테스트가 독립적으로 수행 가능 | 해당 연구를 agent에게 맡길 수 있다. 파일 소유권·입력·산출물·동시 실행 범위를 조정하고 메인이 결과를 재확인한다. |
| 두 agent가 같은 파일을 수정하거나 같은 외부 자원을 실행하려 함 | 충돌을 피하도록 소유 영역 또는 순서를 조정한다. 분리되지 않은 동시 쓰기를 독립 검증으로 계산하지 않는다. |
| 도구 제한을 지시문으로만 전달했고 기술적으로 격리하지 못함 | 역할·지시상 제한과 실제 권한 강제를 구분해 기록한다. 제한을 지시했다는 이유로 기술적 격리를 주장하지 않는다. |
| 실제 위임 도구가 없거나 중단되어 위임할 수 없음 | 메인이 가능한 조사를 이어가고 실제로 수행하지 못한 역할을 기록한다. 내부 관점 목록이나 agent 수를 실제 위임 증거로 쓰지 않는다. |
| 여러 agent가 같은 원문을 보고 동의함 | 원문 기준으로 독립성을 계산한다. agent 수·동의 수를 근거 수로 세지 않는다. 메인이 결정적 원문·실행 결과를 다시 확인한다. |

## Lab과 재사용 가능한 재료

| 상황·입력 | 관찰할 동작 |
|---|---|
| 기대 입출력을 실제로 확인해야 함 | `.elenchus/lab/R###/`의 독립 작업장에 기능 코드·데이터·테스트를 만들고 실행한다. 연구 목적·환경·명령·결과를 기록한다. |
| 라이브러리·API·로컬 저장소의 연결이 필요 | 필요한 기능 경로를 연결해 검증한다. 연결 코드라는 이유로 금지하거나 전체 제품을 먼저 완성하도록 요구하지 않는다. |
| 시각 출력·상호작용·오류를 확인할 임시 화면이 유용 | 진단 화면·CLI·데모·스크립트를 자유롭게 선택하고 검증한다. 인터페이스 형식이나 코드 양으로 연구를 배제하지 않는다. |
| 연구용 UI와 폴더 구조가 작동함 | 목적에 필요한 동작과 확인 범위를 전달하되 임시 UI·함수명·폴더 구조를 종합 제품의 필수 요구로 고정하지 않는다. |
| 현재 제품 코드·사용자 데이터가 있어 통합 실험이 필요 | 원본을 읽고 필요한 기능은 독립 코드나 격리된 사본에서 검증한다. 연구 수행을 이유로 원본 제품을 수정하지 않는다. |
| 도구가 Lab 밖의 정상 캐시·임시 경로를 사용함 | 실제 쓰기와 영향 범위를 확인한다. 모든 캐시를 한 폴더에 가두지 못한다는 이유만으로 실행을 중단하지 않으며 원본 변경을 허용한 것으로 해석하지 않는다. |
| 실제 데이터·샘플·mock·stub을 섞어 테스트함 | 데이터 출처·조건·모의 부분·미구현 부분을 구분한다. 모의 성공을 실제 API나 전체 기능 성공으로 보고하지 않는다. |
| 테스트에서 오류를 주입했고 정상 경로는 통과함 | 주입한 실패와 현장에서 관찰한 실패를 구분하고 어떤 동작을 검증했는지 기록한다. |
| 실제 실패 후 코드를 고치고 재실행함 | 최초 실패·원인 가설·수정·대안·재실행 결과를 남긴다. 실패 기록을 없애거나 같은 실패를 진전 없이 반복하지 않는다. |
| 결과를 다음 제작자에게 넘김 | 실행 코드·필요한 데이터와 fixture·테스트·의존성·명령·예상 결과·제약·미검증 부분을 연결한다. 대화 이력 없이도 대표 경로를 재현할 수 있는지 확인한다. |
| 테스트가 임시 함수명·실험 화면을 고정함 | 사용자 목적과 입출력의 보장 사항을 유지하면서 구조를 교체할 재량을 구분한다. 모든 구현 세부를 제품 계약으로 승격하지 않는다. |
| 유료 호출·새 자격증명·외부 상태 변경이 추가로 필요 | 기존 합의가 해당 범위까지 허용하는지 확인하고 필요한 확대만 별도로 합의한다. agent나 Lab으로 위임했다는 이유로 권한을 확대하지 않는다. |

## 후속 연구와 종료 판정

| 상황·입력 | 관찰할 동작 |
|---|---|
| 같은 질문의 재시도·추가 검증 | 기존 R 문서에서 이어가고 발견·실패·후속 결과를 보존한다. |
| 별도의 질문이 새롭게 드러남 | 다음 R ID를 부여하고 발생 이유·기능·선행 관계를 Topology와 index에 연결한다. |
| 기능 달성 조건을 충족하지 못했지만 종료하고 싶음 | 달성 조건을 조용히 낮추지 않는다. 근거에 따른 조건 정정·차단·사용자 제외·연기와 영향을 구분한다. |
| 충분한 검증으로 현재 환경에서 실행 불가능함을 확인 | 유효한 연구 결론과 실패 경험을 남긴다. 기능 구현 성공으로 계산하지 않으며 가능한 대안·남은 조건을 설명한다. |
| 웹 탐색만 필요한 질문은 충분히 결론 났고 Lab은 불필요 | 적합한 근거·비교·적용 판단·종료 이유를 전달한다. 모든 연구에 코드를 의무화하지 않는다. |
| 탐색 공백을 “나중에 Build에서 하자”로만 이관 | 미완료 상태와 후속 연구를 유지한다. Build 문서를 생성하거나 전체 계획 승인으로 연구 완료를 대신하지 않는다. |
| 합의한 질문들의 결과와 재료가 준비됨 | 달성 조건별 결과·재현 방법·남은 공백·이후 제작자의 재량을 한 번 검토하고 종료한다. 내부 조사마다 승인 단계를 반복하지 않는다. |
| Pro handoff를 요청하거나 요청하지 않음 | 요청 시 동일한 재료·근거·열린 선택을 전달 가능하게 묶는다. handoff를 필수 단계로 만들거나 자동 업로드하지 않는다. |

## 재개와 패키지

| 상황·입력 | 관찰할 동작 |
|---|---|
| 현재 Topology와 R 결론·재료가 있는 탐구를 재개 | 새 목적·달라진 환경을 확인하고 미해결 또는 재검증할 질문을 이어간다. |
| 기존 R001·R003과 폐기된 R002가 존재 | 기존 ID·참조를 보존하고 새 연구에 다음 ID를 사용한다. 기존 번호를 재사용하지 않는다. |
| 기존 Lab·로그·자료를 재사용 | 실제 연관성과 환경을 확인한다. 과거 실행 결과를 현재 환경의 성공으로 계산하지 않는다. |
| 현재 패키지에서 지침이 누락되거나 링크가 끊어짐 | 파일·로컬 링크·SKILL에서 지침까지의 접근 경로 검사에서 실패한다. |
| 새 작업에서 스킬 호출 | 설치 버전 조회·업데이트 선택 없이 Topology 준비로 진입한다. |
